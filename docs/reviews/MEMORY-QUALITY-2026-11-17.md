## 交付

- 同轮去冗余只发生在来源、敏感值、日期、逐类型上限和总写入预算之后。只有已保留模型候选完整覆盖“记住某事实”的正文，才抑制规则层的指令副本。独立子句、数字、否定或关系不一致时保留规则。模型失败、空输出、无来源或预算淘汰不能取消规则兜底。真正的“以后都”偏好保留。明确记住的设置事实被模型误标 entity 时，沿用已有规则提供的 preference 类型；实体名称本身不因此转换。
- 修正来源检查将所有“读取”字样当作读取请求的问题：“FirLedger 允许读取但不允许删除”可核对；“请读取…”、问句、数值或否定不一致仍不作为新事实来源。
- 设置 → Trivium 记忆 → 运行记录 → 待补写，新增有界来源片段、补充依据并核对、确认记住。核对不调用模型；依据不足仍挂起。手动确认须经过内容确认框，记录为 manual / user-confirmation，不伪造原宿主消息定位。
- 确认路径只插入所确认的内容，不合并、删除、归档、建立替代边，也不认可候选里推测的实体关系。原有记忆、原始窗口和核对记录保留。更改旧决策的现行状态仍使用原替代提案流程。
- 请求必须指定已知工作区，服务端从磁盘取候选，校验候选 ID、物理工作区和窗口 ETag，并取得工作区写锁。过期页面返回 409。稳定操作 URI、落盘后确认和持久核对回执防止中断重试插入第二份或旧缓冲复活候选。回执最多保留 1024 条；这是有界重试保护，不是无限期全事件归档。
- 新审计中缺失的节点/来源序号保持 null，不再被转成虚构的 #0；早期测试记录保留原样。

## 真实模型结果

新夹具 `memory-live-v1.json` 在本轮实现前固定，8 开发 + 4 预先分组题；作者可见全部题，且首轮后题目均已暴露，不宣称盲测泛化。共 12 次实际抽取、24 次实际回答，单次输出上限 900 token。每个回答臂独立建库，使用相同的手工种子事实、问题、模型、回答格式和 300 **估算**上下文 token 上限，交替两臂先后顺序，不使用上一臂对话。

写入与回答是两项测量：回答库独立预置真值，不使用抽取库的结果。因此下面的回答分数不是完整跨会话 Agent 的端到端准确率。

实际抽取轮次的事实正文覆盖 10/10，重复 0，两个不应新增的场景（未确认问题、旧记忆回显）均未新增非实体事实。该轮仍有 1 条设置被模型分为 entity、1 条读取权限候选挂起；规则保住了对应事实。修复后将这 **12 次真实响应原样回放** 到最终写入路径，并逐条校验抽取请求与原请求一致：正文 10/10、错类型 0、重复 0、挂起 0、不应新增 0。回放增加模型调用 0；这部分是基于已观察样本的确定性写入验证，不是又一轮独立模型成绩。
