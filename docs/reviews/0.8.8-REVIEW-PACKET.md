## 一、本版改了什么（按风险排序）

### 1. 提案不再跨库（F88-01，最高风险）

**症状**：切工作区时，旧库的提案响应可能后到。选择器显示 B，卡片显示 A 的原句；点「保持原样」把
请求发给 B，服务端 200，**拒掉 B 的提案**，A 的还挂着。

**改法（两半）**：

- 客户端 `lib/client.js`：读提案前清空列表；请求记住读取时的工作区；迟到响应按 `proposalSeq` **和**
  工作区双重丢弃；切库递增序号并清空忙碌态/错误；提交前核对 `scope !== currentCwd()` 则拒绝提交并重读。
- 服务端 `lib/supersede-review.js`：`proposalEtagOf(db, id, cwd)` 把**工作区**折进 sha1 前 16 位；
  `listSupersedeProposals / confirmProposal / rejectSupersede` 都传 `cwd`。两个库即使节点 id、正文、
  节点级 ETag 全同，A 的令牌拿到 B 也是 `409 proposal-stale`。

**要独立验证的三件事**：见 §三.1。

### 2. 确认/拒绝各有审计行

`lib/change-log.js` 新增两个 reason：`supersede-confirmed` / `supersede-rejected`；`lib/server.js` 在
动作成功后写行（含后继、被退役事实、入口）。审计写失败不吞：返回体带 `warning: "audit-not-recorded: …"`，
面板同时显示「动作已生效，但审计没有写入」。

### 3. 交互写操作也进工作区锁

`lib/server.js` 的 `lockedWrite` 增加：`POST /nodes/<id>`（编辑）、`/nodes/<id>/(merge|archive|delete)`。
持锁时统一 409 `WORKSPACE_WRITE_BUSY`。**故意不加**：设置/芯片/pins/sidecar（只写外围文件），
以及 `map/backfill`、`map/cut`、`embed-backfill`（长耗时管理任务，占锁会把抽取堵死）。

### 4. 部分导入如实回执

`api()` 把响应体挂在 error 上（`err.body`）；`importBuddy` 读取 `partial / newNodesBeforeFailure / retryHint`，
分「0 条 / N 条 / 未知」三种说法，回执移到按钮下方。

### 5. 面板重排（视觉，只有目检证据）

- 运行记录：提案卡片提到最前；候选显示正文；动作后就地显示结果；
- 记忆库：搜索独占首行，筛选/可见性开关/图例收进「筛选（n）」，归档与删除移入展开详情；
- 设置·向量：新增「保存连接」（此前字段只在别的开关顺手写整组 flag 时才落盘）。

### 6. 其余

删除节点时清热度边车条目（`forgetNodes`）；身份语料 + 闸门（`identityMerge` 仍默认关）；
`p91` 版本声明一致性检查；65 份历史文档移入 `docs/archive/`。

## 三、请独立验证的失败场景

### 1. 跨库提案（F88-01）

1. 两个工作区各造一条**完全同名同文**的提案（节点 id、正文都一样）；
2. 取 A 的 `etag`，对 B 发 `POST /supersede-proposals/<id>/reject?cwd=B`；
   **期望**：`409 proposal-stale`，B 的提案仍在列表里（`p89` 有这条，但要独立复现一次）；
3. 面板层：在 A 的提案请求未返回时切到 B，**期望**：卡片不显示 A 的句子；此时若能点到「保持原样」，
   请求必须带 B 的 `etag`（A 的令牌应被服务端拒绝）。

### 2. 确认/拒绝的审计行

确认一次、拒绝一次，`GET /api/dsh-trivium/changes` 里应各有一行 `supersede-confirmed` /
`supersede-rejected`；`nodeId` 是提案节点、`byId`/`detail` 指被退役的事实。

### 3. 锁覆盖面

在另一个进程持有 `.dsh/trivium-write.lock` 时，以下六条都应 `409 WORKSPACE_WRITE_BUSY`，
且**状态未变**：`nodes/<id>`、`nodes/<id>/merge`、`nodes/<id>/archive`、`nodes/<id>/delete`、
`supersede-proposals/<id>/confirm`、`supersede-proposals/<id>/reject`；释放后编辑应 200 且能读回新名称。

### 4. 部分导入

造一个会让服务端写到一半失败的导入（例如中途让 sink 抛错）。**期望**：面板显示「中断前已写入 N 条」，
`0` 与「未知」是**不同**的句子，绝不出现"被拒绝"；回执在按钮下方。

### 5. 视觉（只有截图，没有自动断言）

设置 → Trivium 记忆：760px 与宽屏各看一次——提案卡片在最前、候选有正文、拒绝后有条目内结果、
筛选默认收起、归档/删除只在展开后出现、向量卡片有「保存连接」。

## 四、作者声明为「未验证」的部分（请不要当成已验证）

1. **没有真实模型轮次**：本版的宿主检查是启动 + Playwright 操作，**没有**花一次付费对话；
   所以「抽取在 0.2.2-rc.1 + 新面板下仍按预期落库」只有上一版（0.8.7 代码）的真机证据。
2. **窄栏只有 760px 目检**：上一轮复审提到的约 420px 内容宽度是在宿主设置弹窗里观察的；
   本轮没有在 420px 下复看，只确认了元素在 760px 与宽屏下不换行/不重叠。
3. **视觉改动无自动断言**：按仓库约定（`AGENTS.md` §5）不新增 UI 断言，只有截图与人工点击。
4. **`p24`/`p26` 的用例被改过**：因为归档/删除移进了展开详情，用例改成「先展开再点」。
   断言条数只增不减（9→12、16→19），但**这是测试跟着实现改**，请确认没有把失败路径改宽。
5. **`npm pack` 与 registry 逐字节一致**（shasum `454bf0d7…`，43 个 `lib/*.js` sha256 全同），
   但**没有**在独立目录里安装这个 tgz 并起宿主（0.8.7 做过）。
