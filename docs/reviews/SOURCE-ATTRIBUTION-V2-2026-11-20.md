# 来源归因第二版：改写候选与历史重复（2026-11-20）

对象：`dsh-trivium@0.9.2` 的自动抽取写入路径。上一轮只处理**精确**的工具回显；本轮回答"换个说法复述刚读到的记忆"会不会变成第二条当前事实。

结论：**不需要新增相似度守卫**。现有 `requireSource` 来源门已经覆盖改写：无用户原句支撑的模型候选进入 pending，带上来历的 read id，不写入有效记忆。本轮用 `p117` 把这套行为固定下来。

## 1. 机制（读代码确认）

`lib/extract.js` 的 `applyCandidates` 在 `requireSource:true` 时对每个 `via:"model"` 候选做 `candidateEvidence(candidate, sourceTurns)`：

1. `exactReadMemory` 先拦精确回显（`memory-read-echo`）。
2. 剩下的候选只有在本轮**用户原句**里能找到支撑（或显式读取请求的 `reuseRead`）才写入；
3. 否则走 `onUnverified`，由 `possibleReadOrigins` 附上可能的读取来源 id，`distill()` 以 `unverified` 返回，调用方存入 pending 并显示在「待补写」。

因此"改写"和"精确回显"走的是两条不同路径：前者**留待核对**（可以人工补依据后写入），后者**直接拒绝**（本来就已经在库里）。

## 2. 用例（`scripts/smoke-p117.mjs`，7/7）

种子事实统一为 `报表游标可以复用 24 小时。`（decision）；同轮先 `ctx_read` 该节点。

| 用例 | 模型候选 | 期望 | 实际 |
|---|---|---|---|
| 精确回显 | 原文 | 拒绝，`memory-read-echo` | 通过 |
| 改写（同义换词） | 「报表游标可复用的时长是 24 小时。」 | 不写；pending 1 条，`memory-read-unverified`，含 read id | 通过 |
| 用户自己复述并改值 | 「…可复用的时长是 12 小时。」+ 同句 quote | 写入 1 条 | 通过 |
| 改写 + 同轮新事实 | 改写 + 「报表导出目录是 out/。」 | 只写新事实；改写进 pending | 通过 |
| 跨类型复制 | 原文是 preference，候选是 decision | 不写；pending 带 read id | 通过 |
| 无读取证据的改值 | 「…复用 6 小时。」（用户只问了问题） | 不写；pending 1 条 | 通过 |
| 用户明确改值 | 「更新一下：…复用 6 小时。」 | 写入 1 条，旧值保留（共 2 条） | 通过 |

## 3. 边界

- 只测`ctx_read`路径的改写；`ctx_find` 的多条结果与长正文在 `p100` 里已有覆盖，二者共用同一来源门。
- "历史重复"（库里本来就存在同正文的旧节点）**不会**被自动合并或删除；本轮只确认新候选不会再加一条。
- 判定依赖用户原句是否包含支撑，不做语义等价判断；真正的语义改写仍可能被当成新事实，只要模型同时给出了用户原话里的片段。这不是回归，是当前取舍：宁可留待核对，不静默判重。
