## 1. 这条基线测什么、不测什么

| 维度 | 是否测量 | 说明 |
|---|---|---|
| 事实写入是否命中冻结期望 | 测 | 走真实 `distill()` 写入路径（秘书化、去重、否定/数值守卫、回显守卫、来源字段） |
| 无来源新增、重复写入 | 测 | 以冻结的"不应出现"与最终库状态比对 |
| 自有工具回显是否被再次写成新节点 | 测 | 冻结 `ctx_find` / `ctx_read` 结果，检查新增节点与 skip 原因 |
| 范围内检索 Top-1/Top-5 | 测 | 真实 `searchEntity` 后端，语义通道关闭，只读词面 |
| 跨实体/跨工作区/历史记录是否被当作当前事实 | 测 | 冻结 `forbidden` id，逐场景报告命中 |
| 无答案题的候选 | 只列不判 | 候选数、状态照实记录，不记为答对或答错 |
| **模型抽取能力** | **不测** | 候选由固定夹具提供（见下） |
| **最终回答正确率** | **不测** | 不生成回答；报告中固定写 `not measured` |
| token、账单 | 不测 | 无真实模型调用；不用字符数冒充 token |

**输入方式**：每个场景的种子节点用 `db.insertWithId`（固定 id、固定 `createdAt`）写入临时工作区；写入阶段调用真实的 `extract.distill()`，其中 `llmCall` 是测试替身，只返回夹具里冻结的候选——所以这是**"冻结候选 + 真实写入守卫"基线**，不是真实模型的抽取质量。

**读取方式**：每个可回答场景用真实 `searchEntity({entityId: anchor, query, limit: 5})`（词面通道，`semantic` 未请求），与面板和 HTTP 端点共用同一后端代码。

## 2. 语料

26 个场景，6 类，18 个开发场景 + 8 个留出场景；每类 ≥4。期望事实、相关/禁止 id 在首跑前写死，本轮未改。

| 类别 | 场景 | 覆盖点 |
|---|---|---|
| `same-name-cross-workspace` | A1–A5 | 同名实体、同名事实、跨工作区同 ID 不同正文、锚点无事实 |
| `numeric-negation` | B1–B4 | 数值改动、否定、单位变化、标识符 |
| `history-supersede-expiry` | C1–C4 | supersede 链、过期、归档、同名新旧无替代边 |
| `tool-echo` | D1–D4 | `ctx_find`/`ctx_read` 回显、同轮回显+新事实、数值改动不算回显 |
| `no-answer-out-of-scope` | E1–E4 | 只存在于别的工作区、锚点孤立、同名旁支、仅字面相关 |
| `identifier-zh-en` | F1–F5 | 精确标识符、中文问英文正文、英文问中文正文、中英混排 |

## 5. 失败与需要说明的样例

1. **A3（无来源新增，唯一 1/1）**：本轮问"导出格式是什么？"，冻结候选给出另一个工作区里的"导出格式固定为 XLSX。"。写入路径把它当成一条正常 decision 落库（新节点 `#202`），说明**写入守卫不校验候选是否由本轮对话支持**（只做密钥、日期、类型、偏好线索与去重/否定/数值守卫）。这不是评分器误判，也不是夹具写错；当前策略如此，本轮不修改。
2. **C4（历史记录排在前面）**：两条同名同域、都处于 active 的"审计记录保留 30 天 / 90 天"，没有 supersede 边。搜索把**较旧的 30 天**排在第一。有替代边（C1）、过期（C2）、归档（C3）的场景都能正确排除旧记录，说明缺的是"同名新旧但没有显式替代关系"时的排序信号。
3. **F2 / F5（中英跨语言词面检索为 0）**：中文问、英文正文（`Upstream rate limit is 60 rps per key`）与英文问、中文正文（`备份保留 14 天`）都返回 0 个候选。词面通道不做跨语言归一；这是当前默认路径的真实差距，语义通道默认关闭。
4. **A1 / A2 / F1 / F4 的 Top-1 由锚点自身占据**：结果是 `[101, 201]`，锚点实体排在事实前面。按"排除锚点"看是 4/4 命中。两列都报告，不修改冻结的相关集。
5. **D3 的回显是被"精确去重"拦下的，不是被回显守卫拦下的**：同一轮里既有 `ctx_read` 回显又有新事实时，回显候选没有产生新节点（好），但 `skipped` 里没有 `memory-read-echo` 记录，`applied` 里是一条 `merge`。结果正确、归因不同；报告里分开写。
6. **规则层冗余（3 条）**：`记住：…` 类句子会同时被确定性规则整句写成 preference、被模型候选写成 decision（A1、D3 等）。不是同正文重复，但同一事实在库里出现两次，属于后续"少花代价"要处理的冗余。

## 6. 可比较与不可比较

- **可比**：同一夹具、同一版本下，不同实现之间的写入判定、Top-1/Top-5、禁止 id 命中、候选数可直接对照；留出集可用于放行判断。
- **不可比**：与历史 `bench-quality-v2` / `bench-extract-cost` 的分数不可比（语料、判据、是否有真实模型都不同）；本基线的候选由夹具提供，**不能**当作模型抽取能力；Top-1 低不代表最终回答低（未测）。

## 7. 局限

- 单工作区合成库，规模很小（每场景 2–4 个节点）；跨工作区的检查方式是"另一个库 + 同 ID 不同正文"，不是多库并发。
- 检索只测实体范围词面通道；不支持多跳、不做融合排序，也没有测自动召回/短地图注入。
- 无答案题只记录候选，没有人工判断"这些候选是否构成误导"。
- 时延含模型替身与临时建库开销，不代表宿主内实际查询延迟。
