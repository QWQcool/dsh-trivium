日期：2026-11-18。基于 `fe78243` 的本地开发改动。三项一起实现后集中验证；使用合成工作区，正式桌面、正式 npm 包和用户记忆均未改变。

## 任务记忆包

`ctx_find` 可传 `entity_id`，在当前会话所属工作区内做一跳词面检索并返回完整事实，预算由可选的 `pack_tokens` 控制。`since` 使用同会话、同实体、同问题和同预算返回的 `Cursor`，只回送变化；相同结果不重发正文。退出所选范围的 ID 单独说明，相关冲突成组呈现。游标过期或切换任务时明确请求重新查，不回退到无范围搜索。开场短地图和默认召回策略不变。

在相同两个事实的合成比较中，原详细包 **147**、紧凑包 **60**、无变化答复 **14**、单事实变化 **41** 个估算 token。覆盖保持；无关库内写入未带来额外正文。四个工具仍在原位置，工具定义估算 **529 → 547**。这是工具结果和定义的测量；实际对话总用量、答案质量与费用未测。

## 抽取与恢复

需要抽取的来源窗口先落盘。启动恢复最长等 8 秒；抽取准备超过 30 秒时，取消模型等待并释放写锁，保留候选和来源。受控模型故意忽略取消，旧结果迟到后未写入；新一次恢复在旧请求还没结束时只写一条。已进入同步提交的操作不被强停。

已有记忆的工具返回不作独立证据。可确认的原样回显仍跳过；无法确认的新说法保留待核对，能定位到旧记忆时给出提示。独立用户或有名字的成功外部工具来源可支持新事实；明确要求重分类时，仅可重用核对过的原文，并标明是用户操作。旧事实未自动删除、替换或合并。

真实账号模型 `deepseek-flash` 用两份固定合成窗口、实际 `ctx_read` 返回和真实抽取入口验证：复述 ApricotWorker 的旧值 4 次时，模型给出 `{"candidates":[]}`；增加独立用户陈述「ApricotWorker 的生产重试次数为 7 次。」后只写入一条，旧值两次都保留。**2 次请求**，总输入 **1015**（其中缓存读取 **384**）、输出 **86**，金额未测。对模型确实产生改写候选的情况，另用受控输出验证其留在待核对，而非丢弃或入库。

原冻结 26 场景一次复核：应记 **9/9**、旧事实 **6/6**、回显误写 **0/3**、无来源误写 **0**、冗余新增 **0**、检索和包命中 **12/12**。待核对 **1 → 2**：D3 现明确保存回显候选用于人工核对；旧版在这个场景由精确去重兜底。原冻结题和期望未改。

## 文档证据

「上下文 → 文档依据」可选择一个 UTF-8 `.md` / `.markdown` / `.txt` 文件（≤64 KiB）或粘贴正文。选文件只填入本地草稿，保存才写入；不按文件名从主机读取路径。保存原文和 UTF-8 边界，用 [TDB 0.9.1 的分组词面检索](https://github.com/YoKONCy/TriviumDB/blob/46f767f8c5befeb7da091267f2b19052f3cba8d9/docs/documents.md#分组文本检索)在指定来源及修订里取片段。一段重复文字也可以通过选中实际位置来关联。长文片段示例为 **613 → 74 估算 token**；旧单块来源也能定位片段而无需重写。修订对照保留旧引用，并显示新版本的同一段或旧位置附近的文字。附近文本不会被当作已验证替代。
