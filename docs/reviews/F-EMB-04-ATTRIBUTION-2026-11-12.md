# F-EMB-04：纯向量 32/32、混合检索 31/32 的归因

2026-11-12，生产源码基线 `3c1830f`，TDB 0.9.0。**完成归因与对照，未修改 lib/、排序、权重、默认预算、内核或版本，未发布。**本轮只扩展既有评测脚本、增加诊断问题和证据文档。

## 结论

唯一漏题是 **Can a 768-number vector be accepted by this plugin?**。正确文档为 `embeddingdim` / 节点 26，正文规定向量必须恰好包含 1536 个有限数值、错误维度被拒绝。

该文档在纯向量与精确向量搜索中都排第 **1**，在原生混合检索中排第 **19**。插件只接收前 16 个原生候选，关键词补召回、实体锚点和图扩展均未将它找回。因此它没有进入最终 Top-5。

造成第 19 名的机制是：**正确文档与问题无字面 token 重合；18 条其它文档命中了通用词或泛化词，在当前加权 RRF 下都获得更高分。**扩大候选池后，正确文档仍排第 19，不能仅靠增加候选解决 Top-5 漏题。这是当前查询文本、融合配置与候选策略的组合结果，本轮没有发现向量损坏或原生算分偏离实现。

## 逐层证据

复用上一轮持久化的 36 条合成业务记忆，以只读句柄打开；重新调用同一份本地 GTE 权重生成问题向量。固定相同向量，逐层比较。问题、相关文档标签和原始 32 题均未修改。[原质量语料](../../scripts/fixtures/local-embedding-corpus.json)

| 层 | 正确文档的位置 / 结果 |
|---|---|
| 纯向量 `search` | 第 1，余弦分数 0.4680464 |
| 精确向量 `searchExact` | 第 1；原 32 题的 Top-5 与普通向量搜索逐题相同 |
| 原生文本单通道 | 未命中正确文档；共命中其它 18 条 |
| 原生混合完整结果 | 第 19，融合分数 0.9836066 |
| 插件的原生候选阶段 | 前 16 条中没有正确文档 |
| 关键词补召回 / 实体锚点 / 关系扩展 | 均为空 |
| 插件将候选池扩大到全部 36 条（诊断） | 正确文档回到候选，但最终仍第 19 |

原 32 题中，原生混合与插件最终 Top-5 顺序 **32/32 相同**。本漏题所有候选的插件词面加分和 `rankBoost` 都为 0。当前小库没有业务边；关闭图扩展结果逐题不变。最小分数从 0.01 改为 0 的诊断也不改变 Top-5。原生观测为 36 个向量候选、未走 QuIVer。由此排除了本轮中 ANN、后置加分、到期过滤或图扩展导致这个差额的解释。

### 原生融合怎样把第 1 名压到第 19 名

插件传入 `hybridAlpha=0.2`。TDB 0.9.0 的 Node 绑定将它换算为文本排名权重：

`textBoost = max(1 - alpha, 0.1) × 3 = 2.4`

它并非 20% 向量分数与 80% BM25 原始分数的线性相加。两通道均有候选时，按各通道名次融合（名次从 1 开始）：

`score = 60 / (60 + denseRank) + 2.4 × 60 / (60 + sparseRank)`

缺席某通道时，该项为 0；整个文本通道为空时保留稠密原始分数。源码见 [Node 参数换算](https://github.com/YoKONCy/TriviumDB/blob/v0.9.0/src/bindings/nodejs.rs#L2421) 与 [RRF 实现](https://github.com/YoKONCy/TriviumDB/blob/v0.9.0/src/database/pipeline.rs#L559)。用两个通道的实际名次及 f32 运算重建，本题全部 36 个融合分数与实际结果的误差为 **0**。

文本单通道对照使用全零查询向量并保留正的 0.01 门槛，排除零余弦的稠密候选。这里只使用该输出的文本名次；其返回分数已经是排名变换后的分数，不能称为原始 BM25 分数或置信度。

| 文档 | 稠密名次 | 文本名次 | 本题字面重合 | 融合分数 |
|---|---:|---:|---|---:|
| 正确的维度契约 | 1 | 无 | 无 | **0.983607** |
| 轻量 payload 读取 | 2 | 1 | a、vector | 3.328398 |
| 卸载行为 | 4 | 5 | plugin | 3.152885 |
| Node 运行时 | 5 | 6 | plugin | 3.104895 |
| 独立快照 | 15 | 4 | can、a | 3.050000 |
| 包管理器 | 23 | 2 | this | 3.045472 |

稀疏通道最后一名（第 18）的文本项本身就约为 **1.846154**，已经大于正确文档的总分 0.983607，尚未加上它自己的稠密项。因此这 18 条全部排到正确文档之前。

原生 BM25 的 tokenizer 保留 `a / can / this / plugin` 等词。插件有自己的词面覆盖规则，但它不改变传给原生混合检索的完整问题。[文本分词与 BM25](https://github.com/YoKONCy/TriviumDB/blob/v0.9.0/src/index/text.rs#L76)

固定原问题向量，仅改变**临时诊断调用**的文本通道输入：

| 文本通道输入 | 正确文档名次 |
|---|---:|
| 完整原问题 | 19 |
| 只保留 can a be by this plugin | 19 |
| 只保留 768 number vector accepted | 2 |
| 关闭原生文本通道 | 1 |

这组干预验证了通用词的影响。它不是上线的停用词规则，也没有选取新权重。

## 固定对照结果

各方案复用同一组向量、正文、标签与生产函数。`plugin-text-off` 仅在临时代理中把原生查询文本置空，其余插件步骤保留；`pool-all` 仅扩大临时调用的原生候选上限。lib/ 文件不改。

| 原 32 题 | Top-1 | Top-5 |
|---|---:|---:|
| 关键词 + 图 | 22/32 | 25/32 |
| 混合检索，原始问题向量 | 26/32 | 30/32 |
| 纯向量 / 精确向量，带查询指令 | 23/32 | **32/32** |
| 当前原生混合 / 当前插件混合 | **27/32** | 31/32 |
| 仅扩大原生候选池 | 27/32 | 31/32 |
| 仅关闭原生文本通道，保留插件规则 | 26/32 | 32/32 |

关闭文本通道使 2 题 Top-1 改善，也使 3 题 Top-1 退步：公开发布审批、宿主写入期间的外部稳定读取、快照捕获后的新事实。故不能根据 Top-5 的一题差额宣称纯向量整体更好，也不能据此直接移除文本通道。

另加 [14 道归因压力题](../../scripts/fixtures/embedding-attribution-queries.json)，包含维度改写、数值、否定、精确名与语义改写。它们是在看到漏题之后编写的，**不是独立盲测集**，不与原 32 题合并计算通用准确率。

| 14 道压力题 | Top-1 | Top-5 |
|---|---:|---:|
| 纯向量 / 精确向量 | 13/14 | 14/14 |
| 当前混合 | 10/14 | 13/14 |
| 关闭原生文本通道、保留插件规则 | 13/14 | 14/14 |

压力题新增的漏题为“in_workspace 边是否使实体不再孤立”：正确文档纯向量第 2、原生融合第 10。它仍在前 16 个候选中，却没有进入 Top-5，再次说明候选池大小与最终排序是两个问题。

三道原有无答案题，在纯向量和混合下都返回了候选。这里测的是候选返回，未生成模型回答；它不能表述为三次错误回答，也不能认为有候选就有答案。

## 稳定性与复现

- 原小库读取前后文件 SHA-256 完全一致。换序调用重复 5 次，本漏题名次和分数一致。
- 生产 store 的临时副本仅增加检查函数导出并改写 import 路径；46 题逐题核对副本与生产函数输出相同。原排序函数未改。
- 用缓存的真实向量重放，**51/51** 检查、HTTP **0**。停止模型运行器后，再从完整缓存离线新建库，**50/50** 检查、HTTP **0**。
- 重新生成 36 条正文向量，与旧库的 f32 向量摘要完全相同。原 32 题的结果复现。
- 另控制工作区 bookkeeping 文本：换成公开文本或不入全文索引，原 32 题主结果及本漏题第 19 名不变。该索引参与 BM25 语料统计；压力题的 raw-query Top-1 有 1 题随此改变，已保留差异，不能把不同索引语料视为相同实验。
- 正式真实 embedding 调用 **131 次**（95 次查询、36 次正文核对），另有 2 次单题探测；全部 loopback、同一份本地权重，费用 **¥0**，付费模型生成调用 0。
- `node scripts/run-all.mjs` → **85/85**。scripts 仍 120 个 .mjs；没有新增 smoke 或 UI 测试。生产 lib/、package.json、lockfile 和冻结 UI 测试保持不变。

主评测与离线重放的复现命令（输出目录可自行命名）：

```powershell
node scripts/verify-local-embedding.mjs --attribution --source-workspace .tmp/local-embedding-read-20261112-131530/measurement-complete/quality --output .tmp/emb04-real --budget 0 --nodes 0
node scripts/verify-local-embedding.mjs --attribution --source-workspace .tmp/local-embedding-read-20261112-131530/measurement-complete/quality --query-cache .tmp/emb04-real/query-cache.json --offline --output .tmp/emb04-replay --budget 0 --nodes 0
```
