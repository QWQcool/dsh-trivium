# dsh-trivium 0.9.0

0.9.0 正式版交付默认保留卸载数据、抽取来源检查和去冗余、候选核对入口、实体范围检索与显式任务记忆包，以及 TriviumDB 0.9.1。功能基线为 `10e09ac`，发布只同步版本和文档，运行时代码保持该验证基线。

## 交付内容

- 移除旧 `preuninstall` 清理钩子，普通卸载保留工作区记忆、设置、pending、旁路、快照、变更记录和偏好导出。新包不替用户清理历史重复节点。
- 自动抽取区分可核对的已有记忆回显与新事实。无法核对来源的模型候选持久保存，不进入有效记忆；来源不变时不反复付费重放，也不阻挡其他窗口。
- 在来源、敏感值、日期和预算守卫之后抑制被完整事实覆盖的同轮规则副本，保留模型失败时的规则兜底与真正的长期偏好。修正“允许读取”被误判为读取请求的问题。
- 「运行记录 → 待补写」提供来源片段、补充依据并核对、明确确认记住。核对不调用模型；确认只插入内容，不替代、合并或删除旧事实。工作区/候选/ETag、持久回执和落盘确认保护重试；缺失来源序号保持 null。
- 「上下文」提供实体范围检索、词面/语义分通道、live/快照来源与显式 `packTokens`。记忆包默认 0；正预算选择完整事实、路径和已有来源，同名有效备选保留歧义，不自动判真伪。
- 交付已完成的批量持久化、未变化文本索引跳过和 16 条向量写入合并。性能数字只对应各自历史合成负载，单次写入尖峰仍有待改进。
- 运行内核固定 `triviumdb@0.9.1`。四工具、少注入默认和人工替代提案继续沿用；记忆包没有自动接入工具或默认召回。

## 升级与数据保留

1. 完全退出桌面应用（包括托盘），或停止 Web 宿主。**不要先卸载已发布的 0.8.9**：它含旧的破坏性卸载脚本。
2. 在原 profile 直接升级：

   ```sh
   dsh plugin --profile desktop add dsh-trivium@0.9.0 --ignore-scripts
   ```

   Web 使用 `dsh plugin --profile web add dsh-trivium@0.9.0 --ignore-scripts`。`--ignore-scripts` 用于跳过包生命周期脚本；命令不要求删除原 `.dsh` 或新建工作区。
3. 重启原宿主，仍选择原工作区。0.9.0 普通卸载保留数据；若以后确实要清除，需用户自行明确选择文件。

**插件版本与内核版本不同**：发布插件 0.8.5–0.8.9 使用 TDB 0.9.0，本版使用 TDB 0.9.1。新内核打开并 checkpoint 后可能推进到 `.tdb` v13 / WAL v6，旧内核不能直接读取。若需要回退，在首次打开前保留完整 `.dsh` 文件组（含 `.vec`、`.wal`、`.text`、索引和 payload 附属文件）；单独 `.tdb` 或 Git JSONL 都不是完整副本。回退旧副本不包含保存后新增的记忆。不要用旧内核直接写新格式库。

本机正式桌面已使用 TDB 0.9.1 的本地构建，本次 npm 发布不安装、重启或迁移该桌面实例，不操作现有记忆文件。已有损坏库不会因发版自动修复。
