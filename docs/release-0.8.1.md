# dsh-trivium 0.8.1

状态：待发布（发布后补回执）。本轮是 0.8.0 的**正确性补丁 + 证据批**：修复长正文尾部在注入里被截掉、
以及一个藏在预算前面的候选条数上限；不改四工具、数据格式、默认开关和内核 pin。

## 变化

### 注入完整性（唯一的产品行为改动）

- **长事实保留尾部**：`preserveEnds()` 保留头 89 + `…` + 尾 110 字符，只在上限内截断，短文本原样。
  同一条规则贯穿三层——检索行（`store.formatHit`）、版本投影与更正提示（`revisions`）、
  候选塑形与最终渲染（`context-budget`）——避免上游先把正文截残、下游再按“已经截过”渲染。
  背景：C4 的 S05 里，关键命令位于 500 字正文的尾部，旧实现只保留头部，注入里只剩背景。
- **去掉候选条数上限**：`recallCandidates()` 原先在 300 token 预算之前还有一处未写进文档的
  `topK: 3`，六条并列事实被砍到三条而整块只用了 89 token。现在与 anchor 模式一致取 8，
  真正的约束交给预算；装不下的整条丢弃并记 `over-budget`，不截半条。
- 这两处只在**注入/装配层**，不改变检索排序算法、不改变写入、不改变工具输出契约。

### 证据与测量脚本

- **C4 对手验装与同语料对照**：`dsh-goodmemory@0.1.2` 与 `dsh-memory`（HEAD `29c361a`）在本机均可安装、
  可走真实 `agent/pre-step` 注入；7 臂 42 格，臂间差异如实记录（含对手默认门槛会改变结论这一条）。
- **D0 复测**：同一协议、修复后重跑 144 格，我方注入臂 18/18、平均注入 97 token（同库完整纯文本 360）；
  第二模型 `deepseek-v4-pro` 上结果一致。1k/10k 规模档、跨工作区泄漏 0 条、同轮累计 53/300、
  损坏修订链被拒绝等可管理性证据一并记录。
- **D1/D2 成本口径**：D1 实测“10 轮 + 压缩”下累计输入 0.51×、费用 0.85×、正确率不降；
  D2 用真实提示词测抽取成本（每轮 ¥0.00179/会话、批量 ¥0.00086/会话），
  **含抽取后 10 轮净账仍为负**（−¥0.00139 / −¥0.00046），外推 16–20 轮才可能翻正，未实测。
- 所有 bench 同时记录峰价与谷价，对外口径统一用谷价；证据账本带 sha256 清单，
  `.gitattributes` 固定账本换行，避免 Windows 检出改变哈希。

## 升级

```sh
dsh plugin --profile web add dsh-trivium@0.8.1
```

升级前停止宿主并备份完整 `.dsh/trivium.tdb*` 文件组。数据格式未变（JSON `version: 2` / JSONL `v: 2`），
无需迁移；回退到 0.8.0 不会破坏库文件。

## 已知限制

- 尾部保底只保证“头 + 尾”在 200 字符内可见；关键信息落在**中部**且单条远超 200 字时仍需要 `ctx_read`。
  本轮没有把注入改成全文，也没有改变“摘要 + 工具读取”的分工。
- C4/C/D 的数字来自合成语料、单/双模型、n=1–3；不是用户真实会话，也不构成与同类插件的产品排名。
  对手的工具面没有对照，`goodmemory` 在 S05/S07 返回 0 的内部原因仍未定位。
- 50k 节点档在 0.8.0 记录里被判不合格，本版未宣称改善；本轮实测覆盖 1k 与 10k。
- 真实宿主端到端（UI/审批/压缩/多轮）仍未覆盖；Web 与桌面验收层级见 [文档入口](README.md#验证覆盖与缺口)。
