# A-9：真实压缩后的跨会话召回（补上 A-5b 的空白格）

日期：2026-10-30。分支 `codex/r1-r2-reliability`。真实模型 3 次运行、**¥0.059296**。未发布、未推送。

前置：[A-5](A5-WIDER-BASELINE-2026-10-30.md) §3 的压缩尝试因工具循环中止；本轮加了闸门后重跑。

## 1. 做法

- 代理给**第一个带工具的 agent 请求**注入一次 `context_length_exceeded`（`R3_PROXY_INJECT_OVERFLOW=1`，只对 `tools>0 && body>40KB` 的请求生效，抽取/摘要调用不会被误伤）；
- 宿主走它自己的「总结 → 重试」路径（这一步是真实代码，不是模拟）；
- 之后在**新会话**问同一个事实，只有落库记忆能回答。

闸门：每个任务最多 10 个请求或 120 秒，超了就杀进程并记录（防止 A-5b 那种 43 请求的工具循环把预算烧穿）。

## 3. 必须说清的限制

1. **闸门在 2/3 轮里触发过**（每任务 10 请求上限），说明 setup 轮出现了较多请求（压缩重试 + 工具调用）。事实与回答都在闸门触发前完成，但**这不是一次“完整无中断”的会话**——只能说“压缩发生了、事实落库了、新会话答对了”。
2. **`aborted` 标记是每轮累计而非每任务**，所以表中无法区分“哪一步被截断”。要做成正式指标，需要按任务记录。
3. **只有 3 次**，且压缩由注入的溢出触发，不是上下文自然涨满。真实长会话的压缩点、总结质量和多次压缩叠加都未覆盖。
4. 摘要调用的输出没有单独评分——只验证了“压缩后事实仍可用”，没有验证“摘要本身写得对不对”。
