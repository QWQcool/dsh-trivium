# D1 结果：记忆让「压缩」变得安全，但省不省钱取决于会话长度与抽取成本

> **R1/R2 更新（未发布）**：旧模拟没有持久化注入历史，也未计入首轮短图，0.514 仅是旧模拟协议的数值，不能宣传为真实宿主节省。D1-R2 已修历史/短图/压缩事件装配，但未运行新付费实验，完整宿主闭环仍待下一批。 以 [R1/R2 验收](R1-R2-RESULTS.md) 为当前入口。以下保留原始报告，数字不被改写成新实验。


日期：2026-10-29。协议见 [D1-PLAN](D1-PLAN.md)（含跑前追加的 D1b）。基线 `c8ab07d`。

## 1. 设计一句话

同一批 6 个会话，第 1 轮交代 3 条约定，第 4 轮起**只保留最近 1 轮历史 + 只含第 1 条约定的摘要**
（第 2、3 条明写已压缩）。压缩后还要答对「第 2、3 条是什么」，就必须靠记忆。
四个臂只差「有没有记忆」和「压不压缩」。

## 2. D1（5 轮，120 次调用，¥0.0515）

| 臂 | 压缩 | 通过（ask1+ask2） | 累计 prompt | 注入 token | 费用 |
|---|---|---:|---:|---:|---:|
| `none-full` | 否 | 12/12 | 4317 | 0 | ¥0.01298 |
| `none-compact` | 是 | **6/12**（ask2 全错） | 3373 | 0 | ¥0.01146 |
| `trivium-compact` | 是 | **12/12** | 4373 | 821 | ¥0.01377 |
| `plain-compact` | 是 | 12/12 | 4582 | 1405 | ¥0.01332 |

- **H1（≤0.75）不成立**：4373 / 4317 = **1.01**。5 轮里压缩只覆盖 2 轮，注入把省下的又加了回去。
- H2 成立：12/12，与不压缩相同。
- H3 成立：4373 < 4582（纯文本按整库投影注入更贵）。

**5 轮结论：记忆的收益是「压缩后仍然答对」，不是「更便宜」。**

## 3. D1b（10 轮，240 次调用，¥0.1185）

| 臂 | 通过 | 累计 prompt | 注入 token | 费用 | 相对 `none-full` |
|---|---:|---:|---:|---:|---:|
| `none-full` | 12/12 | 15660 | 0 | ¥0.03254 | 1.00 |
| `none-compact` | 6/12 | 7126 | 0 | ¥0.02615 | 0.46（但错一半） |
| **`trivium-compact`** | **12/12** | **8052** | 821 | **¥0.02772** | **0.51** |
| `plain-compact` | 12/12 | 9781 | 2810 | ¥0.03207 | 0.62 |

- **H1b 成立**：8052 / 15660 = **0.514**（门槛 0.75）。
- H2b 成立：12/12，且 ask1/ask2 各 6/6。
- H3b 成立：比纯文本省 1773 prompt token（18%）。
- 费用口径同样成立：¥0.02772 vs ¥0.03254，**低 14.8%**。

逐轮拆开看，差异完全落在压缩之后：`none-compact` 的 `ask2` 是 **0/6**，另外三个臂都是 6/6。

## 4. 现在能说什么（带条件）

**能说：** 在「会话 ≥10 轮 + 会压掉早期约定」这一条件下，装记忆插件让同一批任务的**累计输入 token 降到 0.51×**、
**费用降到 0.85×**，正确率不降（12/12），且优于把同样事实整段塞进去（0.51× vs 0.62×）。

**不能说：** 「装了就省钱」。5 轮时是 1.01×（不省），说明节省是**会话长度的函数**，两次测量之间出现交叉，
交叉点本身没测。短会话里记忆买到的是**正确性**，不是省钱。

**最关键的缺口（必须写在任何对外材料里）：** 本实验**不计抽取成本**。
D2 已把抽取测准（真实提示词、18 次调用）：每轮抽取 **¥0.00179/会话**、整段批量 **¥0.00086/会话**，
而 10 轮会话检索侧只省 **¥0.000402/会话** → **含抽取后净账仍为负**（−¥0.00139 / −¥0.00046）。
原因是省下的 token 大量落在缓存价（¥0.02/M），抽取花的是未命中输入（¥1/M）+ 输出（¥4/M）。
详见 [D2 抽取成本](D2-EXTRACT-COST.md)。按外推，约 **16–20 轮**才可能翻正（未实测）。

所以现在的准确表述是：**检索侧已经省了 49%，但含写入后还没到净省**；下一步是「按内容门控 + 批量抽取」，
这是工程任务，不是可以略过的脚注。

## 5. 未覆盖

1. **抽取成本未计入**（见 §4）；抽取质量也未测——本轮事实是直接种入库的。
2. 真实 host 的压缩算法未接入，本轮用固定摘要模拟；换一种摘要（保留更多/更少）结论会变。
3. 会话只有 6 个、单模型、n=1；10 轮与 20/30 轮之间的交叉点未定位。
4. 只测「事实复用」类任务，不含工具调用、代码修改、多话题切换。
5. 摘要里保留了第 1 条约定，这对 `none-compact` 是偏宽松的设定（它仍能答对 ask1），
   若摘要什么都不留，`none` 会更差、对比会更悬殊——**这一项没有再跑，也是故意不跑**，
   因为那会把对比做成单方面有利。
