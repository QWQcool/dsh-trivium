## 3. 边界与工作方式

### 本批必须保留

- 不重写插件；四工具签名、默认开关、DIM=1536、已发布版本号不变。
- 继续采用当前内核 pin；不升级数据库，不引入新的常驻服务。
- 300/400 估算预算不扩大；审计记录仅供管理界面读取，不自动注入模型。
- 保留已修的混合句、空响应留 pending、成功消费/失败重试、历史 pin 与更正预算语义。
- 旧事实不进行无来源批量重解释；旧数据缺来源明确显示未知，不补造来源。
- 敏感值的拒绝规则继续覆盖事实、候选、审计与 UI；不依赖模型是否开启推理来保证过滤。

### 执行约定

开工后按 **W1 → W2 → W3 → W4 → W5** 连续推进。每片一个可审查提交和独立证据目录；只在明确阻塞或超出边界时停，不要求用户逐片转发确认。提交和推送仍须按本机 AGENTS 执行脱敏检查；本批不发布、不改版本、不自动合并 main。

这是开工计划，不是本消息已经授权执行整批。用户明确开工后再开始实现。

## 5. 五个切片

### W1：来源贯穿与可核验摘录

**目的**：给后续替代/日期判断提供实际源事件，而不只相信模型回填的 quote。

主要文件：`lib/index.js`、`lib/extract.js`、`lib/provenance.js`、pending 与来源专项回归。

实现要求：

- 从已观察到的宿主事件保存可用的会话、消息 id 或 event sequence、角色、源时间、所在范围；字段来自真实事件，不从日期或节点 id 猜一个宿主消息 id。
- 缓冲、合批、失败 pending、恢复重放、候选校验、最终落库贯穿同一来源引用。多个源事件共同支持一条事实时可记录有限引用集合。
- 将“源事件信息已记录”“引用片段匹配”“宿主原文当前可读取”分别表示。若缺定位接口，仍如实展示摘录和定位信息，不做假链接。
- 候选引用必须匹配允许的源事件；用户陈述、助手建议/承诺、工具结果区分。模型自己写出的 quote 不能反过来成为用户证据。
- 旧 pending / 旧节点继续可读；缺字段降级为未知，不删除已有事实。普通记忆保留与高影响自动替代分别决定，来源不明不得自动隐藏旧决策。
- 来源集合和文本均有上限；本批不复制全部会话，不搭建第二套全量聊天档案。

**验收**：

1. 中文混合句、合批多条、跨轮引用都能对应正确的源事件与角色。
2. 同一句重复两次不会凭文本相同误判为同一个事件；同一事件重试不会重复登记。
3. 失败后重开再处理，仍指向原源时间/事件，而非重放时间/当前会话伪装的新来源。
4. 助手猜测和伪造 quote 不能成为用户确认；源缺失显示 unknown/unavailable。
5. 原有 50 组保持通过；新增正常正文不能因为来源增强而被整轮吞掉。

**停止条件**：若宿主没有定位能力，交付诚实降级，不为实现跳转私读真实会话目录。若必须改变公开数据格式，先提出兼容方案，不静默改 schema。

### W2：安全的自动替代

依赖：W1 来源契约。主要文件：`lib/extract.js`、`lib/revisions.js`、`lib/store.js`、p48 或其新增独立反例。

实现要求：

- 替代意图由受支持的当前来源证明，不能只看候选是否含替换词。
- 仅在同一作用域、对象明确、被替代的当前节点唯一时自动执行。问题、讨论、假设、引用、否定替代及“保持原样”的对象不得退休。
- **停止按节点 id 给多个候选串链。** 同名、多个对象或关系不明时保留原有效事实，把新意图标为待处理；待处理不是模型失败，不自动付费反复重试。
- “明确替代多个独立决策”的语义不能硬塞进线性版本链；本批转既有人工处理流程，不扩大图关系约束。
- 模型与规则生成的重复候选必须有来源/内容依据才能判重，不能凭同名视为同一事实。
- p48 目前包含“多个同名目标都串入替代链”的断言；该断言随本片明确改为歧义保留/待处理，记录这是契约纠正。合法单目标、历史读取和幂等正例继续保留，不能为维持旧断言而保留错误算法。
- 使用既有版本校验和原子提交边界，避免事实先落库、随后半条错误链留下副作用。新候选、替代操作与来源绑定需可回查。
- 语义不明的候选不能同时以“已确认当前决策”进入短地图，造成两套互相矛盾的当前答案。

**验收**：

- 明确 A→B 成功，旧 A 默认不作为当前事实，显式历史读取仍可用。
- “仅讨论是否替换 A”没有版本边变化。
- “不再使用 A；B 保持原样”中 B 仍当前。
- “不要替换 A”“假如换掉 A”“文档提过更换 A”均不自动退休 A。
- 同名不同对象不串链；规则/模型重复写入不会多建替代；跨工作区无影响。
- 写入故障、重试、重开、并发与版本链上限下，逻辑快照满足原子性和幂等性。

**停止条件**：任何反例能隐藏不相关的当前事实，或失败后留半条链，不能进入真实模型试验。不能把测试改成“所有匹配旧节点都退休”来取得绿灯。

### W3：有依据的日期转换

依赖：W1，复用 W2 的候选来源核验。主要文件：`lib/extract.js`、必要的日期解析辅助模块、p49 或新增专项。

实现要求：

- 以原始表达所属事件的时间和确定时区为锚点；pending 重放不能使用重放日把“明天”重新算一遍。
- 第一版先明确支持范围：有效的数字绝对日期，以及“今天/明天/昨天/后天/前天/下周某星期”等可确定表达。定义周一为周起点并测试跨月/跨年；其他表达保留原话与不确定性。
- 将候选日期与对应源事实绑定。其它句子说过“明天”，不授权本条候选写任意未来日期；一个源事件里出现别的对象的日期也不能直接借用。
- 日期合法性、来源支持、相对解析分别检查。取消“位于宽时间区间就认正确”的放行逻辑。
- 确定的日期可以规范化；无法确定的日期保留原话或候选待核，不把删掉日期后的句子伪装为等价事实。
- **事件发生时间、陈述时间与失效期限分开**；不从普通叙述日期自动生成期限，显式期限沿用现有工具/设置契约。

**验收**：

- 固定源时间 2026-10-30：“明天”只支持 2026-10-31，不支持 2027-03-01；“下周五”对应 2026-11-06。
- 跨日重放仍使用源时间；跨月/闰年/非法日、时区边界均有反例。
- 两个对象、两个时间、无关相对词、引用他人的日期，不能互相授权。
- “以后”“月底前”等未冻结语义不被强行精确化；原文仍可追溯。
- 每次规范化、拒绝或待核都有原因和源依据，无静默错误调整。

**停止条件**：错误日期仍能作为已确认事实写入，或修复靠删除全部日期/全部事实，均不通过。

### W4：有界的变更记录与管理界面

依赖：W1–W3 的事件/原因契约。主要文件：`lib/index.js`、`lib/server.js`、`lib/client.js`、`lib/provenance.js` 及必要的本地审计模块。

实现要求：

- 先补齐 superseded 的运行结果记录，不能只在 distill 返回后丢失；保留最近一次诊断的兼容读取。
- 建立有限、持久的变更记录：写入/合并/替代/拒绝/日期调整/待核/恢复状态，关联节点与版本、源事件、处理时间和原因。原因码稳定，显示文字中英可切换。
- 在 W1 的契约中冻结保留上限、裁剪规则和删除行为。核心来源信息随事实保留；辅助操作列表有界。历史被清理后显示“记录已过保留期”，不伪装完整历史。
- 尽量复用现有详情、版本历史、操作回执和按工作区请求。新增一块“记忆变化”即可，不做整页重设计，不新增模型工具。
- 一眼区分成功、拒绝、待核、恢复中、恢复失败与无事实。语义待核不显示为网络失败，也不自动反复重试。
- 同一操作幂等记录一次；来源/事实与派生审计文件之间的提交边界必须明确。不能在审计写失败时声称所有记录都完成，也不能无依据回滚已提交事实。
- 敏感值在进入审计之前脱敏；不是先落完整内容再在 UI 隐藏。源指针、引用显示和复制也遵守同样边界。
- 所有管理记录不加入模型提示词；针对相同合格事实，新增审计前后注入正文/预算没有额外开销。

**验收**：

1. 拒绝、日期调整、替代与歧义均可查看，不能只有最近一次覆盖所有历史。
2. 重启后可查看保留范围内记录；切换工作区不串数据；失败重试没有重复成功回执。
3. 来源缺失/无法跳转明确说明；既有替代/撤销操作继续工作，不扩大自动写入权限。
4. 合成敏感值不进入状态响应、审计文件、日志或 UI 文本。
5. 中文/英文、明暗主题、900px，以及 Tab/Enter/Escape 可操作；视觉/键盘与组件桩分别记覆盖层级。
6. 用户手工操作截图优先，不把 Computer Use 操作作为必须步骤；可独立完成的接口/组件检查先做。

**停止条件**：跨工作区泄漏、敏感内容进入审计、以无限日志换取“可追踪”，或把审计自动塞进上下文。

### W5：端到端连接检查与总回交

依赖：W1–W4。主要关注来源→候选→写入→版本→投递→新会话读取，不扩大为新功能开发。

执行要求：

- 用冻结的正常集和独立反例集检查上述路径；先离线，再用隔离真实宿主 + 可控模型桩验证消息、失败、等待和恢复顺序。
- 覆盖：重放完成、超过 8 秒后后台完成、两个会话同时启动、重试、关闭、切换工作区，以及首次短地图生成。区分 replay 等待时间与整个宿主启动耗时，不承诺总启动必定小于 8 秒。
- 恢复中不能说“库为空”；后台落库后应有确定的可观察状态，不悄悄把旧空地图永久当作当前状态。
- 本片不做自然增长长会话、多模型、对手排名、50k 性能或费用节省结论。
- 基准单次事实必须能沿来源链查回，整批没有误退休、错误日期或跨库写入；有意拒绝/待核不算漏记成功，单独报告。
- 验证最终源代码及本地测试包，包只用于验收，不发布；版本号保持 0.8.2，明确与 npm 现有包不同。

**验收输出**：全量回归、各反例修前/修后、同源事实与逻辑快照、最终请求文本/预算、恢复状态、UI 覆盖、脱敏扫描、未解决 F-W 编号。任何失败不能通过静默跳过或改判据消失。

**停止条件**：真实宿主接口与计划假设不符时记录阻塞，不换成假钩子后仍称宿主通过。未解决的 P1 阻止进入付费质量复测与发布准备。

## 6. 付费与凭据规则

本批 W1–W5 的实现与确定性验收以**零付费模型**为目标。真实模型质量复测放在本批结果回交后的独立执行轮，不因本计划生成而启动。

若之后安排付费：

- 遵守本机新额度：每次运行 ≤3 元、Asia/Shanghai 当日累计 ≤10 元，必须有预算熔断，不能沿用旧文档 15 元上限。
- 发送前持久预留最高适用费用；主回答、抽取、回退、摘要、嵌入与重试统一记账。缺 usage/价格未知时保留预留并停止，不填 0。
- 当日已用和未决预留必须能核对；超限或无法安全确认余量时不发请求。
- 隔离凭据仅在单次运行期存在，finally 清除并检查隔离 home 无凭据文件；真实 memory.db 的修改时间与运行前一致。
- 每次输出独立、不可覆盖证据目录；公开证据脱敏，记录代码/内核/宿主/模型版本及试验边界。
