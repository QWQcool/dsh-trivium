## 抽取成本与可靠性

以前的合批和冷却方向合理，但“68% 降低”只是离散模拟。实际代码还把失败批次当成去重成功、异步完成后清掉在途新消息，并在冷却未到时放弃定时器。它们会让调用变少，却不能算有效节省。

保留 60 秒静默 / 12 条消息 / 5 分钟冷却，改为单批在途、快照消费、成功去重、失败保留、冷却结束自行唤醒。压缩与 pending 重放走同一调度入口；同一工作区的重放在途不重复领取。失败不自动无限重试，等待后续事件或启动恢复。pending 同步写出避免旧异步写覆盖成功清理；完成时不删除另一个会话拥有的 pending。仍是原有每工作区一个 pending 文件，**多会话未新增持久队列格式**。

只对完整的纯致谢/确认短句跳过模型；显式事实、隐含事实及工具失败/成功证据继续抽取。发现 `方案 BluePlan` 被规则截成 `方案 B`，加名称边界修复；实际单字方案 B 仍正常。

比较实际插件事件钩子（假时钟、模型桩、两个独立进程；不是原来的估算调度器）：

| 20 轮固定工作负载 | 旧版 | 发布版 |
|---|---:|---:|
| 纯致谢：模型调用 / 提示词估算 tokens / 残留消息 | 8 / 1711 / 4 | 0 / 0 / 0 |
| 有效对话：模型调用 / 提示词估算 tokens / 残留消息 | 10 / 2798 / 2 | 13 / 3417 / 0 |

有效对话费用可能上升，因为修复后会完成旧版遗留的工作。这里没有把漏处理算成节省，也没有承诺日常总费用降低固定百分比。

**提示词压缩已试验但不进入发布。** 两次各六场景的旧/新对照，共 22 次真实请求；第一版压缩省掉了必要来源 quote，第二版仍出现经验字段不齐、摘要重复及实体正文差异。样本无法证明质量不降，因此恢复原始提示词。生产的 2400 字符输入上限和 400 输出上限不变；规则+模型的近义候选仍可能重复，后续应在明确身份/来源证据下处理，不能靠删除所有相似句省 token。
