## 结论与范围

本次计划实现三个相互依赖的部分：统一上下文预算与去重、记忆来源与召回解释、人工确认的决策替代关系。前端效果以 FRONTEND.html 为准，它使用虚构的示例数据，不连接数据库。

目标是让用户知道“记了什么、从哪里来、为什么被用到、现在还有效吗”，同时限制进入模型的文本。详情可见性增加，不等于把详情自动塞进模型。

不能承诺整个会话绝不增长：工具输出会进入历史，重复调用工具也可能重复返回文本，已经注入的旧消息不能被本插件回写删除。这里承诺的是可检查的默认注入预算、同轮去重与详情按需读取。源码尚未实施本计划；HTML 的预算与交互是设计演示。

## 现状与上下文约束

现状见 `lib/index.js`、`lib/tools.js`、`lib/pins.js`、`lib/store.js`：

- 默认芯片、自动召回都关闭；会话开场有一份不超过 400 的估算 token 地图。
- 开启芯片与自动召回后，两者分别截到 300，当前没有共享预算。两路可以包含同一个节点。
- pre-step 可能在同一用户轮的多个工具步骤中执行；不能只按查询文本判断是否已经注入。
- `ctx_find` 有 top_k 上限，缺少完整工具输出的统一 token 上限。
- `estimateTokens()` 是 CJK/ASCII 启发式估算，不是模型 tokenizer 或费用统计。所有界面和报告必须标明“估算”。

### 必须满足的上下文契约

1. **默认不变**：芯片/自动召回仍关闭。打开来源、历史、诊断面板不触发 `agent.inject()`、模型请求或 embedding 请求。
2. **地图**：每个会话一次，默认预算 400；不附加来源引文、诊断日志、完整关系链或旧版本正文。只显示可用当前节点的短标签。
3. **每轮附加预算**：芯片 + 自动/锚点召回共用 300，包含标题、状态、路径、分隔符与必要的失效通知。不能各自再用 300。
4. **同轮去重**：按 workspace + session + 用户消息/事件标识 + compaction generation 去重。相同文字的两条不同用户消息是两轮；同一轮的工具循环不是新轮。
5. **节点去重**：先解析当前版本，再以稳定 URI（旧数据可回退本库 id）去重。芯片优先、召回只用剩余额度；同一节点出现在多路时只呈现一次，同时保留 UI 解释所需的渠道记录。
6. **跨阶段重复**：地图中本次已经包含的事实不再以相同正文重复注入；地图仅含标签时允许后续补一条摘要。不能把“出现过节点 id”误当成“全文已在上下文”。
7. **投递账本**：仅在宿主接受注入/返回成功后标记 delivered；失败可重试。会话关闭清理，compaction 后重建必要上下文。fork 子会话不继承父会话的 delivered 标记或 pins。
8. **工具输出**：`ctx_find` 默认合计上限 1200 估算 token，默认 top_k=8、最大20仍保留；超预算返回较少完整记录并给出简短截断提示。不要截断 id 或制造半条 JSON。`ctx_read` 是显式全文读取，保留现有正文读取能力，不为本次新功能加入无续读手段的硬截断；其新来源/历史诊断字段不自动展开。同一节点正文未变时，默认ctx_read结果不得因新metadata而变大。完整来源和历史通过 UI 获取。
9. **四个工具的 schema 不膨胀**：不新增工具；本轮不新增模型侧参数。`include_stale` 保持仅表示“期限过期”，不得悄悄兼任“已替代”。来源详情、历史开关及替代操作走 UI 的 HTTP API。工具说明可精简修改，估算 schema 总量不得超过基线。
10. **模型输出保持精简**：`ctx_find` 只含 id/type/L0/必要状态及最多两条短路径；历史关键词命中新版本时可带一条 `matched_history=#17 → current=#42` 指针，仍计入1200。`ctx_read` 不直接序列化新加的巨大 provenance/trace/history 字段。
11. **不是删除过去**：旧消息仍可能保留在宿主会话中。如果本轮已注入节点后来被替代、归档或到期，下一次需要注入时给一次短更正提示，计入300；不谎称已经从会话历史移除旧内容。

300是同一用户轮的累计额度，不是每个pre-step重新获得300。更正提示也共用剩余额度；本轮预算不足时留待下个用户轮，UI明确显示“待下一轮生效”。人工历史pin是用户明确选择的例外，保持原id与历史标记；自动召回才把旧版本映射到当前头节点。

默认首次记忆注入仍最多400估算 token；用户主动开启两个通道后，首次地图与本轮附加合计最多700，后续每轮附加最多300。以上不包含用户消息、模型输出和主动工具调用；不能宣传为整个会话的总 token 上限。

## 交付顺序

### M0 统一预算与投递去重

先实现纯函数 `selectContextRecords()` / `renderContextRecords()`（命名可调整），再接到 `agent/pre-step`。输入包括 pins、召回候选、当前版本映射、当前轮上下文与预算；输出包括入选记录、预算、去重/过滤原因以及实际待发送文本。

不能从 `buildPinInject()` 截断后的字符串再反解析节点。先取得结构化候选，统一排除脏数据、归档、失效和被替代记录，再合并与截断。人工明确钉选历史节点时：保留用户选择、标为历史并按预算注入；不得在不提示用户的情况下自动把该 pin 改成后继节点。UI 显示“已被替代，可改为钉选当前版本”。自动召回始终只用当前、未过期节点。

新增 per-turn 账本。稳定用户轮标识应从宿主用户事件的 message id/seq/turn 获取，具体适配现有 host-format；禁止用 `Date.now()`、查询字符串或每次 pre-step 自增计数冒充用户轮。账本只记录实际入选且成功交付的条目和内容指纹，不记录被预算挤出的条目。

如宿主没有可用的注入成功确认：将账本更新与该次 enter 返回组装在同一受控路径，失败撤销，并用测试证明可重试；不能静默吞掉唯一一次注入。

M0 独立提交并验证，再开始后续 UI。它是“新增详情不造成默认冗余”的发布门槛。

### M1 来源与召回解释

复用当前 Settings → Trivium 记忆入口，不增加顶层导航。管理面板内分“记忆条目”和“召回检查”；详情内分“内容 / 来源 / 决策历史”。原来的配置、导入导出、归档与删除入口保留，可放到配置折叠与更多菜单。

来源扩展沿用已有 `payload.source`，允许缺失。推荐可选字段：`kind`（manual/extract/chip/import）、`sessionId`、`messageId` 或 `eventSeq`、`quote`、`capturedAt`、`importPath`。只记录确实知道的字段；不得根据文本内容补造会话、作者或证据。旧记录显示“此条目没有可定位的来源”，而不是猜一个来源。

来源引文短预览最多240字符，经现有卫生检查，文本渲染；默认不下载或扫描整个会话。用户点击“查看来源”才请求当前工作区可访问的具体片段。来源会话失效时显示“会话已不可用，保留现有摘录”；复制摘录是显式动作，不触发注入。没有可靠的宿主定位 API 时禁用跳转并解释，不拼造 deep link。

召回解释记录**实际候选管线**：原生混合、关键词兜底、实体锚点、业务边扩展、版本归一、去重、过期/归档/卫生/预算过滤。保留 reason code 和节点引用供 UI 显示，不保存全量向量、提示词、API key 或整段对话。

0.8.11 `searchWithContext()` 能提供管线计数/诊断，但不保证每条结果有独立 BM25 / 向量贡献。没有证据就只写“原生混合检索”，不得画虚构的贡献百分比或把分数称为置信度。原生 diagnostics 是可选增强，基础解释由插件实际走过的分支产生。

最近诊断只保留内存中最多20次、10分钟 TTL，按工作区及会话隔离，单条体积上限64KiB。每个阶段最多保留100个节点摘要，超出明确 `truncated`；不要记录全库被过滤明细。面板展示真实进入过候选集的记录，不能把“未进入候选”说成已被某条规则过滤。

“运行只读检查”使用当前本地文本/图通道，不执行工具、不写库、不请求 embedding。若已有最近的向量查询诊断，可只读展示；缺少查询向量时直接标“未运行语义通道”，不得伪造语义结果。关闭面板不影响记忆检索。

### M2 人工确认的决策替代关系

只处理**两个已存在的 decision**，经 UI 明确确认。首版不做自动冲突判断、不让模型自动批准替代、不做一键生成并连接新节点。用户先通过现有新增入口创建新决策，再选择它来替代旧决策。

新增有向边 `newDecision --supersedes--> oldDecision`。它不是 `same_as`，也不是 `until`；保留旧节点正文与原始期限，不将旧节点强行归档。两类状态独立显示：有效期（未过期/已过期/无期限）、版本（当前/已被替代）。

- 首版采用线性链：每个节点最多一个直接前驱、一个直接后继。拒绝自环、循环、跨工作区、非decision、重复冲突和归档端点；每次操作最多检查32跳，超过预算拒绝并提示，不返回不完整的“当前版本”。
- 新增 `supersedes` 单独放在 REVISION_EDGES，不直接加入现有 BUSINESS_EDGES 的默认扩展白名单，否则每次召回会把整条历史带回来。
- 默认自动注入和记忆列表显示当前头节点。UI 的“显示已替代”单独控制历史，不复用“显示过期”。主动 `ctx_find` 保留0.4.22的过期历史语义；对已替代节点的命中先映射到当前后继、去重并给短指针，旧节点仍可用 `ctx_read(id)` 阅读。
- 当前后继已过期或归档，不自动复活其旧前驱。UI 给出明确状态，自动召回不输出这一条链；用户可查看历史或执行符合规则的撤销。
- 既有 pins 指向旧id时不悄悄改写，UI 提醒用户选择当前版本。历史pin的说明计入共享预算。
- 链上的正文视为已确认的历史，自动抽取/merge不得覆盖。遇到实质不同的文本，返回 `revision-protected` 并在本地诊断显示；不把整批抽取卡成永久 pending。手工修改正文需先新增独立决策，再替代；来源补充等不改变事实的字段可编辑。
- 对链上节点的永久删除或同义合并先返回409 `REVISION_LINKED`，提示先处理替代关系。归档可保留，但不得造成历史自动复活。导入冲突先预检并报告，不能悄悄覆盖链上正文或丢掉边。

使用 workspace 写队列包住“读取→校验→原生事务”。`commitTransaction()` 一次提交既有节点间的 supersedes 边与必要的 payload 更新时间。0.8.11 事务接口只有数字src/dst，没有插入临时id引用；不要杜撰API或用猜测的next id实现原子插入。

HTTP修改携带前后节点的 opaque ETag（由内容及相关边生成），队列内重读比对，冲突返回409并让用户刷新。操作带 UUID `operationId`，重试不得制造平行重复边。原生图事务提交失败时两端保持原状；提交成功但响应丢失时重读关系判断是否已应用，不能盲目再次执行。

0.8.11 的文本登记不在同一事实事务里。边关系先以图为权威提交，衍生文本索引和JSONL写出随后维护；失败要有可见的待重建/待同步状态，重启能修复。不得宣称跨文本、事实文件完全原子。发生正文索引变更时，以权威payload和别名重建，避免累积过时的显式关键词。

撤销只支持最近直接替代关系，确认后用 `unlinkLabel` 删除指定 supersedes 边，不删其它边；撤销后两条决策重新独立，UI明确说明。撤销前也校验ETag，拒绝把已有后续变更的链拆错。首版不宣称提供完整不可变操作审计日志。

## 建议的 HTTP 契约

继续沿用 `/api/dsh-trivium`、现有loopback Origin检查与已登记工作区白名单。下面是拟新增契约，不是已有API：

- `GET /nodes/:id/detail?cwd=…`：summary、expiryState、revisionState、currentId、sourceAvailable、etag；默认不包含完整来源与历史正文。
- `GET /nodes/:id/provenance?cwd=…`：已保存的来源字段和短引文；不可访问返回明确状态，不泄露其它工作区。
- `GET /nodes/:id/history?cwd=…&limit=20&cursor=…`：链上的节点短摘要、方向、关系时间/原因、分页游标及truncated。默认不展开每个节点全文。
- `GET /recall-traces?cwd=…&session=…` / `GET /recall-traces/:traceId?cwd=…`：短期内存诊断；traceId失效返回410。
- `POST /recall-preview`：`{cwd, query, sessionId?}`，仅本地文本/图只读检查；返回候选、真实过滤原因、预算规划与 `semantic: not_run`。query上限500字符。
- `POST /nodes/:oldId/supersede`：`{cwd, successorId, reason, expectedEtags:{old,new}, operationId}`；只连接已有节点。
- `POST /nodes/:oldId/supersession/revoke`：`{cwd, successorId, expectedEtags:{old,new}, operationId}`。
- 所有写接口由服务端校验输入；不要信任前端隐藏按钮或HTML demo的状态。reason最多240字符，按纯文本呈现。

错误至少区分：400非法输入、404节点不存在、409并发/循环/链限制、503内核暂不可用。无权限/跨工作区沿用现有响应约定，不通过错误正文泄露路径或内容。

`ctx_link` 不开放直接写 supersedes / revocation，返回明确提示要求在管理界面确认。普通业务边保持兼容。导入含supersedes时同样执行图验证，不能绕过约束。

## 存储、导入与降级

- 不批量推断/删除旧 `until`；缺少新字段按旧数据兼容读取。
- 来源会话定位与原始引文默认仅留本机，不自动写入 Git JSONL；完整用户导出可明确选择是否包含来源。默认JSON事实备份沿用已有数据策略并说明其范围。
- JSON图导出保留有效的supersedes边及必要metadata，URI作为跨库身份；导入重映射数值id后验证链，验证失败不部分提交。
- Git旁路支持版本关系时升级格式版本并明确兼容矩阵；旧v1可读，新v2新增edge metadata和supersedes。新数据写出前做好备份并给出降级说明。不能承诺旧0.4.22读取/写入v2安全；降级需恢复升级前文件组。
- 导入/拉取删除一段链或覆盖链上正文时先报告冲突，保持现库可用；不能自动复活旧版本。关闭Git写出不关闭读取的现有语义保留。
- 不升级到0.9 beta，不引入外部数据库、云服务或新的LLM调用。快照API等0.9能力不在本次范围。

## 前端规格

FRONTEND.html 是离线可交互规格。外框的“演示场景 / 设计标注”属于交接辅助，不进入正式产品。

- 入口仍为 Settings → Trivium 记忆。顶部显示工作区、配置折叠与原有管理动作，不增加宿主顶层导航。
- 桌面布局：列表为主、详情侧栏为辅；宽度不足时详情改为全宽下方或单独页，不把列表挤到无法读。
- 记忆条目显示类型、短标题、正文摘要、过期/替代标签。旧版本有“查看当前版本”动作；不要把“已替代”写成“已过期”。
- 来源默认折叠/按标签页加载。决策历史默认只展示当前节点与前一条摘要，继续展开按页取；历史全文需要点击。
- 召回检查默认展示本轮实际选择与简短原因，可查看候选明细和“将发送给模型的文本”。预算条只计估算token，不能称实际计费token。
- 替代弹窗并排展示旧/新决策与可选原因，按钮明确“确认替代关系”。保存中禁止重复提交；冲突保留用户选择并提供刷新，失败不假装成功。
- 交互必须支持键盘、可见focus、Escape关闭弹窗、焦点恢复、窄屏、宿主中英文与暗色主题。沿用DSH已有Button、输入框和主题变量；HTML里的固定色值只用于原型。
- 空列表、无来源、来源不可访问、无历史、无最近诊断、预算不足、并发冲突、数据库不可用均有明确状态和下一步。HTML可用外部场景选择器查看这些状态。

## 文件改动指导

- `lib/index.js`：调用统一上下文规划器、稳定轮标识、投递账本与compaction/fork清理。
- `lib/pins.js`：提供结构化候选，展示历史pin状态；取消自身独立300截断路径。
- `lib/context-budget.js`（建议新增）：纯函数预算、指纹去重、完整记录裁剪。
- `lib/store.js`：结构化召回trace、当前版本归一、链校验、权威写入保护；不要把新的历史边直接混进默认业务扩展。
- `lib/provenance.js` / `lib/revisions.js`（按需新增）：来源投影、历史链与事务操作；保持store调用边界明确。
- `lib/schema.js`：来源可选字段、单独的revision边集合；新字段不能悄悄改变旧节点type/status。
- `lib/tools.js`：精简投影与输出预算，保持四工具schema；阻止模型直接写版本关系。
- `lib/server.js`：按需读取/预览/替代/撤销API、权限和ETag。
- `lib/client.js`：复用设置入口和i18n；详情与召回面板可拆出helper，不能把Node依赖打进客户端。
- `lib/sidecar.js`：版本关系与metadata的可验证导入导出、冲突预检和兼容说明。
- `scripts/smoke-p16.mjs` 起：新增上下文和历史回归；保留既有测试，不以改期望值掩盖退化。
