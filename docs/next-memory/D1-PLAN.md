# D1 预注册：记忆是否让「更激进的压缩」变得可行（写于付费请求之前）

日期：2026-10-29。基线：`c8ab07d`（注入完整性修复之后）。

## 0. 要回答的问题与不能回答的问题

要回答：**在没有记忆插件时，为了做对同一条任务，必须保留多少对话历史？**
装了记忆之后，能否把历史压到更小、总 token 更低，而正确率不降？

不能回答（本轮明确不做）：

- 单会话里「注入本身」能不能省 token —— 它**只会加**（D0 实测每轮 +95 token）。所以本协议不把
  「注入越小越省钱」当卖点，而是测「**省下的历史保留量**」是否大于注入量。
- 抽取成本（自动写入那条 LLM 调用）。本轮事实由测试直接种入库，抽取开销另记（见 §6），不与注入相加。

## 1. 为什么必须换一个设计

C4/D0 都是单轮：上下文本来就只有一问一答，记忆能做的只有加 token。
真实长会话里，成本的主项是**历史消息**；而 host 压缩是有限度的——压掉的正是「早先定过的事」。
记忆插件的价值主张因此是：**让压缩可以更狠**。这可以测。

## 2. 会话与压缩策略（冻结）

每会话 5 轮，第 1 轮用户交代 3 条约定（F1/F2/F3），第 2 轮做无关整理，第 3 轮问 F1，
第 4 轮触发压缩，第 5 轮同时问 F2+F3（结构化字段严格比较）。

压缩规则（第 4 轮起生效，预注册）：

- 历史只保留**最近 1 轮**；
- 顶部放一段固定摘要，**只保留 F1**，F2/F3 明写「已压缩，未保留」；
- 摘要文本对四个臂完全一致。

也就是说：不给记忆的臂，在压缩后只剩 F1；要答对第 5 轮，只能靠不压缩（保留全部历史）。

## 3. 四个臂（同一模型、同一判据、同一会话脚本）

| 臂 | 记忆 | 历史策略 | 预期 |
|---|---|---|---|
| `none-full` | 无 | 全留，不压缩 | 全对，token 最高（这是「不装记忆时的代价」） |
| `none-compact` | 无 | 压缩（§2） | 第 5 轮必错，token 最低 |
| `trivium-compact` | 有我方注入（真实 pre-step） | 压缩（§2） | 若成立：全对且 token ≈ `none-compact` |
| `plain-compact` | 无（把同库事实整段注入） | 压缩（§2） | 全对，但每轮多 360 token（上界对照） |

**判据（预注册，先写后跑）**

- H1（成本）：`trivium-compact` 的**会话累计 token** ≤ `none-full` 的 **0.75**；
- H2（不降级）：`trivium-compact` 第 3/5 轮通过数 = `none-full`；
- H3（相对纯文本）：`trivium-compact` 累计 token ≤ `plain-compact`。
- 若 H1 不成立（≥0.9），结论写「压缩省下的历史不足以抵掉注入」，不再对外宣称省成本。
  若 H2 不成立，写「记忆在压缩后不可靠」，这是更严重的问题。

## 4. 模型与预算

`deepseek-flash`、关思考、`temperature=0`、`max_tokens=600`；每臂每会话 5 次调用。
4 臂 × 6 会话 × 5 轮 = **120 格**（无工具，单次调用）；预算上限 **3 元**，预计 <¥0.5。
每请求先预留、超预算不发、缺 `usage` 立即停。

## 7. D1b：10 轮变体（在付费跑 D1 之前预注册）

离线装配自检（**零模型调用**，只看 token 尺寸、不看任何回答）显示：5 轮会话里
`none-full` 平均 ~759 token、`trivium-compact` ~712（比值 0.94），因为压缩从第 4 轮才生效，
5 轮里只有 2 轮真的受益。按 §3 的 H1（≤0.75），**D1 大概率不达标**——这不是坏消息，而是
说明「省下的历史」与「会话长度」成正比。

因此同时预注册 D1b：会话脚本、压缩规则、四个臂、判据全部不变，只把轮数从 5 提到 **10**
（seed / noise / ask1 / 6 个 filler / ask2，压缩仍从第 4 轮起）。

- H1b：`trivium-compact` 累计 token ≤ `none-full` 的 **0.75**；
- H2b：通过数与 `none-full` 相同；
- H3b：累计 token ≤ `plain-compact`。

若 H1b 也不成立，结论只能是「在 ≤10 轮、事实量很小的会话里，注入抵消了压缩收益」，不得外推。
两轮都跑、都报，不合并成一个最好看的数字。
