前置：[A-1 整轮漏记](A1-FACT-LOSS-FIX-2026-10-30.md)、[A-2 长文本定位](A2-LONG-TEXT-DIAGNOSIS-2026-10-30.md)。

## 1. 这一轮改了什么

A-2 之后抽取仍有 12/18 次被 `maxTokens` 截断（900 也不够），因为模型把预算花在 reasoning 上。A-3 把抽取调用改成 **`reasoningEffort: "off"`**：

- 抽取是 JSON 杂务，不需要推理；
- 若宿主目录不认这个档位（`UNSUPPORTED_REASONING_EFFORT`），**回退一次去掉该选项**，不允许“未知档位导致抽取完全不可用”；
- `maxTokens` 保持 900。

`lib/index.js` 的 `makeLlmCall` 现在导出以便单测；新增 `scripts/smoke-p45.mjs`（11 条）覆盖：请求 off、回退只发生一次、回退时保留 model/budget、无关错误不重试。

## 2. 夹具（全部非敏感）

| 场景 | 输入 | 金标 |
|---|---|---|
| LONG-TAIL | `记住这段长约定：` + 60×`背景记录。` + `另外关键一条是，本次发布代号是 BlueHeron。` | `BlueHeron` |
| NAME-AMOUNT | `下一步，项目负责人是张三，预算上限 5000 元。` | `张三` |
| CORRECTION | `先别动旧方案 A。` → `更正：不再使用旧方案 A，改用方案 B。` | 只认单独出现的 `B` |

判分：候选正文/数据库正文必须含金标；问答环节必须有独立值（`A、B、C 都没有记录` 判负），出现“没有/为空/无法/不给”一律判负。跑法：每场景 3 次独立运行，每次独立 `DSH_HOME` + 独立库 + 新会话提问，本地转发代理逐请求记账。

## 4. 一个必须说的副作用

**关掉推理后，模型不再自行隐去“口令形状”的内容。** 同一个 `verify-QA-71` 夹具：

- 有推理时返回：`…含校验口令，按不落库敏感信息处理，口令内容已隐去。`
- 关推理后返回：`发布前置校验：…必须先校验口令 verify-QA-71。`（原样落库）

省下的是截断与思考成本，**代价是把“不落敏感信息”的判断从模型手里拿走了**。

更正一处我先前的说法：插件**本来就有**本地写入闸门（`lib/hygiene.js` → `looksSecret`，抽取与 `ctx_remember` 共用），但它只认英文关键词（`api_key/password/token/bearer/sk-`），不认中文“口令/密码”与常见凭据前缀，所以上面这条才漏了过去。已在本轮补齐（见 [A-4](A4-SECRET-VALUE-GATE-2026-10-30.md)）。

## 6. 仍未解决

1. ~~没有本地 secret 过滤器~~ **已补**（[A-4](A4-SECRET-VALUE-GATE-2026-10-30.md)）：写入闸门新增凭据值形状（GitHub/AWS/Google/npm/Slack/JWT/PEM）与中文“口令/密码/密钥 + 值”，并把拒绝原因报出来（不回显密文）。仍剩：英文词 `token` 的旧规则会误伤“token 预算”这类正常表述，未动。
2. **n=3 太小**：9/9 只能说明“这三条夹具在这个模型上稳定”，不能外推。要做通用基线至少 5 次重复、场景覆盖否定/指代/跨压缩。
3. **两条写入路径没有分开计量**：agent 自己调 `ctx_remember` 占 8/9，抽取命中 9/9，但一次运行里两条都可能写同一条事实（未测重不重复）。做净收益对比前要把它们分开打点。
4. **只测了一个模型**（deepseek-flash）。`reasoningEffort: "off"` 在别的模型上未必存在，回退路径已覆盖但质量未测。
5. **`maxTokens=900` 现在是冗余保险**：关推理后没有一次接近上限，但保留它作为“模型不支持 off”时的兜底。
6. 压缩链路（跨压缩召回）本轮**没有**覆盖；R3 的“压缩后同 step 重试缺短地图”仍未修。
