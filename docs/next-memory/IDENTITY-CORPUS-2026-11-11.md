# 事实身份：校准语料与基线（P1，2026-11-11）

结论先说：**现有词面打分在“宁可漏、不可错”这条线上是安全的，但召回只有 7/11**；
剩下的 4 条是真同义改写，字符 n-gram 看不见，**不能靠调低阈值解决**。

## 1. 语料怎么来的（用户定的 1 + 2）

`scripts/fixtures/identity-corpus.json`（26 对，11 同 / 15 不同）：

- **真实事实**：从本仓库工作区 `.dsh` 只读导出 7 条事实，取其中 5 条改写成
  “同一事实的另一种说法”，并为其中 4 条造了“改口版本”。实体类型不走文本合并
  （实体按名字合并），所以这一组在语料里重标为 `decision`，只测文本路径。
- **手写对照**：覆盖改写的六种形态（换序、同义、数字写法、缩写）与四种必须拒绝的形态
  （数值冲突、否定、主体不同、更正），另加“类型不同不得合并”。

标注是“人会怎么判”，不是“打分器怎么判”。

## 2. 基线（`sameFact` 现状）

```
pairs 26  same 11  different 15
recall 7/11 (63.6%)   false merges 0/15 (0.0%)
```

分数分布：

| 标签 | min | p50 | max |
|---|---:|---:|---:|
| same | 0.188 | 0.594 | 0.875 |
| different | 0 | 0.455 | 0.909 |

**两组分布重叠**，所以纯阈值不可行：同一份语料上

| 阈值 | 召回 | 误合并 |
|---:|---:|---:|
| 0.5 | 7/11 | **7/15** |
| 0.6 | 5/11 | **7/15** |
| 0.8 | 1/11 | 1/15 |
| 0.9 | 0/11 | 1/15 |

真正挡住误合并的是现有的**类型 / 否定 / 数值守卫 + 名字族**，不是相似度阈值。

## 3. 本轮做了什么

1. 语料固化成 `scripts/fixtures/identity-corpus.json`（可复现，不依赖任何人本地库）；
2. `smoke-p87` 增加闸门（**不新增脚本**，119/120）：
   - **误合并必须为 0**（硬门禁，因为合并会退役事实且没有修订链）；
   - 召回不得低于记录的 7/11（回归线，不是目标）。
3. 阈值维持原样。**没有**为了好看的数字放宽判据。
