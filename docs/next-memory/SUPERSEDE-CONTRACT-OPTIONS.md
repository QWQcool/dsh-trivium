# 替代关系契约：C 现状 / P / P′ 备选

日期：2026-11-02。状态：**当前采用 C**；P 与 P′ 作为后续开发方向保留，不排期。

## 背景

"改口是否退休旧决策"这件事经历了四轮独立复验（R-01/R-02 → P1-1/2/3 → P1-A/B/C → P1-1..4），
每一轮都是同一根因：**从文本推断"谁替代谁"**。第四次复验方明确指出并证明：
模型给出显式 `supersedes` **不等于**用户授权——四个攻击案例里有三个在带该字段时同样误退休。

## 三个契约

### C（当前）

- 抽取命中"替换措辞 + 方向 + 唯一目标"即自动建 `supersedes` 硬边。
- 已有守卫：问句（含句中问句）、引号、转述、未批准、撤回（含否定式）、讨论/假设、方向、候选顺序。
- 已知风险：**未预料到的措辞仍可能误退休**。发布说明必须写明这一点，不能宣称"安全"。
- 代价：0 代码量。

### P（提案制，复验方建议）

- 自动路径**一律不建硬边**，只写 `review: supersede-proposed`；
- 硬链接只由"用户在面板确认"或"调用方用结构化参数给出目标 id"创建；
- 短地图对"被提案替代"的节点**保持可见**。
- 代价：召回下降（未确认则 A/B 并存，模型可能答旧值）；需新建确认接口与面板区块
  （可复用"导入预览"的预览→确认交互）；约 7 个测试文件的断言要从"建边"改为"提案"。
- 收益：自动误退休归零。

### P′（窄自动 + 其余提案，作者倾向）

- 只有同时满足：单一活目标、含替换措辞的分句、无任何守卫命中、候选本身是改口句 → 自动建边；
- 其余一律转提案。
- 代价：召回损失小于 P；仍需确认接口与面板；约 3 个测试文件改断言。
- 风险：窄车道内仍有未知措辞（四轮案例已证明"看起来干净"不等于安全）。

## 若启动 P/P′，验收标准

1. 复验方四轮共 37 条反例（8 + 6 + 11 + 12）在"提案"模式下全部不产生硬边；
2. 用户确认后建边，并在变更记录里留下"确认人/时间"；
3. 短地图在未确认期间同时列出两个决策，且 UI 明确标注"待确认替代"；
4. 离线全量回归通过，且新增一条"未确认不隐藏"的断言。

## 当前发布口径（C）

- 允许发布，但 release notes 必须写：自动替代基于措辞启发式，**可能误判**；已登记的守卫类别；
  以及"完全无替换措辞的改口不退休""改名同义句可能留两条"等已知限制。
- 不得使用"已保证不误退休"一类表述。
