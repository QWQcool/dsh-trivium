# W8 证据：删除日期后的残句 + 重复写入

基线 `bce8d5e`。真实模型复测 3 次，¥0.013971。

## 1. 删除日期后留下的连接词

W7 真机里见到：候选原文 `2026-07-13 起采用方案 B`，落库成了 `起采用方案 B`。

修法（`lib/extract.js` `scrubUnsupportedDates`）：

- 前缀日期被删时，**把属于日期的连接词一起吃掉**：`时 / 当天 / 当日 / 起 / 开始 / 起算`；
- 另加一道兜底：删完后若句首仍残留 `起 / 开始 / 起算`，一并去掉。

回归 `p49` 17 → **20/20**（新增：日期消失、连接词消失、剩余正文正好是 `采用方案 B`）。

## 2. 同一句话被写两遍

W7 真机里见到 r1 落库两条完全相同的 `这次上线改走方案 B，方案 A 作废。`。

原因不是并发，而是**替换路径拒绝合并**带来的副作用：同一窗口会被处理两次（pending 重放 + 轮末），
第二次的候选文本完全相同，但因为是「替换」所以跳过了 `findMergeTarget`，于是又插入一条。

修法：替换场景改用 `findExactDuplicate()`——**同 type + 同 name + 同正文**才算重试，直接并入自身
（正文没变，`mergeInto` 不会触发 `REVISION_PROTECTED`），不再新插节点。

它**不会**重开"子串合并"那道口子：只认完全相等，`先按 A，随后改 B` 与 `按方案 A 走` 仍然分开。

回归 `p63` 11 → **14/14**（新增：同一候选连写两次只有 1 个节点、1 条边，且边仍指向旧决策）。

## 4. 仍未解决

1. r1 这类"两次抽取都返回空"仍会整轮丢事实；空回答只被当作失败保留 pending，模型连续两次给空时没有兜底。
2. `supersedes` 的写法仍不稳（`方案 A` / `上线方案 A` / `上线方案A` / `上一个方案` 都出现过），靠名称/标签/部分匹配加代指兜底，未做语义归一。
3. 去重只覆盖"同 name 同正文"；同名但正文略有差异的重复仍会出现（属于旧的子串合并问题域）。
