# W3 证据：有依据的日期转换

基线 `db35034`（0.8.2）。零模型调用、零费用。

## 修前

`before-counterexamples.json` 是计划阶段保存的 F-W02（**保留原样，未改期望**）：

```text
source: 明天复盘工作。   referenceDate: 2026-10-30 Asia/Shanghai
candidateDate: 2027-03-01   expectedDate: 2026-10-31
accepted: 我们定于 2027-03-01 复盘工作。      adjusted: []
```

即：一个宽区间 `[now−7d, now+400d]` 让"明天"授权了七个月后的任意日期，且**没有任何 adjusted 记录**。

## 修后（p52-after.txt，20/20）

- **锚点换成来源事件的时间**：`lib/date-parse.js` 用 `Asia/Shanghai`（UTC+8，无夏令时）把 turn 的 `at` 折成日历日；重放用源时间，不用重放当天。
- **只认确定性表达**：今天/明天/后天/昨天/前天、`下周X`/`本周X`/`周X`（**周一为一周起点**）。`月底前`、`以后`、`尽快` 一律不精确化。
- **一句话只允许一个相对表达**：同一句里出现两个相对表达时，谁也不授权（避免"两个对象两个时间互相借用"）。
- **授权范围**：候选日期必须等于"该来源句解析出的那一天"，或原文里字面出现过这一天。
- **三类结果分开报告**：`unsupported-date`（无依据）、`invalid-date`（2026-02-30 这类不存在的日期）、`ok`（保留）。
- **宽区间放行已删除**。

覆盖：F-W02、下周五=2026-11-06、邻近日期被拒、跨月（10-31→11-01）、闰日（2024-02-28→02-29）、非法日期、双相对表达、字面日期、重放锚点、模糊表达、解析器单测（含 `下周一`/`本周一`）。

## 契约变化（p49 同步更新）

p49 原来用 `now` 作为锚点；W3 之后锚点必须是**来源 turn 的时间**，因此 p49 的相对时间用例改为给 turn 加 `at`。这是契约纠正，不是为了让测试变绿：没有来源时间的相对表达本就不该被精确化。

## 本片未覆盖

- `N 天后`、`下个月 N 号`、季度表达未支持（保持原文，不精确化）。
- 时区固定为 Asia/Shanghai；宿主事件不带时区，未做用户可配置。
- 事件时间、陈述时间、失效期限三者分开存储仍未在 UI 呈现（W4 范畴）。
