## 1. 三条 P1 的成因

| 编号 | 现象 | 成因 |
|---|---|---|
| **P1-A** | "把方案 A 换成方案 B？"、"请翻译下面的原文；“别用方案 A；改用方案 B。”" 都会退休 A | 分句切分把句末的 `？` 切掉，导致问句守卫失效；引号内部被分句切开，片段被当成指令 |
| **P1-B** | 显式 `supersedes: "方案 B"` 时退休了 B（应退休 A）；同一句带"日志格式保持原样"时，带正确显式字段反而失败 | 显式路径解析目标后直接建边，没有方向校验；且否定词按**整句**判定，而启发式路径按分句判定，两条路径不一致 |
| **P1-C** | "不再使用方案 A，改用方案 B。" + 结果态候选"本次上线使用方案 B"（无 supersedes）→ 不退休 | 要求候选必须"提到被替换的方案"，结果态候选只提新方案 |

## 2. 修法

1. **守卫分层**：问句（句末 `？` / `吗` / `呢`）与元请求（翻译/解释/引用/原文）在**整句**上判定；`保持原样` 一类只在**分句**上判定。分句符补齐全角逗号、顿号与英文句点。
2. **引号先行剥离**：先去掉引号内容再找替换词；剥完没有替换词 → `quoted-replacement`。
3. **方向解析统一**：`改用方案 B` / `方案 A 换成方案 B` 两种写法都把**词后**的方案记为"新方案"、词前且不同的记为"被替换"；新增 `KEEP_CUES`（继续使用/还是用/照旧）用于**撤回**，撤回优先于指令。
4. **显式路径复用同一套上下文**：方向错误 → `supersedes-wrong-direction`，并**回落到句子级路径**（模型指错边不能连累正确退休）。
5. **结果态候选**：候选只要点明"新方案"，即可退休句子指名要弃用的那个；不再要求它复述旧方案。

## 5. 必须说清的事

这已经是同一处逻辑的**第三次**返工（R-01/R-02 → P1-1/2/3 → P1-A/B/C）。三次都是"从文本推断替换意图与目标"，每次修完都在相邻方向露出新洞。当前实现的不变量是：

- 措辞证据只来自**用户句子**，从不来自候选；
- 判定作用域显式区分（整句 vs 分句）；
- 目标由**方向**决定，不由"谁被提到"决定；
- 显式指认与启发式**共用**同一套校验，指错时回落而不是硬失败。

如果下一轮再出现同类问题，建议**换方案**而不是继续收紧：只允许模型显式指认（`supersedes`）建立硬链接，启发式只产出"建议替代"并由 UI 确认。这条路的代价是召回下降（模型不填就不退休），收益是不再有误退休。
