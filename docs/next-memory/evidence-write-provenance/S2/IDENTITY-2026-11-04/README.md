# 事实身份：换句话说的同一件事只存一份（2026-11-04）

基线 `main` @ `18ed9ef`。零模型调用、零费用。

## 修前

去重只有一条规则：正文互相包含。

```js
nText.includes(text) || text.includes(nText)
```

于是「发布窗口固定在每周四晚上」与「每周四晚上是发布窗口」——同一个事实的两种说法——会存成两条。
阶段 2 的「去重键从事件升级到事实身份」一直没做，这是最弱的一环。

## 修后

新增 `lib/identity.js`，三个本地信号：

| 信号 | 规则 |
|---|---|
| 类型 | 必须相同；`entity` 仍走名字那条老路 |
| 否定 | 一方含 `不/别/禁止/没有/无需/取消/never/not/don't` 而另一方不含 → **不合并** |
| **数值** | 两边的数字集合（阿拉伯数字、CJK 数词、周X）必须一致；不一致 → **不合并**（`value-conflict`） |
| 相似度 | 字符二元组 Jaccard（CJK 与拉丁都适用）；名字同族时 ≥ **0.5**，否则 ≥ 0.8 |

接在 `store.findMergeTarget` 里：子串规则之后、返回 null 之前。

**不用 embedding**：它会在写路径上引入一次网络调用，一旦服务不可用，去重就静默停止——"悄悄不再去重"比"偶尔多一条"更难发现。

## 实测（阈值怎么定的）

| 对比 | 相似度 | 判定 |
|---|---|---|
| 记住：发布窗口固定在每周四晚上 ↔ 记住：每周四晚上是发布窗口 | **0.571** | 合并（`name+text`） |
| 发布窗口固定在每周四晚上 ↔ 每周四晚上是发布窗口 | **0.538** | 合并 |
| 发布窗口固定在每周四晚上 ↔ 部署窗口固定在每周四晚上 | 0.692 | 合并 |
| 部署窗口是周四晚上 ↔ 部署窗口是周五晚上 | 0.600 | **不合并**（`value-conflict`） |
| 日志保留 30 天 ↔ 日志保留六十天 | 0.375 | 不合并（`value-conflict`） |
| 日志保留 30 天 ↔ 鉴权走 header X | 0.000 | 不合并 |
| 发布窗口固定在每周四晚上 ↔ 部署窗口固定时间已经确认 | 0.158 | 不合并 |

阈值取 **0.5**：真实改写落在 0.54–0.57，无关句落在 0.00–0.16，中间没有样本靠近 0.5。
这是实测出来的界线，不是拍出来的。

## 为什么先做数值守卫

第一次接上就撞到真实风险：p84 的三条「w1/w2/w3 只在自己的目录里提交代码」被并成一条（相似度 0.9+）。
它们只差一个数字——正是"修订版"的形态。若不管，**「周四改周五」会被静默并进旧事实**，
用户看到的仍是旧结论，而库里没有任何修订痕迹。

现在规则是：**数字不同 = 不同事实**，宁可多一条，也不静默改历史。

## 验收

```
node scripts/smoke-p87.mjs  → 14/14（新增）
node scripts/run-all.mjs    → 88/88（改前 87/87）
```

p87 覆盖：同文相似度=1；改写合并；周几改动不合并；数字改动不合并；否定翻转不合并；类型不同不合并；
实体仍走名字；短句只有完全相同才合并；名字同族容忍修饰词；拉丁正文可用；
以及三条**经过 `applyCandidates` 的真实路径**（改写走 merge 且不新增节点、改天走 insert 且确实新增）。

## 未覆盖 / 已知边界

1. **只有 Jaccard + 名字族**，没有语义理解：同义不同词（"包管理器" vs "依赖管理工具"）仍会存两条。
2. **否定守卫会挡住互补句**：「用 npm，不用 pnpm」含 `不`，与「用 npm」不合并——偏保守，会多一条。
3. **只在 `findMergeTarget` 生效**：导入（`importGraph`）、芯片、JSON 导入各有自己的去重，未统一。
4. **阈值是按一组手写样本定的**，没有大规模语料校准；0.5 附近仍是灰区。
5. **性能**：每个候选要对同类型节点全表算一次 Jaccard（O(n)），千级库可接受，万级需要倒排索引。
