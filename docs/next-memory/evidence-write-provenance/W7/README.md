## 2. 模型会不会填 `supersedes`（真实模型，3 次，¥0.018109）

场景 `SPOKEN`：`这次上线按方案 A 走。` → `上一个方案不要了，走新的，用方案 B。`
这句话**既没有替换词也没有标签**，只有模型主动填 `supersedes` 才可能建链。

报文原文（`supersedes-wire.txt`）：

| 轮 | 模型返回的 `supersedes` | 能否解析 | 结果 |
|---|---|---|---|
| r1 | `"方案 A"` | ✅ | 建成链（retired=1），回答 B |
| r2 | `"上一个方案"` | ❌（无此标签） | 未建链（retired=0），仍答 B |
| r3 | `"方案 A"` | ✅ | 建成链（retired=1），回答 B |

**结论**：模型 3/3 都主动填了这个字段（不是摆设），但它有时填**代指短语**而不是标签。

因此本轮补了一条规则（`lib/extract.js` `DEICTIC_SUPERSEDE`）：
`上一个/之前的/原先的/旧的/上一条 (+ 方案/决定/计划)` **且工作区只有唯一一个活决策**时才认；
有多个活决策时报 `supersedes-ambiguous`，不猜。

回归 `p65` 12→**16/16**（新增：代指唯一命中、代指多目标拒绝），全量 **66/66**。
