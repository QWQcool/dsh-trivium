# C3 场景集（10 个 pilot 场景）

> 独立复核更新（2026-10-29）：离线9/10已在本机重跑确认。下文在线数字是旧报告记录，原始输出未回交；跨场景/臂共库与判据假阳性使“准确率/零增益/稳定持平”的结论失效。详见 [C-RESULTS](C-RESULTS.md) 和 [复核报告](C-REVIEW-2026-10-29.md)。脚本修复不追认历史实验；本轮真实模型调用为0。

日期：2026-10-29。基线 `cb2b070` + 抽取降本改动。预算按用户授权：**单次实验 ≤ 15 元**。

## 为什么先跑"离线版"

端到端答对率需要真实模型。但"模型能不能答对"之前有一个更前置的问题：**记忆层到底有没有把该给的材料给出去**。这一层零成本可测，而且是端到端实验的分母——如果材料都没送到，测出来的答对率反映的是检索缺陷，不是模型能力。

所以 C3 分两步：

- **C3-offline（本文件 + `scripts/bench-c3.mjs`）**：只测"材料齐备性"。注入块里有没有目标事实、有没有不该有的、有没有越预算。
- **C3-online（需真实模型）**：在 C3-offline 通过的前提下，才用 15 元预算测答对率与端到端 token。

## 场景设计

每个场景 = 铺事实 → 发问 → 判定三件事：`recalled`（该给的给了）、`forbidden`（不该给的一个都没给）、`tokens`（注入估算 token）。

| # | 场景 | 铺什么事实 | 问什么 | 判什么（gold） | 负例/陷阱 |
|---|---|---|---|---|---|
| S01 | 单条偏好 | `preference`：偏好先看实际演示 | "推荐什么技术视频" | 注入里出现"实际演示" | 库里另放无关偏好（饮食），不得注入 |
| S02 | 决策更替 | v1「只看教程」→ v2「教程与演示都可以」（supersede） | "现在推荐视频的约定是什么" | 注入出现"教程与演示都可以" | 旧版正文**不得**作为当前出现 |
| S03 | 过期决策 | `decision` + `until: 2020-01-01`「周五不发版」 | "这周能发版吗" | 出现该决策且被标 stale | `include_stale=false` 时召回为空 |
| S04 | 跨工作区同名 | A、B 各一条同名「上线规范」，正文不同（B 带唯一标记） | 在 A 问"上线规范" | 只能是 A 的正文 | **B 的标记出现次数必须为 0** |
| S05 | 需读正文 | 事实正文里藏细节（"先跑 run-all.mjs 再发布"） | "发布前要做什么" | 命中该节点（名称可近似） | 只给名称不给正文也算不合格（要能 `ctx_read`） |
| S06 | 无关记忆 | 20 条与问题无关的节点 | "1+1 等于几"（不需要记忆） | **不注入任何记忆块** | 注入即算有害注入 |
| S07 | 预算耗尽 | 一轮内 6 条都相关（各约 60 token） | "把刚才几条约定一起说一遍" | 注入不超 300；最相关优先 | 越界即失败 |
| S08 | 归档不复活 | 决策 v1 被归档（`archive`） | "当前约定是什么" | 归档节点不作为当前事实出现 | 不得把归档内容当现行规则 |
| S09 | 多轮累积 | 第 1 轮说偏好、第 2 轮说约束、第 3 轮问复合问题 | "按我的偏好和约束，推荐什么" | 两条事实都要在注入里 | 少一条即不合格 |
| S10 | 显式问历史 | v1 → v2 替代链 | "上次为什么改成现在这样" | 历史可检索（旧版可读到，但标明历史） | 不得把旧版当当前 |

## 指标与预注册门槛

| 指标 | 门槛 |
|---|---|
| `recalled`（gold 出现在注入或 `ctx_find` top-8） | 8/10 以上 |
| `forbidden`（不该出现的内容出现次数） | **0** |
| 单轮注入 token | ≤ 300（S07 是压力点） |
| 跨工作区泄漏 | **0** |
| 有害注入（S06） | **0** |

不达标不调门槛，只记录并交给 D。

## C3-online 的成本预估（供 15 元预算参考）

按 `bench-extract` 实测：单次抽取提示词 1,392–2,175 token，输出约 200；注入按 149/300 实测取中位 150。

| 组 | 每场景轮次 | 每场景 token（估） |

| 仅地图（B 臂） | 3 | 地图 ≤400 一次 + 回答 |
| 当前默认（C 臂） | 3 | 注入 3×150 + 抽取 1×1,800 + 回答 |
| 自动召回（D 臂） | 3 | 注入 3×150 + 抽取 1×1,800 + 回答 |

这是初稿的量级预估，不是已核价格或预算保证；原先“15元不够重复3次”的说法撤回。任何新付费运行必须先固定模型/价格/调用上界，并保留逐调用usage。当前复核没有调用真实模型。

## 不做什么

- 不用模型自评分充当金标：`recalled/forbidden` 是字符串断言，不是"看起来答对了"。
- 不把离线通过说成"模型答得对"。
- 不在 50k 档跑端到端（单次工具调用 7.7 s）。

### 我自己的两个断言错误（先记下来）

- **S05**：断言检查"输出里有节点名「发布流程」"，但 `ctx_find` 的输出只打正文不打名称，节点其实找到了。
- **S10**：断言检查"旧正文出现"，而正确行为恰恰是**不把旧正文当当前**，只报 `matched_history=#5 → current=#6`。我把"正确"判成了"失败"。

教训与前几次一致：**判据写错会让产品看起来更差，也会让"修好"变成假象**，所以每次改断言都要看真实输出，而不是猜输出格式。

### S06 的有害注入：已修（D 最小改动）

- 现象：问「1+1 等于几」时自动召回投了一条无关实体。
- 两层原因，都要修：
  1. `queryTerms` 的正则把 `1` 当检索词（汉字早有 ≥2 长度闸，ASCII/数字没有）→ 加 `term.length >= 2`；
  2. `primaryScore` 里还有一条**原文子串**分支 `text.includes(q)`，单字符照样命中 → 加 `tooShort` 短路；`lexicalScore` 的 `hay.includes(query)` 同样加下限。
- 回归：新增 `scripts/smoke-p29.mjs`（反例：`1+1 等于几`/`1`/`几` 零命中；正例：`run-all.mjs`、`8787`、`发布` 照常命中；标识符查询不受影响）。`run-all` → **30/30**。

### 仍未解决的 S09

问「按我的偏好和约束，晚上推荐什么」时，只召回到「晚上十点以后不要推长视频」，漏掉「我喜欢有实际演示的内容」。两条事实**没有任何字面重合**，纯词法无法建立联系。

当前词法路径缺少可匹配线索，候选方向包括别名、查询改写、主题锚点或语义检索，不只有embedding一种方案。本次P0只修精确名称排序，不给S09写特例；embedding继续暂停，S09保留为未解决样本。

### 对 C3-online 的影响

有害注入已清零、材料齐备性 9/10，端到端实验的前提基本具备。剩下的 S09 属"换述漏召"，会让 online 结果里"多事实复合问题"这一类的分数偏低——报告里必须把这一类单独标注，不能混进总平均。

## C3-online 实测结果（2026-10-29，真实模型，`scripts/bench-c3-online.mjs`）

> 本节是 n=1 的首轮。**正式数字看下一节的三次重复**；本节保留用于对比"单次 vs 重复"的差别。

配置：`deepseek-chat`、`temperature=0`、10 场景 × 3 臂 = 30 次对话，共 49 次模型调用。
计费取 provider `usage`（`prompt_tokens` / `cache_hit_tokens` / `completion_tokens`），不用插件估算值。

| 臂 | 说明 | 通过 | 成本 | 工具调用 |
|---|---|---|---|---|
| A `nomem` | 无记忆，只有问题 | **3/10** | ¥0.0184 | 0 |
| C `default` | 当前默认：不自动注入，模型自己 `ctx_find`/`ctx_read`（最多 3 轮工具循环） | **10/10** | ¥0.0477 | 37 |
| E `plain` | 对照：同样事实以普通文本塞进 system | **10/10** | ¥0.0050 | 0 |

合计 **¥0.0712**（预算上限 15 元，用了不到 0.5%）。累计 prompt 20,141 / cache hit 9,472 / completion 5,645 token。

### 首轮曾提出的结论（复核后撤回）

1. **记忆确实有用**：3/10 → 10/10。失败的 7 个场景（S01 S02 S04 S05 S07 S08 S09）全部是"需要历史事实"的，无记忆臂只能答"我不确定"。
2. **但图记忆相对纯文本没有增益**：`default` 与 `plain` 都是 10/10。
   也就是说，在"静态事实能不能被正确带进回答"这件事上，**工具检索 + 图结构没有比"把同样的话塞进 prompt"更好**。
3. **而且更贵**：`default` ¥0.0477 vs `plain` ¥0.0050，约 **9.5 倍**。差额来自工具往复（37 次调用）而不是注入本身。

### 这对产品定位意味着什么（重要）

如果我们的卖点写成"记得更准"，这份数据不支持——**相同事实下没有准确率优势**。

我们的价值必须落在纯文本对照做不到的地方：

- 事实**可以被更正/替代**，且旧版仍可查（S02 的替代链、S10 的 `matched_history`）；
- 每条事实有**来源与工作区归属**（S04 的零泄漏）；
- 有**预算与投递账本**，能解释"这一轮到底给了模型什么"；
- 不依赖"每次都把全部事实塞进 system"——事实一多，plain 臂的 prompt 会线性膨胀，而我们有检索与预算上限。

**换句话说：该卖的是"可管理"，不是"更聪明"。** 这与视频策划文档里"不是现阶段承诺：最省钱、最快"的边界是一致的。

### 这次跑测自身的三个坑（都是我的）

1. **判据假阳性**：S01 无记忆臂"通过"，因为回答里出现了"演示"——那是模型自己在列选项。收紧成"实际演示"后才正确判负。
2. **判据假阴性**：S02 记忆臂"失败"，因为它在**解释旧约定**时提到了被禁词组。字符串判据无法区分"提到"与"当成当前"，该场景降级为人工复核（`strictForbid: false`）。
3. **provider 噪声**：DeepSeek 有时把工具调用当**文本**吐出来（`<｜｜DSML｜｜…>`），还出现过一次 `ds_safety` 分类标记。不清洗会把"工具调用标记"当成最终答案，直接判失败。已在 `sanitize()` 里清掉，并在内容为空时补一轮 `tool_choice: "none"`。

### 局限（不许藏）

- 每格 **n=1**，`temperature=0`，单一模型；没有重复测量，**不能报置信区间**。
- 判据是字符串包含，不是语义判分；同义表述会被判错。
- 场景是我们自己写的 10 个，不是外部金标集；**不能外推成"真实使用质量"**。
- `default` 臂只有 3 轮工具循环，超过即判失败——这是 harness 上限，不是产品上限。

## C3-online 重复测量（3 次重复，2026-10-29）

上面那轮是 n=1。补跑 `--repeats=3`（30 格 → 90 格），用来量方差。

| 臂 | 通过 | 成本 | 工具调用 |
|---|---|---|---|
| A `nomem` | **11/30**（36.7%） | ¥0.0588 | 0 |
| C `default` | **30/30** | ¥0.2153 | 139（≈4.6 次/对话） |
| E `plain` | **30/30** | ¥0.0146 | 0 |

合计 **¥0.2884**（累计 prompt 84,614 / cache hit 22,912 / completion 19,194，145 次调用）。

旧报告称default与plain均30/30，但这是每臂10场景×3重复的启发式分数，不是9次独立比较。判据饱和、小样本、单模型和共库干扰使“稳定持平”结论不能成立。

旧报告称nomem有19格失败，并同时写“S07只败1/3”和“那1次通过”；这两处计数表述不一致。缺少原答案，不能独立决定假阳性的确切数量。本轮合成反例已证明：泛泛提基线、否定式“都可以”、复述问题中的“增量”都能通过相应旧判据。

**旧报告的估算费用比**：`default` / `plain` = ¥0.2153 / ¥0.0146 ≈ **14.7**。这是硬编码价格下的算术比值，不是token倍数或供应商账单；原始分臂usage缺失，不能称“重复后更准”。

### 当前结论（以独立复核为准）

1. 旧关键词匹配分数不能称为准确率；不据此量化记忆的真实回答收益。
2. 不能证明图记忆零增益或两方案等效，也不能证明有准确率优势。
3. 14.7是旧脚本假定价格下的估算费用比，不是token倍数；两臂不是同等完整事实、同样系统提示，也不是图结构消融实验。
4. 可管理性是可从实现核实的产品能力；其价值不能由这份失效在线比较推导。先建立盲审rubric和隔离实验，再评估收益。
