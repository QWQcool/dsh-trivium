# 0.8.6 范围建议（基于 2026-11-06 真机验收）

证据：[REAL-SESSION-2026-11-06](evidence-write-provenance/S2/REAL-SESSION-2026-11-06/README.md)。
那次验收 5 项里 4 项通过，**A2 的「一轮只走 1」失败**（一轮走 3）。下面的取舍全部基于
实测值，没有实测支撑的项一律标注。

## 1. 一句话结论

按用户倾向的裁剪方向执行是合适的（只发 增量地图 + 待补写/诊断 + 批量写入 + 热度，
快筛留代码不宣传，身份与 Router 顺延），**但增量地图要先修 `turnsSince` 再发**：
三态机制本身没问题，坏的是计数口径，而计数口径直接决定 token 成本。

## 2. 逐项

| 项 | 真机证据 | 建议 | 理由 | 风险 |
|---|---|---|---|---|
| 增量地图注入（full/skip/diff） | `full`123 tokens → `diff`42 tokens，`skip` 0 tokens；三态都在真实会话里出现 | **发（先修计数）** | 价值最确定：省的是每轮重复的全量地图 | 计数不修则每两轮一次全量（§3 P1），"省"变成"多花" |
| 新轮次键（`t:<n>`） | 一轮 +3，复现两次 | **不发（先修）** | 这是 0.8.6 的卖点之一，现在的行为等于没修好 | 只影响成本与诊断读数，不丢数据 |
| 待补写 + `GET /pending` + 诊断卡 | `lock-busy` → 1 窗口 / 51 事件；卡片与文件/接口三处一致（1/51/144/05:38:44）；stuck/recovered 配对齐全 | **发** | 唯一完全通过且用户能直接看见的一组；诚实性（"没观测到就写没有记录"）实测成立 | 低 |
| 批量写入 | 本次未复测吞吐（导入 4 条 259ms，口径不同） | **发，但别引用旧数字** | 导入路径与写回都正常；`22 条 110ms` 是上一轮的测量，这次没重做 | 发布文案里写"上轮实测"或补一次基准 |
| 地图热度（B2） | 边车计数按次递增、60s 节流、格式版本 1；**顺带发现删节点不清边车条目** | **发** | 只是排序信号，坏了也不丢事实；代码降级路径清楚 | 「排序有没有变好」没对照 → 别写效果承诺；幽灵条目建议随本次一起清（§3 P3） |

| `MemoryWriter` / scope / inherit / Router | 默认关、无调用方 → 零真机数据 | **顺延** | 端口先留着，等有真实调用方再验 | 现在发等于发布未使用代码，增加复审面 |

## 3. 发布前建议先做（都很小）

**P1（必须先做）`turnsSince` 一轮只走 1。**
最可疑根因：`lib/index.js` 的 channels-off 提前返回（第 1405–1408 行）在 `beginTurn()`
（第 1410 行）之前，导致 `currentTurnKey()` 恒为 `""`，任何"窗口里没有用户消息"的
pre-step 都被当成新一轮。修法二选一：把 `beginTurn` 提前；或 `refreshShortMap` 在
`turnKey === ""` 时保持上一轮 key。修完要有一条"一轮内有 N 个 pre-step，`turnsSince`
只 +1"的回归。

**P2（建议做）`lastScreen` 补一个"0 分被工具证据保留"的计数。**
现在只能靠"用户原文 + 纯函数 + `gate.reason`"三条线拼出这个结论（见验收文档 §1.2），
`counts` 读的是工具提升之后的组分数，`audit` 只收最终仍为 0 的组。加一个
`keptByToolEvidence: n` 就能自证，成本极低。

**P3（顺带）两个口径/清理小口子。**
(a) `mapInjections.full` 不含 session-start 的 full，按名字读会少算，建议补计或改名；
(b) 删节点不清 `.dsh/trivium-usage.json` 里的条目，热榜会留幽灵条目，建议在删除路径
顺手清，或在读取时按现有节点过滤。

## 4. 不建议现在做的事

- **不要为了提高"省调用"数字去扩快筛白名单**。2026-11-04 那次已经把命令/路径一类规则删了
  （理由是"形状不证明无事实"），这次实测也没有可省的空间：真实窗口几乎都带工具轮。
- **不要在没有语料校准的情况下开 `identityMerge`**。合并是写路径上的不可逆操作，比漏存更难
  收拾。
- **不要拿这次的 ¥0.88 当账单**。那是峰价上界估算（宿主这几场的 `usage` 没落盘），真实值更低。

## 5. 与用户既定路线的差异

用户原话是"只发 增量地图 + 待补写/诊断 + 批量写入 + 热度；快筛保留但不宣传；身份与
Router 顺延"。本次证据支持这个方向，**唯一要加的前置条件是把 `turnsSince` 修掉再发增量地图**
——否则发出去的正是 11-04 已经修过一次、这次又复发的那个洞。
