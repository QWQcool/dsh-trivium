# 0.8.5 — 上下文管线与内核升级

2026-11-04。这一版**第一次把记忆管线本身的行为改动带给用户**（0.8.4 只改了设置页），
并升级到 `triviumdb@0.9.0` 正式版。

## 变了什么

### 抽取不再为"没内容的话"付钱

事件在进入抽取窗口之前先打一次分（0 无内容 / 1 可能有 / 2 明确陈述）：

- 整窗都是 0 分时，窗口被消费掉，**不发起抽取调用**；
- 2 分的事件排到批首；
- 某个 0 分事件所在的那一轮如果带了工具调用，会被**升到 1 分**，不当作填充句丢掉。

白名单刻意窄：寒暄、纯命令、纯路径、单个 URL 才可能是 0；带引号、带管道、含中文一律按 1 分。

### 短地图按真实使用排序，并且只在变化时注入

- 被 `ctx_find` / `ctx_read` 命中过的事实会获得热度，优先占据短地图的槽位（旧版按插入顺序，最旧的永远进不去）；
- 会话内地图带版本：没变化时 **0 token**（旧版是每次会话开头一份就再也不更新），
  变化时注入"摘要 + 最多 6 行差异"，每 6 轮强制一次全量；
- 面板的「上下文」页显示的是真实的送达账本与只读试算，「运行记录」页顶部显示上一次注入的 mode / reason / token。

### 卡住与待补写都可见了

- 抽取超时（30 秒）、过期写锁、重放超时会被记成 `stuck`，恢复后记 `recovered`，两条成对出现在变更记录里；
  面板「运行记录」页有对应行，没有观测值时显示「没有记录」，不显示 0。
- 抢锁失败、抽取失败或被中断的窗口以前只躺在文件里；现在「运行记录」页有一张**待补写**卡片，
  显示窗口数、事件数、文件更新时间与每个窗口的 80 字预览。

### 批量写入快了一个数量级

外部导入（WorkBuddy / Claude Code / Codex 的 `MEMORY.md`、`CLAUDE.md`、`AGENTS.md`）
以前每写一条都落一次盘。现在整次导入只 flush 一次：实测 22 条从 **2020 ms / 47 次 flush** 降到
**110 ms / 2 次**。

### 内核：`triviumdb` 从 `0.9.0-beta.3` 升到 `0.9.0`

正式版修了我们在 Windows 上反复踩的两件事：关闭后重新打开拿到已删除句柄、原子替换期间的锁路径竞态。
代价是 0.9.0 的批量路径更慢（同机实测队列 p95 206 → 483 ms、吞吐 1462 → 559 次/秒，仍然 0 丢写），
单条写入反而更快（188 → 155.5 ms）。

## 预埋但默认关闭

以下能力**没有调用方**，只是接口与开关先就位；关掉时行为与 0.8.4 一致：

- `scope` 参数（`workspace` / `parent` / `inherit`）：`parent` 仍未实现；
- `inherit` 只读继承（`lib/inherit.js`）：读父库的短地图，有 Router 时经 Router 读，失败降级不抛；
- Router 单点写（`lib/router.js`）：命名管道上的四个写操作 + `apply` / `map`；
- 开关 `scopeInheritance`（默认关，`~/.dsh/trivium.json`）。

## 没变什么

模型工具的名称/参数/返回、schema 版本、`DIM=1536`、token 预算（300/400）、
默认开关、决策替代判据、写入过滤与版本链保护，全部未动。

## 已知限制

1. **快筛可能静默丢事实**：0 分只命中完整白名单，但真实语料里"纯路径 + 一句指令"仍可能被判 0，且没有事后回收机制。
2. **每轮重建地图有成本**：5000 节点实测约 108 ms/轮，发生在每个用户轮的第一个 pre-step。
3. **`lastMapInjection` 是工作区级**：多会话下会互相覆盖，看到的不一定是当前会话的。
4. **超时不取消抽取**：被放弃的运行仍持锁；`stuck` 每类每会话只记一次。
5. **地图热度有自我强化**：已排除面板浏览与自动召回，但"读得多的更容易被读到"本身是偏差。
6. **0.9.0 的批量路径更慢**（见上）：如果以后调大批窗口需要重测。

## 验证

`node scripts/run-all.mjs` → **86/86**（0.8.4 为 74/74）。
真机验证：事件快筛的两种结局、地图 full/skip、`stuck → recovered` 成对出现，
均在本机 DSH 宿主上跑过，证据在 `docs/next-memory/evidence-write-provenance/`。
