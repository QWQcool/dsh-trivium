# dsh-trivium 0.8.8

**写入正确性补丁 + 面板重排。** 0.8.7 把「替代」改成了提案制；这一版修的是提案在真实操作里
仍会出错的三处边界（切库、跨库令牌、审计缺失），并把「运行记录」页改成先看要处理的事。

内核不变：仍是 `triviumdb@0.9.0`（0.8.5 引入）。已验证宿主：`@deepseek-ai/dsh@0.2.2-rc.1`。

## 一、提案不再串库（F88-01）

**切工作区时，旧库的提案响应可能后到。** 选择器已经显示 B，卡片却还显示 A 的原句；点「保持原样」
会把请求发给 B —— 服务端返回 200，于是**把 B 的提案拒掉**，而 A 的那条还在。

修法分两半：

- **客户端**：读提案前先清空列表；请求带上「读取时的工作区」，迟到的响应按序号和工作区丢弃；
  切库时递增序号并清空忙碌态；提交前再核一次这条提案属于当前库，不属于就拒绝提交并重新读取。
- **服务端（纵深）**：提案令牌 `proposalEtagOf` 把**工作区**折进去。两个库即使节点 id、正文、
  节点级 ETag 全同，A 的令牌拿到 B 也会得到 `409 proposal-stale`。

面板文案会说明发生了什么：「工作区已切换，这条提案属于上一个库，已重新读取。」

## 二、确认与拒绝都留下审计行

- 确认成功 → 变更记录新增 `supersede-confirmed`（「替代已确认」），带后继节点、被退役的事实和
  来源入口；
- 拒绝成功 → 新增 `supersede-rejected`（「替代已拒绝」）。

以前「谁在什么入口确认/拒绝了什么」只能从关系元数据猜。现在动作结果也**就地显示在卡片里**
（「已保持原样：这条提案（#3）的两条决策都继续现行」）；如果动作成功但审计写入失败，卡片会
同时说明两件事：「动作已生效，但审计没有写入：…」。

## 三、交互式写入也进工作区锁

0.8.7 只覆盖了确认/拒绝/修订/撤销四类。这一版把**节点编辑、合并、归档、删除**也纳入同一把
工作区锁：另一个进程正在写时返回 `409 WORKSPACE_WRITE_BUSY`，不再出现「面板说改成功、库里锁着」。

明确**不取锁**的两类（写进报告，避免被理解成"全部写接口"）：

- 只写外围文件的：设置、芯片、pins、sidecar；
- 长耗时管理任务：`map/backfill`、`map/cut`、`embed-backfill`——占着交互锁几分钟会把抽取堵死。

`smoke-p89` 用**真实子进程**持锁验证六条路由（编辑、合并、归档、删除、确认、拒绝）全部 409。

## 四、部分导入不再显示成「被拒绝」

外部 Markdown 导入是批量不是事务：服务端写了一半失败时返回 500，但**一半数据已经进库**。
以前前端统一显示"被拒绝"。现在读取响应体里的 `partial`、`newNodesBeforeFailure` 和 `retryHint`：

- 中断前写入 **0 条**、**具体 N 条**、**数量未知** 三种分开说；
- 回执显示在导入按钮下方，作为这次操作的结果。

## 五、面板重排

| 位置 | 变化 |
|---|---|
| 运行记录 | 「待确认替代」提到**最前**（它是这一页唯一等人工的卡片）；候选直接显示**正文**，不用再靠名字猜；处理后就地看到结果 |
| 记忆库 | 搜索独占首行；类型筛选与两个可见性开关收进「筛选（n）」；归档/删除移到**展开后的详情**里；归档/删除/合并的说明也随筛选收起 |
| 设置 · 向量 | URL/模型/Key 下方新增**「保存连接」**；以前这些字段只有在别的开关顺手触发整组保存时才会落盘 |
| 导入 | 回执移到按钮下方（见第四节） |

四页导航与 `Ctrl/Cmd+K` 命令面板不变。

## 六、诊断与文档

- 删除节点时清理热度边车条目（以前会留一条不可见的记录）；
- 身份合并的校准语料与闸门：误合并必须为 0，召回不得低于记录的 7/11；`identityMerge` 仍默认关；
- 新增 `smoke-p91`：**文档里的版本声明必须和 `package.json` 一致**，发布说明不能写成计划。
  这正是"每次发版 README 落后一档"的机器检查。

## 升级

`npm install dsh-trivium@0.8.8` 或 `dsh plugin add dsh-trivium`。与 0.8.7 之间**没有数据格式变化**，
不需要转换；0.8.6 自动建出的替代边保持原样（不回滚），有争议的用「撤销替代」逐条处理。

**没有 `supersedeMode:"auto"` 的改动**：想临时回到自动建边的旧行为，仍可在 `~/.dsh/trivium.json`
里设置，但这不是推荐用法。

## 发布后验收勘误（2026-11-11）

**独立验收未通过。** 在 DSH 0.2.2-rc.1 切换工作区后，如果旧记忆列表仍在，删除确认框可能显示旧库条目，实际永久删除新库同 ID 的条目。使用本版时，切库后请先刷新，等目标库的列表加载完成，再核对条目并操作。

普通目录的提案隔离及上文列出的六条写路由持锁检查通过。不同实际目录的小写名称相同仍可能产生相同的提案令牌。芯片新增和批量删除会写主库，目前能绕过工作区写锁。外部导入回执里的 0 是新增节点数，已有记忆可能已被合并更新。申报宿主可运行原 tgz，但在空目录用标准 npm 与该版本的真实 peers 安装会遇到 `ERESOLVE`。审计字段及其他界面差异见[独立验收与复现记录](reviews/0.8.8-INDEPENDENT-ACCEPTANCE-2026-11-11.md)。
