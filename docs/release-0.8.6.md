# 0.8.6 — 上下文管线

2026-11-06。内核升级（`triviumdb@0.9.0`）**单独发在 0.8.5**，这样出问题时分得清是内核还是插件行为。
这一版只有行为改动。

## 变了什么

### 抽取前先给窗口打一次分（**保留，不作为本版卖点**）

事件在进入抽取窗口之前先打一次分（0 无内容 / 1 可能有 / 2 明确陈述）：

- **只有整窗都是 0 分时**，窗口才被消费掉、不发起抽取调用；混合窗口里的 0 分组会随其他分组一起抽取；
- 2 分的事件排到批首；
- 某个 0 分事件所在的那一轮如果带了工具调用，会被**升到 1 分**，不当作填充句丢掉。

**0 分只剩四种**：空输入、纯标点、`继续。/好的/ok/收到` 这类填充语、寒暄。
命令、路径、URL、单字**一律按 1 分**——外部评审指出"形状像命令"不等于"没有事实"
（`npm is the package manager for this project` 曾被判 0），而那些 0 分无法回收。

**不宣称它省调用**，理由是实测不支持：命令类语料调用 30 → 30（0.0%）；2026-11-06 的真机
复测里，模型每轮都会调 `ctx_find`（连 `ok` 都调），工具证据把窗口升到 1 分，**只有用户
主动中止轮次**时才看得到"整窗丢弃"。保留它只是因为 0 分白名单已收窄到填充语，不是成本收益；
工具证据那条 gate 只在整窗判定之前生效，**整窗被消费掉之后没有回收或重试入口**（见"已知限制"1）。

### 短地图按真实使用排序，并且只在变化时注入

- 被 `ctx_find` / `ctx_read` 命中过的事实会获得热度，优先占据短地图的槽位（旧版按插入顺序，最旧的永远进不去）；
- 会话内地图带版本：没变化时 **0 token**（旧版是每次会话开头一份就再也不更新），
  变化时注入"摘要 + 逐行差异"（**每类最多六行**，再按地图预算裁剪，超出时删尾行并写明省略条数）；
  `turnsSince` 到 6 时强制一次全量（`reason:"refresh"`，**不含会话启动那一次**）；
- **一轮只算一轮**：工具循环里同一个用户轮会出现多次 pre-step，只有第一次能推进计数。
  真机复测发现原来的守卫只比对*相等*的轮次键，而后续 pre-step 不带用户消息、键是空串，
  于是每步都算一轮（实测一轮走了 3 轮）。复审又找出两个缺口并一并修掉：空键会话里
  "第一次空观察"与"已处理过的空观察"无法区分、以及无 host id 且正文在 `content[]`
  里时两条不同消息都得到 `t:1`。现在用独立的 `sawTurnKey` 锚点，并从句子的
  `content[]` 读文本；回归在 `scripts/smoke-p74.mjs` / `smoke-p86.mjs`；
- **计轮的前提是宿主至少在某一步给出用户消息**。一个从不在任何窗口里暴露用户消息的宿主
  拿不到轮次键，会停在第一次观察、不触发 6 轮全量；这是如实说明的能力边界，不是"已修好"。
- 诊断字段的口径：`mapInjections.full` 只数**刷新阶段**的全量，不含 `session-start`；
  `lastScreen.counts` 是**工具证据提升之后**的组分数，不是初始评分；
  `lastMapInjection` 是工作区级，不带会话标识。
- 面板的「上下文」页显示的是真实的送达账本与只读试算，「运行记录」页顶部显示上一次注入的 mode / reason / token。

### 卡住与待补写都可见了

- 抽取超时（30 秒）、过期写锁、重放超时会被记成 `stuck`，恢复后记 `recovered`，两条成对出现在变更记录里；
  面板「运行记录」页有对应行，没有观测值时显示「没有记录」，不显示 0。
- 抢锁失败、抽取失败或被中断的窗口以前只躺在文件里；现在「运行记录」页有一张**待补写**卡片，
  显示窗口数、事件数、文件更新时间与每个窗口的 80 字预览。

### 事实身份：默认**不**做模糊合并

新增 `lib/identity.js`：同一事实换个说法（词序不同、加了修饰）可以被识别为同一件事，
判定用类型、否定、数值（含小数与中文数词）与字符二元组相似度四道闸。

**但它默认关闭**（`~/.dsh/trivium.json` 的 `identityMerge`，缺键=关）。原因是外部评审实测出
三组误合并：`1.5 秒` vs `5.1 秒`、`生产环境 npm` vs `测试环境 pnpm`、`十六天` vs `六十天`
——都属于"修订"而不是"重复"，而合并没有修订链，**误合并等于静默改历史**。
**关掉的只是"模糊合并"这一步**。`lib/identity.js` 的否定 / 数值 / 类型守卫**默认就会执行**
（`lib/store.js` 的 `findMergeTarget`），会阻止一部分旧版会做的子串合并（例如"允许自动发布"
与"不允许自动发布"）。所以"关掉时行为与 0.8.4 完全一致"是不准确的：**默认去重结果有变化**。

### 批量写入：历史离线测量 + 本版如实的部分提交回执

外部导入（WorkBuddy / Claude Code / Codex 的 `MEMORY.md`、`CLAUDE.md`、`AGENTS.md`）
以前每写一条都落一次盘，现在整次导入只付极少数 flush。

- **2026-11-05 的历史离线测量**（不是本版重测）：22 条从 **2020 ms / 47 次 flush** 降到
  **110 ms / 2 次**（代码里仍保留末尾一次收尾 flush）。这个 18× 只属于那次夹具。
- **本版真机只测到**：24 行 `CLAUDE.md` → 259 ms、写入 4 条 / 跳过 7 条；它**不能**证明 18×。
- **批量不是事务**：后面的候选失败时，前面已经落盘的条目仍然保留。复审（F86-03）指出旧的
  错误响应只有一个普通 500、调用方不知道部分成功，现已返回 `partial:true`、
  `newNodesBeforeFailure` 与 `retryHint`（重开验证 2 条确实留存，`smoke-p83` 钉住）。
  重复导入同一文件是幂等的，重试不会重复落盘。

### 背景（**0.8.5 已发布**，不是 0.8.6 的新功能）：内核 `triviumdb` `0.9.0-beta.3` → `0.9.0`

> 0.8.5 用户已经完成这次升级，可以跳过本节；从 ≤0.8.4 直接升到 0.8.6 的用户仍需按下述方式备份。

正式版修了我们在 Windows 上反复踩的两件事：关闭后重新打开拿到已删除句柄、原子替换期间的锁路径竞态。
代价是 0.9.0 的批量路径更慢（同机实测队列 p95 206 → 483 ms、吞吐 1462 → 559 次/秒，仍然 0 丢写），
单条写入反而更快（188 → 155.5 ms）。

> **升级前请备份整个 `.dsh` 目录（插件关闭状态下）。**
> 0.9.0 把库文件版本升到 v10，旧内核读不了（`TDB_UNSUPPORTED_DATABASE_VERSION`），
> 也就是**不能靠降级插件回退**，只能恢复升级前的备份。备份要复制**整个文件组**
> （`trivium.tdb` 及同前缀的 `.gidx` `.pidx` `.pld.*` `.text` `.text.meta` `.vec` `.wal` `.lock` `.flush_ok`），
> 只复制 `.tdb` 会得到 `TDB_CORRUPTED_FILE`。演练记录见
> `docs/next-memory/evidence-write-provenance/INFRA/KERNEL-UPGRADE-DRILL-2026-11-05/`。

## 调用关系（**按实际代码，不按"预埋"笼统归类**）

复审（F86-04）纠正了一处申报错误：这些模块**不是**整组"零调用方、零默认行为"。

**默认已接入主链路**：

- `lib/memory-writer.js`：默认抽取的 `applyCandidates` 就走它（`lib/extract.js` 的
  `memoryWriterFor(db, writer)`），四种写入都经过这个端口；
- `lib/identity.js`：模糊合并本身默认关，但类型 / 否定 / 数值守卫**默认参与**
  `findMergeTarget`，会改变部分子串合并结果（见上）。

**没有调用方、默认关闭、标注为实验**（关掉时不影响主链路）：

- `scope` 参数（`workspace` / `parent` / `inherit`）：`parent` 仍未实现；
- `inherit` 只读继承（`lib/inherit.js`）：读父库的短地图，有 Router 时经 Router 读，失败降级不抛；
- Router 单点写（`lib/router.js`）：命名管道上的四个写操作 + `apply` / `map`；
- 开关 `scopeInheritance`（默认关，`~/.dsh/trivium.json`）。

这些**没有**在真实宿主上按宿主能力验收过，只是接口与开关先就位；不要当作已验收能力宣传。

## 没变什么

模型工具的名称/参数/返回、schema 版本、`DIM=1536`、token 预算（300/400）、
默认开关的**取值**、决策替代判据、写入过滤与版本链保护，未动。
但默认开关取值不变**不等于默认行为不变**：上面 identity 守卫那一条就是例外。

## 已知限制

1. **快筛只剩填充语**：0 分只有空输入、纯标点、`继续。/好的/ok` 与寒暄；命令、路径、URL、单字一律 1 分。
   因此这项能力现在基本不省调用（命令类语料实测 0.0%），且被丢弃的窗口只在内存里留一条 audit 记录，没有重新处理入口。
2. **每轮重建地图有成本**：5000 节点实测约 108 ms/轮，发生在每个用户轮的第一个 pre-step。
3. **`lastMapInjection` 是工作区级**：多会话下会互相覆盖，看到的不一定是当前会话的。
4. **超时不取消抽取**：被放弃的运行仍持锁；`stuck` 每类每会话只记一次。
5. **地图热度有自我强化**：已排除面板浏览与自动召回，但"读得多的更容易被读到"本身是偏差。
   热度边车只按引用递增，**删节点不会清掉对应条目**，榜单可能留幽灵条目（不影响事实正确性）。
6. **0.9.0 的批量路径更慢**（0.8.5 的历史测量，见上）：如果以后调大批窗口需要重测。
7. **计轮依赖宿主暴露用户消息**：从不在任何窗口给出用户消息的宿主会停在第一次观察，
   不触发 6 轮强制全量；离线契约复现已通过，但这条路径没有真机宿主样本。
8. **待补写文件损坏会明确失败**（`GET /pending` 返回 500 / `ok:false`），不会再把"读不出来"
   显示成"没有待补写"；刷新卡片只重读、**不会重试**，重放只发生在下次会话启动。
9. **批量导入可部分提交**：返回体带 `newNodesBeforeFailure` 与 `retryHint`；重试同一文件是幂等的。

## 验证

`node scripts/run-all.mjs` → **89/89**（89 个脚本合计 147.4 秒，作者本轮在本机复跑；
0.8.4 为 74/74）。复审只跑了 14 个非 UI smoke（292/292 条断言），**没有**替我们复跑 `run-all`；
两条数据不要混为一谈。

复审后本轮改动的断言数：`smoke-p74` 29 → **36**、`p82` 13 → **14**、`p83` 12 → **14**、
`p86` 15 → **16**、`p87` 20 → **22**。

真机验证（2026-11-06，本机 DSH 宿主 + `deepseek-flash`，证据见
`docs/next-memory/evidence-write-provenance/S2/REAL-SESSION-2026-11-06/`）：

- 快筛两种结局都复现了：整窗丢弃（`skippedBy:"screen"`、`screenedOut:1`）与 0 分被工具证据保留（`gate.reason:"tool-evidence"`）；
- 地图三态复现：`full` 123 tokens → `diff` 42 tokens → `skip` 0 tokens；
- `stuck{lock-stale}` → `recovered` 成对，`afterMs` 86 021；
- 待补写卡片与 `GET /pending` / 文件三处一致（1 窗口 / 51 事件 / 144 已确认）；
- 真实导入 24 行 `CLAUDE.md`：259 ms，写入 4 条、跳过 7 条；
- **同一轮 `turnsSince` 走了 3**——这一项当时是失败的。修复后又在离线契约层复现了
  复审给的两个反例（无键会话六次空观察、无 id 且正文在 `content[]` 的两条消息）并修掉；
  真实宿主**仍未复测**（要再花一次模型调用），所以本版不宣称"真机已验证一轮只走 1"。

复审发现的两个阻塞项（轮次计数遗漏 / 损坏 pending 被包装成成功）与部分提交回执已修复，
逐条复现值见 `docs/reviews/0.8.6-REVIEW-PACKET.md` 的"复审后修订"一节。
