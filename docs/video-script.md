# dsh-trivium 介绍视频 · 录制脚本（台词 + 对话稿）

> 用途：录一期短视频介绍 dsh-trivium（DSH 进程内图记忆插件）。
> 重点只演示四件事，按用户指定顺序：**跨会话记忆 → 开启芯片后的能力 → 生成检查点新增方框 → 再对话 → fork 检查点 → 再对话**。
> 形式：录屏 + 口播旁白（不出镜）；目标时长 **3 ~ 3.5 分钟**。
> 适用版本：0.4.x（含芯片 / 会话层 / Git 旁路等新功能）。

---

## 0. 一句话立意（开场必须立住）

> DSH 原装没有跨会话记忆——新会话就失忆。dsh-trivium 在进程内补一张图记忆：按**节点和边**记、默认**少注入**，再把压缩和分叉画成**检查点方框**，随时可以 **fork** 出新分支。一个插件，三层能力，全部默认安静、不另起服务。

## 2. 台词全文（按镜号，可直接照读）

### 镜 1 · 开场（0:00–0:15）

**画面**：DSH web 界面，停在某个工作区（建议用 dsh-trivium 自己的开发工作区）。

**口播**：
> DeepSeek Harness 的插件生态里，原装运行时其实**没有跨会话记忆**——你换一个新会话，它就忘了昨天定的方案。dsh-trivium 就是给 DSH 补上这一块的**进程内图记忆**插件：一个文件、四个工具、默认安静。这期视频看四件事：跨会话记忆、芯片白名单、检查点、还有从检查点 fork。

---

### 镜 2 · 跨会话记忆（0:15–1:00）

**画面**：新建一个会话（会话 B），全程打开「轨迹」侧栏。

**口播**：
> 这是新开的一个会话。注意看，它开头并没有被灌满历史——session-start 只带一张 **≤400 token 的短地图**，告诉模型库里有什么实体、几条偏好，剩下的用工具自己下钻。我们直接问它昨天的事。

**与 dsh 的对话（2a）**：

| 项 | 内容 |
|---|---|
| 用户输入 | 「我们上次定的鉴权方案是什么？我记得有个偏好。」 |
| 预期模型行为 | 先见短地图注入（Trajectory 来源 `dsh-trivium`），然后模型调 `ctx_find("鉴权")`，命中 preference「鉴权走 header X」 |
| 预期回复要点 | 「上次定的是：本仓库鉴权走 **header X**，这条偏好 `about→` AuthGateway 实体。」 |
| 画面标注 | ① 圈 Trajectory 里的短地图注入；② 圈 `ctx_find` 工具调用；③ 圈返回里的边路径（`<-about-AuthGateway`） |

**口播（衔接）**：
> 它不只是翻到一个词条，而是**沿着图走**——这条偏好 `about` 到 AuthGateway 实体。所以下次你直接问 AuthGateway，也能带出这条决策，哪怕那句话里根本没有「鉴权」两个字。

---

### 镜 3 · 开启芯片（1:00–1:40）

**画面**：设置 →「Trivium 记忆」→ 拨开 **芯片（记忆白名单）** → 切回对话页，标题栏出现 **对话 / 轨迹 / 芯片** 三个标签 → 点开芯片标签 → 勾选「鉴权走 header X」→ 演示一次「新增」（粘贴一段文字，点新增）。

**口播**：
> 默认是「模型自己想起来才查」。但有时候你希望某几条记忆**必须进窗口**——这就是芯片：记忆白名单。开关拨一下就保存，标题栏立刻多一个「芯片」标签。
> 勾上这条，你发的**下一条**消息就会把它钉进上下文；单会话预算 ≤300 token，按会话隔离，不串工作区。也可以在芯片条上直接「新增」一条，整段粘贴也是一条。

**与 dsh 的对话（3a）**：

| 项 | 内容 |
|---|---|
| 用户输入 | 「好，按这个来。embedding 那条决策也帮我钉上。」 |
| 预期模型行为 | Trajectory 出现来源 `dsh-trivium` 的**钉选注入**（L0，≤300 token） |
| 预期回复要点 | 回复带出「鉴权走 header X」约束，确认按上次决策执行 |
| 画面标注 | 圈 Trajectory 的钉选注入行；圈芯片标签里的勾选状态 |

---

### 镜 4 · 生成检查点（1:40–2:05）

**前置**：设置里已打开芯片下的 **会话层** 开关（镜头 3 顺手拨开，口播可提一句）。

**画面**：切到「芯片」标签（会话层画布）→ 点 **生成检查点** → 右侧「后续」收成左边一个历史方框（显示摘要前两行）。

**口播**：
> 对话积累了一段，我们给它画个格。点「生成检查点」，右侧的「后续」就被收成左边一个历史方框。
> 注意：它只切**情节图**，不触发 DSH 的窗口压缩——你的上下文窗口没被动过，模型看到的还是原来的内容。

**画面标注**：① 圈「生成检查点」按钮；② 圈新出现的历史方框（摘要）；③ 可补一句：没压过就只有一个「后续」方框是正常的。

---

### 镜 5 · 再对话（2:05–2:20）

**画面**：切回「对话」，继续在主线上聊。

**口播**：
> 继续聊，这一段落在「后续」方框里。会话层**不会按条数自动切格**——要分段就手动点生成检查点，或者用 `/compact`。

**与 dsh 的对话（5a）**：

| 项 | 内容 |
|---|---|
| 用户输入 | 「这个方案里，embedding 默认关还保留吗？我担心检索质量。」 |
| 预期模型行为 | 正常回复；可调 `ctx_find` 带出 embedding 相关记忆 |
| 预期回复要点 | 说明默认关的原因（无本地 embedding、关键词 + 图遍历兜底），给出开关建议 |
| 画面标注 | 无需标注，画面自然推进 |

---

### 镜 6 · fork 检查点（2:20–2:50）

**画面**：切回「芯片」标签 → 点历史方框上的**分叉图标** → 侧边栏出现子会话 → 画布长出一条 `forks_from` 分支 → 子会话自动打开。

**口播**：
> 现在我想试一条相反的路：**默认开 embedding**。不想动主线，就从刚才的检查点 fork 一个子会话。
> 子会话出现在侧边栏，检查点之前的内容——包括当时已经压缩的摘要——由 DSH **原样拷过去**，我们不会二次总结，不叠两层摘要。画布上长出一条 `forks_from` 分支。

**画面标注**：① 圈分叉图标；② 圈侧边栏新子会话；③ 圈画布分支连线。

**口播（衔接，一句带过）**：
> 注意，fork 出来的子会话默认不继承芯片钉选——要继承，分叉时勾「分叉时继承钉选」就行。

---

### 镜 7 · 再对话（分支里，2:50–3:10）

**画面**：子会话窗口里继续聊 → 切回主线验证主线没被改。

**口播**：
> 分支里怎么折腾都不影响主线和记忆库。切回主线，内容还是原样。这就像把一次长对话拆成**可以回退、可以并行**的实验。

**与 dsh 的对话（7a）**：

| 项 | 内容 |
|---|---|
| 用户输入（子会话） | 「在分支里：把 embedding 打开，填一个 OpenAI 兼容地址，跑一轮检索对比。」 |
| 预期模型行为 | 模型在分支里推进任务（可能调工具改设置 / 跑检索） |
| 预期回复要点 | 分支内正常执行；切回主线看到原会话内容未被改动 |
| 画面标注 | ① 分支对话推进；② 切回主线对比两窗口内容 |

---

### 镜 8 · 收尾（3:10–3:30）

**画面**：结尾卡片（一行安装命令 + 仓库地址）。

**口播**：
> 总结一下：**记忆**负责跨会话——节点和边，默认少注入；**芯片**是你想钉进窗口的白名单；**会话图**把压缩和分叉画成检查点，想换个方向就从方框 fork。一个插件、三层能力，全部默认安静、进程内、不另起服务。
> 安装就一行命令，链接在简介里。

**结尾卡片文案**：

```bash
dsh plugin --profile web add dsh-trivium
```

## 4. 录制前 Checklist（防翻车，按序执行）

1. **种好记忆种子**：确认工作区 `.dsh/trivium.tdb` 里已有 2–3 条 preference / decision / entity（如「鉴权走 header X」「embedding 默认关」）。
   - 没有就先在会话 A 里说「记住：本仓库鉴权走 header X」等，或直接 `ctx_remember` 写入；抽取偏严，**别指望闲聊自动入库**。
2. **提前验证**：新开会话 B，手动输入一遍 2a，确认 `ctx_find` 能命中——避免录到一半发现记忆库是空的。
3. **开关**：设置里拨开「芯片（记忆白名单）」+ 其下「会话层」；拨一下即保存，无需重启。确认标题栏出现「芯片」标签。
4. **fork 前提**：fork 只能在**已完成轮次**上切；录制时确保当前没有进行中的开放轮次，否则点分叉会失败提示（别在镜头里出现报错）。
5. **演示卫生**：全程不要出现真实密钥 / token / 本地路径 / 机器名；对话里的记忆示例用脱敏内容（「鉴权走 header X」这类）。
6. **画面准备**：Trajectory 侧栏打开；浏览器/字体放大；录屏分辨率建议 ≥1080p；先做一遍完整彩排，把每段口播和操作节奏对齐。
7. **环境**：只开一个 `dsh web` 进程（同一 `.tdb` 不能被两个 Node 进程同时打开）；录制前 git 状态保持干净（可选，避免画面出现未提交提示）。
