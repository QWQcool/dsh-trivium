# 0.7.1 后端可靠性收尾

日期：2026-10-28。承接 [0.7.0 查验](bug-audit-2026-10-28.md)，本页只记录本轮后端收尾，不替代发布回执或真实宿主验收。

## 已完成

| 项目 | 原问题 | 本轮行为 |
|---|---|---|
| 按工作区的旁路 health | A 库失败后，B 库成功会把全局 health 改成正常 | 状态接口按所请求 cwd 返回旁路状态，并返回 `cwd` 与 `scope: workspace`；A/B 状态不互相覆盖 |
| 显式生成的失败 | 定时写出失败可见，但直接点击生成的异常只向调用者抛出，health 可能仍显示正常 | Generate、bootstrap、flush 和定时写出共用记录失败的出口；异常仍向调用者返回，后续恢复只清本库错误 |
| 运行诊断归属 | lastContextPlan、lastExtract、短地图数和 trace 可能来自另一个库 | 运行时按 cwd 保存这些诊断，`/status` 返回 `diagnosticsScope: workspace`；没有记录的库返回 null/0，不借用另一库记录 |
| 更正预算优先级 | 固定 pins 每一轮先占预算，可能使同一条短更正一直无空间 | 优先选择已看事实的更正，再选择 pins 和 recall；仍使用每用户轮累计 300 估算 token，没有额外预算 |
| 自然到期 | 只有写事件能生成更正；时钟跨过期限没有写事件 | 每次真实 pre-step 检查本会话投递账本中已送达事实的当前期限，排入短更正，不修改数据库；不覆盖已经产生的版本替代通知 |
| 暂停／延期解释 | 注入关闭或本轮预算不足，UI 仍可能承诺下一条消息生效 | pending/session 返回 `blockedReason: channels-off` 或 `budget`；恢复注入或新轮有预算后按正常流程送达，成功后才消费 |

旧的无参数 `sidecarHealth()` 保留为带 `scope: process` 的兼容诊断探针，生产 UI/API 不再使用它展示某个库的状态。

## 注入关闭时的明确选择

关闭芯片和自动召回仍表示不再附加这两条通道的上下文；本轮没有绕过用户的关闭选择强制注入更正。已排队更正保留并显示暂停原因。自然到期仍可被下一次 pre-step 观察到，待用户恢复注入后发送。

更正优先于重复 pins 解决的是预算饥饿，不是无条件送达保证：没有后续 pre-step、用户关闭注入、或同一用户轮已用完 300 时，仍需等待。不会为了送更正而重置账本或增开新预算。

自然到期的范围是本进程投递账本实际记录的 pin/recall 事实。开场短地图是线索标签，不在本次新增全文事实跟踪范围内；进程重启会清空账本。本次不新增后台计时器、持久化投递审计或对话历史全量扫描。

## 新增数据字段

| 接口 | 字段 |
|---|---|
| `GET /api/dsh-trivium/status?cwd=…` | `diagnosticsScope: workspace`；`derived.sidecar.cwd`、`derived.sidecar.scope`；原有诊断字段现在只取该库 |
| `GET /api/dsh-trivium/corrections?cwd=…` | `sessions[].blockedReason`、`sessions[].pending[].blockedReason`：`channels-off` / `budget` / null |

前端应翻译为“注入已关闭，恢复后再发送”“本轮预算不足，等待后续轮次”，null 也只表示当前没有已知阻塞，不应写成保证下一条送达。
