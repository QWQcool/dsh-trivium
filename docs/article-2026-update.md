# 用 dsh-trivium 给 DeepSeek Harness 补上跨会话图记忆

> 文稿更新：2026-10-28，对应 dsh-trivium 0.7.0。此文件是仓库内介绍稿，尚未代替用户发布到外部网站；旧截图不作为本版验收证据。安装详情见 [中文 README](../README.zh-CN.md)，版本与验证边界见 [文档入口](README.md)。

聊完一个任务，再开新会话时，模型不一定记得上次确认的约定。dsh-trivium 把其中值得保留的实体、偏好、决策和经验写进工作区图记忆，之后按需检索。它随 DSH 进程加载 TriviumDB，不需要再启动一个数据库服务。

主文件是 `<workspace>/.dsh/trivium.tdb`。记忆按工作区隔离，同一工作区的多个会话共享事实库；对话分叉并不会复制一份独立数据库。

## 四个工具，按需读取

| 工具 | 用途 |
|---|---|
| `ctx_find` | 搜索短摘要，返回节点 id、状态与关系路径 |
| `ctx_read` | 读取指定节点正文与邻接信息 |
| `ctx_remember` | 显式保存事实，可附带关系目标 |
| `ctx_link` | 连接已有节点的业务关系 |

例如，把「AuthGateway 的鉴权走 header X」记成偏好，挂到 AuthGateway 实体。新会话既能按「鉴权」找到它，也能沿 AuthGateway 的业务关系找到相关决策。是否记准、检索是否命中仍取决于实际数据和查询；我们没有做过足以证明胜过同类插件的统一质量对照。

## 少注入，但不把数字当账单

会话开始时默认给一张 ≤400 估算 token 的短地图，告诉模型库里有哪些线索。模型需要详情时再调用工具。

芯片、自动召回默认关闭。用户开启后，芯片、召回和更正共用**每用户轮累计 300 估算 token**，包括包装文本；同一轮的多个工具步骤不会各拿一份 300。主动 `ctx_find` 的默认输出上限另为 1200，`ctx_read` 保留显式正文读取。

这些限制不是整个会话的 token 上限，也不是模型计费统计。长条目可能装不进剩余预算，不能把“勾选芯片”理解成无条件保证送达。

## 决策可以更正，也能保留来路

当旧方案被新方案替代，用户在设置页确认 `new --supersedes--> old`，保留历史正文。自动召回命中旧词时，解析到当前版本，输出当前节点的 id、正文和状态；显式读取旧 id 或人工钉选历史仍保留原选择。

看过旧事实的会话可以收到一条短更正，和其它注入共用预算。0.7.0 在「召回检查」中展示待发与最近已发，并增加只读版本链体检。更正账本是进程内状态，重启后清空；体检只报告问题，不自动修链。

来源页显示已经保存的类型、时间和短引文；没记录或无法定位时明确说明，不凭空补造会话链接。召回检查解释实际经过的候选与过滤步骤；只读预览不请求远程 embedding，也不伪造语义评分。

## 芯片和会话层是可选功能

打开芯片后，可以勾选少量事实供当前会话使用。会话层再单独开启，用方框投影 DSH 的 compaction 检查点和 fork 谱系。

「生成检查点」只切情节图，不压缩模型窗口；「更新检查点」从已有会话标记补投影。fork 由宿主复制会话前缀，插件不再生成第二份总结。子会话默认不继承 pin，用户可以勾选继承。

分支中的对话不会改写父会话历史，但同工作区记忆与插件配置仍共享。需要实验隔离时，应使用独立测试工作区与设置，而不是只创建一个 fork。

## 存储在本地，不等于所有处理都离线

数据库在本机。**抽取默认开启**，规则候选之外，可调用宿主配置的模型整理会话中的事实；模型服务的去向和费用由宿主配置决定。关闭抽取后仍可显式使用记忆工具。

远程 embedding 独立配置、默认关闭；未开启时仍可使用文本与图检索。来源、历史、只读召回检查面板本身不会为展示内容额外调用模型。

## 导入、导出和 Git 旁路

JSON 是结构化事实交换格式；Markdown 是供人阅读和迁移整理的投影，不能当等价回写格式。WorkBuddy `MEMORY.md`、Claude Code `CLAUDE.md`、Codex `AGENTS.md` 的导入是一次性迁移，不是持续双向同步；严格抽取会漏掉不满足规则的内容，需要人工检查。

Git JSONL 写出默认关闭。打开后，图变更约 1.5 秒后写为 `.dsh/trivium.jsonl`，只包含业务节点和边，不包含向量、episode、pins 或本地来源引文。开库发现已有 JSONL 变化时会尝试应用；关闭写出不关闭读取。二进制 `.tdb*` 应加入 gitignore。

JSON / JSONL 当前格式为 v2，可读 v1；旧版不能原地重写 v2 后保证不丢信息。旧数据恢复需要完整备份，不能把降级包覆盖当成回滚。

## 支持范围与安装

0.7.0 使用精确锁定的 `triviumdb@0.9.0-beta.3`。已有 Web rc.4 的交互记录，桌面 rc.3 的历史记录主要是预览工作树 API 验证；详细覆盖见 [文档入口](README.md)。仅支持 900px 及以上宽度，同一 `.tdb` 只允许一个读写进程。性能、检索质量和同类项目之间仍缺少固定条件下的对照，不能把架构特点当作速度或准确率结论。

```sh
dsh plugin --profile web add dsh-trivium
```

重启 DSH Web 后打开工作区，在设置里查看「Trivium 记忆」。芯片、会话层、自动召回和 Git 旁路保持默认关闭，按实际需要开启。
