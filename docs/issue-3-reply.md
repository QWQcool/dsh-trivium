# Issue #3 回复草稿（历史，不再直接发送）

> 该稿写于 0.4.22 发布前，保留对根因和旧数据处理的解释。原修复后来已发布；当前升级与支持信息见 [文档入口](README.md)。本次仅整理仓库文档，没有发送 issue 留言。可复用的排障内容已由 README 和发布记录承接，本文件列为后续删除候选。

感谢你和鱼鱼把复现过程写得这么清楚。我们复现了这个问题，主因确实在插件的期限与召回逻辑。

原实现把 decision 正文里的日期自动解释成 `until`，再计算 `untilAt`。日期一过，检索就会在排序前直接过滤该节点，导致已有的过期降权没有机会生效。数据没有从库里删除，所以会出现 `ctx_read` 能读到、`ctx_find` 找不到的情况。清空期限后重新从正文提取，也是同一条写入逻辑造成的。

以下修复后来已随 **0.4.22** 发布（原稿的“准备发布”已过时）：

- 不再从普通正文自动推断有效期。这同时覆盖自动抽取、芯片新增和 Markdown 导入；模型抽取结果也不能自行附加期限。真正的期限通过设置页或 `ctx_remember` 的独立 `until` 字段明确设置。
- 清空 `until` 会同时清除 `untilAt`，以后编辑含日期的正文不会再填回来。修改期限时也不会残留旧时间戳；保存未改变的相对期限不会不断延长它。
- `ctx_find` 保留相关的过期历史，标记 `stale` 并降权；需要只看未过期记忆时，可以传 `include_stale: false`。开场短地图和自动召回仍排除过期决策，人工钉选的过期条目则会明确标记。
- 附带提到的召回问题也修了。进一步排查发现，底层 BM25 / 向量检索即使已命中，也会被插件的整句 `includes()` 检查丢弃。现在保留原生候选，并增加中英文多词兜底、别名匹配和两字中文实体锚点。你不需要为了正常搜索，手工补齐所有 entity 枢纽。

旧数据的期限不会被批量抹掉，因为旧记录没有保存“手填”还是“自动推断”的来源，直接全部清除可能误伤真实有效期。升级后，误标的记忆可以重新通过 `ctx_find` 查找；也可以在设置里勾选「显示过期决策」，清空对应条目的 `until` 并保存，不必再把正文日期改写成特殊形式。

补充一个小细节：现有 `/nodes?stale=1` 和设置页的过期显示开关能够列出这些条目，不过确实没有清楚解释期限的来源和过滤原因，这部分诊断仍值得完善。

本次还将 TriviumDB 升到了 **0.8.11**。期限和候选过滤的修复是在插件层完成的，并不是靠数据库升级绕过问题。已通过离线回归，并覆盖了历史日期、清空与重开、期限修改、中文多词、向量命中和过期历史检索等场景。
