## 本次变更

按 `docs/next-memory/IMPLEMENTATION_PLAN.md` 实现三个相互依赖的部分，分三个提交。

**统一上下文预算与去重（M0）**

- 芯片与自动召回不再各截 300。两路共用同一用户轮的 300 估算 token：芯片优先，召回只用剩余额度；同一节点跨渠道只出现一次；同一轮的工具循环不会重复注入。
- 轮次由宿主消息 id 判定，不再按查询文本或调用次数。投递失败不记账本，可重试；compaction 之后可以重建；fork 不继承父会话的账本与 pins。
- `ctx_find` 默认上限 1200 估算 token，超预算丢弃整条记录并提示，不切半条 JSON。`ctx_read` 只投影旧字段，来源与版本元数据不会撑大默认输出。
- 四个工具、参数集合与 schema 估算（529）保持基线不变。

**来源与召回解释（M1）**

- 设置页分「记忆条目 / 召回检查」；条目详情分「内容 / 来源 / 决策历史」。
- 来源沿用 `payload.source`，新增 `kind` / `capturedAt`，引文限 240 字符。没有记录就显示「没有可定位的来源」，不补造会话或引文；宿主没有跳转接口，因此不提供 deep link。
- 召回诊断只记录实际产生候选的管线分支，最多 20 条 / 10 分钟 / 每条 64KiB / 每阶段 100 条摘要。跨工作区或跨会话查同一 trace 返回 404，过期返回 410。
- 「运行只读检查」不写库、不跑工具、不请求 embedding，明确标注语义通道未运行。

**人工确认的替代关系（M2）**

- 新增 `supersedes` 有向边（新 → 旧），放在独立集合，不进默认业务边扩展。
- 首版线性链：每个节点最多一个直接前驱与一个直接后继；拒绝自环、循环、分叉、跨库、非决策、归档端点与超过 32 跳。
- 写入由工作区队列串行化「读取 → 校验 → 原生事务」，两端 ETag 失配返回 409，`operationId` 保证重试幂等，事务失败两端保持原状。
- 撤销只删指定 `supersedes` 边，其它边保留；后继已有更新版本时拒绝拆链。
- 链上正文受保护：自动抽取、合并、正文编辑、删除都会被拒绝（`REVISION_PROTECTED` / `REVISION_LINKED`）。非事实字段仍可编辑。
- 自动召回把旧版本命中映射到当前头并去重，带一条 `matched_history=#17 → current=#42` 指针；人工 pin 的旧节点不改写，只标历史。
- 「显示已替代」与「显示过期」是两个独立开关，两个状态也分开显示。

**数据格式**

- JSON 图导出 `version: 2`，边可以带 `metadata`。
- Git JSONL `v: 2`，新增 `supersedes` 行与 `meta`；节点行仍不含 `source`，本地来源与引文不会进入可提交文件。
- 旧 v1 文件仍可读。**v2 不能原地降级**：旧版本会丢掉版本关系，降级需恢复升级前的文件组。

## 与 0.4.22 的行为差异

- 芯片与召回的合计上限从「各 300」变成「共用 300」；同一轮内重复调用 pre-step 不再重复注入。
- `ctx_find` 输出有 1200 估算 token 上限。
- `ctx_read` 输出为字段白名单投影，未知的新字段不会自动出现。
- 默认值全部未变：芯片、自动召回、会话层、Git 旁路、embedding 仍是关。
