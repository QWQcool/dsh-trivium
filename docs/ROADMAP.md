# 开发路线：低成本记忆、Super Agent 与 TDB

更新：2026-11-18。目标是在尽量少的模型调用、上下文和维护成本下，可靠保存、找到并解释有用事实。本页是后续开发的唯一任务入口；实现和发布状态见 [CURRENT-STATE](CURRENT-STATE.md)，契约见 [PLAN](../PLAN.md)。未标完成的条目是规划，不代表功能已接入或已取得收益。

已发布版本及正式桌面交付完成。开发分支的五项首版通过统一测试（98/98），随后补验回退、隔离桌面和真实回答；新增、改进、删除及兼容影响集中见 [UNRELEASED](UNRELEASED.md)。接下来优先 P1-B：显式按需记忆包和变更投递，实测上下文量及证据质量；自动召回等对照通过后再评估。本阶段继续暂缓本地模型安装和远程 embedding 优化。

### 共同测量协议

- 语料含同名不同实体、跨语言改写、精确标识符、数值变化、否定、过期/替代、关系缺口和无答案题；开发题与后续留出题分开。
- 分开计量写入准确性、候选 Top-1/Top-5、错误注入、最终回答、请求数、输入/输出 token、p50/p95 和预算拒绝率。候选命中不等于回答正确。
- 首先做合成语料和确定性离线对照；不要求安装 Ollama，也暂缓远程 embedding 优化。保留失败和跳过样本。
- 缓存键绑定作用域和相关事实/关系版本；取消、范围变化、预算失败不缓存为空结果。既有 embedding 路径继续绑定模型身份。

2026-11-16 起，上面前四项已经有可执行入口：[离线基线](reviews/MEMORY-EVAL-BASELINE-2026-11-16.md)（`node scripts/memory-eval.mjs`，26 个冻结场景，零模型/零 embedding 调用）。它量的是"冻结候选 + 真实写入守卫 + 真实范围检索"，**模型抽取质量与最终回答仍为未测**；后续实验必须在同一夹具上对照，不能改冻结期望。

## 3. Super Agent 的适配与借鉴

2026-11-17 已新增独立[真实模型入口与回答对照](reviews/MEMORY-QUALITY-2026-11-17.md)。原离线入口继续不测模型、token 或回答，二者分开记账；实际结果未支持记忆包在当前题集上普遍胜出。

2026-11-16 核对的公开原型仍为 `8c32a9dc`。它是研究参考代码，与文章和内部系统并不完全相同。公开实现使用 Main Session / Executor Session、Ticket、Trigger、Subscription、Mandate；文章里的 Router/Worker 概念不能当作稳定的通用宿主插件 API。

依据：[原型说明](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/README.md)、[领域模型](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/docs/001-domain.md)、[执行与恢复](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/docs/003-execution.md)、[架构](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/docs/007-architecture.md)。

| 可借鉴机制 | 本插件的具体改进 | 已有基础与限制 |
|---|---|---|
| Gate + Assessment | 程序检查授权和事件身份，复用抽取判断事实；先去重复事件，不额外加筛选模型 | 有 screenTurns；“像命令”不能作为删事实理由 |
| Subscription 扇出 | 任务只订阅相关实体/事实的版本变化，送变更和事实 ID | 有差异地图和投递账本；需限制范围、上限和取消 |
| 上下文与授权分离 | Worker 读到的事实只是上下文；共享写入和替代仍单独确认 | 有人工提案；不能从工单文本/图关系推断权限 |
| 单一 Engine 写者 + 提交后 Effects | 抽取先产候选，主作用域集中写，收到持久化回执后才消费 pending | 有 MemoryWriter/Router；socket 顺序执行不等于持久队列 |
| 稳定 Ticket 身份和恢复 | 保留 source/thread/ticket/assignment/event 标识，按稳定事件键去重 | 临时目录、会话 ID 不能充当长期事实身份 |
| 结构化 Attention 和恢复状态 | 人处理冲突、缺证据和失败；普通进度合并记录 | 复用提案、变更记录和现有页面，避免另造工作台 |

### 三步适配

1. **现在独立做**：显式 `projectScopeId → workspace/ticket` 映射、候选信封和回执；验证双进程/三 Worker 的重启、断连和幂等。现有 `dirname(cwd)` 继承仅是原型，git worktree 的父目录不一定是仓库。
2. **出现真实扩展点后接入**：创建/恢复 Executor 时传作用域和预算，复用主进程句柄或固定快照供读，候选经集中写者回流。[Source 扩展教程](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/docs/008-cookbook.md)可参考事件映射，但不等于记忆生命周期接口。
3. **可靠后优化**：批量提交、实体订阅、优先读取变更。不采用多个进程直接同时写同一 `.tdb`；保留四工具显式读取，不给每个 Worker 自动注入全库。

## 4. TDB 的能力与产品候选

源码和当前发布插件均精确 pin `triviumdb@0.9.1`。上游 0.9.1 于 2026-11-14 发布，核对基线 `46f767f8`。仅升级依赖不会自动启用下列新特性；在隔离库验证后再接入。0.9.1 写入/检查点可能升至主文件 v13、WAL v6，旧内核不能直接作为回退手段。

| 基础 | 可以开发/改进的功能 | 可能节省的成本 | 必须验证的边界 |
|---|---|---|---|
| 0.9.0：payload、图和 ID 限定向量 | 实体问答候选、关系路径、当前决定与历史解释 | 先缩小范围，少噪声和上下文 | 后端已存在；缺边会漏事实，范围完整不等于有答案 |
| 0.9.0：属性索引、参数化 TQL、payload 轻读 | 类型/期限/来源筛选，只取必要字段，用 EXPLAIN 核对访问路径 | 少扫描、少搬向量、少 JS 中间对象 | LIMIT 不等于输入有界，索引收益须测实际访问量 |
| 0.9.0：代际快照与单句柄读取 | 主写者供 Worker 做稳定只读检查、复现实验 | 避免复制对话和争用写锁 | 捕获有磁盘成本，落后时点须明确 |
| 0.9.1：文档根/片段、来源修订和原文范围 | “为什么记住”证据包、项目文档增量导入、只取命中附近原文 | 少做生成式摘要，直接引用局部证据 | PDF/Office 外部解析仍由宿主提供 |
| 0.9.1：分组 BM25、短语/邻近、来源条件、分量分数 | 范围内证据检索、同来源片段合并、去重复引用 | 减少通用词噪声和重复片段 token | GRAPH 只限定图算子；文本/文档/向量来源各自加条件 |
| 0.9.1：命名图与修订条件 | 项目共享事实 + 任务局部关系；共享节点、独立任务边、显式联合读 | 少复制事实和 ID 映射 | 逻辑图不是权限隔离；全局删节点影响所有图，单写锁仍在 |
| 图算法、DPP/PPR、压缩重排 | 有界预算下选择互补事实、依赖/影响分析、大库内存优化 | 去冗余、少读无关数据 | 先与简单规则对照；热度不代表重要，近似分数须校准 |

依据：[0.9.0](https://github.com/YoKONCy/TriviumDB/blob/v0.9.0/docs/changes/0.9.0.md)、[0.9.1 说明](https://github.com/YoKONCy/TriviumDB/blob/46f767f8c5befeb7da091267f2b19052f3cba8d9/docs/changes/0.9.1.md)、[文档模型](https://github.com/YoKONCy/TriviumDB/blob/46f767f8c5befeb7da091267f2b19052f3cba8d9/docs/documents.md)、[命名图](https://github.com/YoKONCy/TriviumDB/blob/46f767f8c5befeb7da091267f2b19052f3cba8d9/docs/named-graphs.md)。表中是从能力推导的产品候选，尚不是本插件的实测收益。

最值得先试：**任务相关记忆包 → 事实变更订阅 → 文档证据记忆**。文档依据首版已在合成库验证修订、删除和引用范围；后续评估自动导入和命名图，再考虑会话抽取接入。

## 5. 仍开放的问题

- 记忆回声：精确、可核对的自有工具回显已有守卫；改写、来源不明或存在独立证据时保守保留，因此仍可能出现语义重复。历史重复不自动合并；继续用真实场景评估来源归因与人工复核。
- F-EMB-03：原始 Ollama 模型包加载暂停，当前环境已删除 Ollama；不以重新安装为后续前提。此前证明的是同权重独立运行器。
- F-EMB-04：远程 embedding 与语义融合优化暂缓；无答案近邻及同实体文本噪声优先从词面与图范围处理。[归因](reviews/F-EMB-04-ATTRIBUTION-2026-11-12.md) · [后端结果](reviews/ENTITY-SEARCH-BACKEND-2026-11-12.md)
- F-READ-01 / F-LAT-01：完整大范围扫描可能超预算，单次同步 flush 仍有阻塞；批处理不代表内核尖峰已消失。[测量边界](reviews/LOCAL-EMBEDDING-READ-RESULTS-2026-11-12.md#剩余事项)
- 验证补口：真实宿主 extract-timeout/replay-timeout、R3 同质量净费用边级证据、REFERENCE 人工复判。B 站 E1-B 等外部扩展点，保持低优先级。

## 6. 投入边界

先做好小库、正确性和低成本路径；内核升级与排序、自动召回分开验收。保留四工具、人工替代确认、显式作用域。下一版在范围与验收明确后定版本；源码变更不代表 npm 已发布。
