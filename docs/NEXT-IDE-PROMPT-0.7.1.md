## 工作方式和边界

遵循 plan → develop → feedback → acceptance：先写范围与依赖，按切片实施并自验，最后交回实际改动和证据供 Codex/用户独立评审。IDE 自己的“已完成”不等于外部验收通过。

本次连续完成 **B1 → B2 → B3 → B4 → B5**。一个切片通过后直接开始下一个，不要求用户转发“继续”。只有真实阻塞或下面列出的范围变化才停。每个切片一个独立 conventional commit，包含代码、必要回归和结果；不 push，不改 npm dist-tag，不发 npm，不关闭 issue，不发送外部消息。0.8.0 只是范围代号，未经明确发布任务不要改包版本。

开始时在 `docs/next-memory/` 写一份 B 批执行计划，结束时写一份对应结果；沿用 `RESULT_TEMPLATE.md` 的证据结构，不再新增重复的 START/HANDOFF/CURRENT 入口。临时日志和截图放 `.tmp/b-<slice>/`；面向仓库的验收摘要必须能定位输入、命令、结果和局限，不把测试库、依赖或真实用户截图提交。

必须保持：

- 进程内 TriviumDB、四工具 `ctx_find/ctx_read/ctx_remember/ctx_link`，不新增模型工具或外部服务。
- `triviumdb@0.9.0-beta.3` 精确 pin；内核稳定版迁移单独立项，不和这轮 UI/召回改动捆绑。
- 默认开关沿用 0.7.1：抽取开启；自动召回、芯片、会话层、Git 旁路写出、远程 embedding 关闭。不把本地存储说成所有处理离线。
- 短地图每会话最多一次；芯片/更正/召回共用每用户轮累计 300 估算 token，标题包装计入；compaction 不免费重置同轮额度。更正顺序和关闭注入时的行为以最终 0.7.1 契约为准，不被旧 HTML 覆盖。
- URI 身份、线性版本链、32 跳、归档历史保留、当前头失效不复活旧版、ETag、operationId 和导入单事务等正确性保护不退化。
- 所有条目与操作绑定明确工作区；一个库一个读写进程；fork 不代表数据库隔离。
- 故障测试只用临时合成库，隔离 `DSH_HOME` 与 `DSH_TRIVIUM_SETTINGS`，不删除用户 `.dsh`，不读/打印 npm token、API key 或其它凭据。不递归删除含 junction 的测试消费目录。
- 页面展示/只读预览不触发模型或 embedding；新增真实模型质量试验、付费服务或真实用户数据采集需要单独明确授权。
- 界面支持 ≥900px、中英文、宿主浅深色及键盘；不顺带承诺手机可用。
- 前端沿用宿主 ModuleLoader、主题和组件；它不支持任意相对 `require()`。先确认打包/装载方式，再拆分源文件，不能为形式上的重构引入新框架或破坏宿主加载。

## B1：交互契约与新原型

先把 B 的具体问题、状态转换、现有组件/API 和拟改动映射写入执行计划。创建 `docs/next-memory/FRONTEND-0.8.0.html` 作为离线交互原型，保留旧 `FRONTEND.html` 的历史身份和链接。

新原型只覆盖本批：工作区与搜索优先、条目详情、明确保存反馈、导入预览、每轮实际投递/只读试算/维护状态。使用合成 fixture，所有模拟状态有显式标记。保留真实宿主侧栏与容器约束，不靠隐藏宿主导航制造宽度，不把场景工具条放进生产 UI。

验收：至少包含正常、空列表、加载、无来源、来源不可用、历史/过期、保存失败、ETag 冲突、导入预检拒绝、预览过期、事实已提交但派生维护失败、更正阻塞等状态；900px 和 1280/1440px、浅深色、Tab/Shift+Tab/Enter/Escape 有清楚行为。给出“原型控件→真实组件/API→验收断言”表。原型预算值来自明确 fixture，不另写一套算法冒充生产账本。

B1 是实施参考，不要求用户为每个常规样式选择再确认。若需要改默认开关、工具数量、数据格式或宿主顶层导航，停止并提出范围差异；不要擅自借原型扩大产品。

## B2：工作区、页面顺序与键盘

依赖 B1。把当前工作区、搜索与条目作为首要工作流，更新和低频维护移到次级区域；沿用宿主主题和组件。支持明确选择已知工作区，切换后旧请求、旧编辑草稿和旧节点缓存不能污染新库；未保存编辑要有明确处理，不静默丢弃。不要开放任意路径访问作为选择器捷径。

把摘要、有效期、自动召回等常用标签写成容易理解的文字，技术字段放详情。对齐按钮、tab 和嵌套弹窗的键盘语义，避免新增一套脱离宿主的外壳。

验收：A/B 工作区同号节点切换与并发响应；快速搜索与写后刷新；鼠标和键盘都能展开、编辑、取消和返回焦点；900px/常用桌面宽度、中英与浅深色均可读；原四工具和注入行为无变化。不要仅用源码字符串测试证明键盘可用。

## B3：统一操作回执

依赖 B2。统一设置与芯片的保存、归档、删除、合并和导入反馈。明确区分即时保存与需要提交的表单，显示进行中、已提交、拒绝、等待处理、失败重试；永久删除显示具体对象并确认。

回执由真实操作结果产生，至少能定位工作区、操作类型、对象及结果；不要把收到请求或排队成功写成“已保存”。事实提交成功但索引/JSONL 维护失败时，要说明事实已存在和恢复方式，不能让重试重复写入。优先复用现有响应和进程内有界记录，不在本批引入无限持久化审计日志或保存完整敏感正文。

验收：成功、服务端拒绝、网络失败、重复点击/重试、ETag 409、派生维护失败分别呈现正确状态；同类动作两处入口反馈一致；取消删除不发写请求；敏感字段不进入回执。需要新的业务幂等协议时先提出具体兼容方案，不能单靠禁用按钮掩盖重复请求风险。

## B4：导入只读预览

依赖 B3。为现有用户发起的 JSON 导入提供 dry-run：显示预计新增、更新、状态变化、关系与冲突；确认后才提交。复用实际导入的身份映射和整图预检，避免 UI 另算一套与提交不一致的规则。Git JSONL 后台同步仍遵守现有快照语义，不直接替换为未经约定的人机审批流程。

预览不能写节点/边、生成 URI、建索引、触发 embedding、写 sidecar/hash 或登记新工作区；提交必须重新验证当前数据库，识别预览后发生的变化。预览成功不是承诺未来提交必成功。

验收：预览前后逻辑快照、数据库与 sidecar 文件字节、设置均不变；URI 不同但正文相同、版本环/分叉、归档历史、缺失端点、事务失败、预览后另一窗口修改、重复提交均有行为断言；取消预览无写入；失败输入可保留、可恢复。不能只检测返回值含 dryRun 字段。

## B5：每轮投递记录与整批验收

依赖 B3；整批验收等待 B4。将现有召回检查组织为“这一轮实际发送”“试算一次查询”“维护检查”。复用真实 trace、账本、更正和按库健康状态，显示候选→筛选→实际提交的区别；送达记录只由成功投递产生，明确预算估算、会话/轮次、保留期及重启后的空状态。没有记录就说没有，不能把预览当历史或把检索命中称为模型已采用。

验收：同一用户轮多步骤、预算耗尽、更正待发/已发/关闭注入阻塞、自然到期、切库、重启后诊断重置等状态能正确解释；界面刷新不触发额外模型调用或上下文注入。保留手工历史 pin 与主动读取历史的语义。

整批跑完整 `npm test`、相关行为回归、独立 tarball+真实 peers 的干净消费验证，并做 Web/桌面实际交互。记录多窗口冲突、保存和导入失败、键盘焦点、中英主题与支持宽度。若用户选择手工操作 UI，提供逐步路径、合成输入和预期结果，由用户回填观察，不能擅自接管浏览器；手工和自动化结果都要记录实际方式。发现退化先修；无法访问某宿主时把该层明确标为未覆盖，不能用 mock 或原型截图替代。通过后做 B5 提交并输出合并后的回交报告。

## B 交付与后续 C–E

B1–B5 连续完成后，在最后回复列出：每片 commit、实际变更、测试命令与结果、原型和真机截图、未覆盖项、已知风险、回滚方式。明确区分“已实现／自验通过／待独立验收／未发布”。将结果交回 Codex/用户评审；不要仅凭自评直接跨到 D/E，也不要继续发布。

后续路线仍完整覆盖调研报告 B–E，按以下依赖准备下一批：

| 批次 | 开工条件 | 工作与证据 | 不应擅自做的事 |
|---|---|---|---|
| C 质量和负载基线 | B 独立验收通过；固定版本与数据协议 | 固定合成或已授权数据、查询和负例；1k/10k/50k 节点档；分别记录 Recall@k、误/有害注入、过时事实、跨库泄漏、估算 token、冷/热 p50/p95、RSS、启动/重开/导入耗时。输出种子、版本、原始 JSON、复现命令与失败样本 | 不混用模型/embedding/硬件/缓存；不以模型自评分充当人工金标；不把合成测试宣称真实使用质量；不调用未授权付费模型 |
| D 有证据改善召回 | C 有可复现基线、失败类型与事先声明的验收门槛 | 只选择一个最明确失败类；一次改一个通道或阈值；与同版本基线做对照，记录受益和变坏查询；检查没有质量/延迟/隔离退化 | 不默认开启 autoRecall；不凭感觉加向量/重排；不用测试集反复调参后再声称泛化；无稳定收益时保留负结果，不强推功能 |
| E 图特色延伸 | B/C/D 的适用结论已评审；具体交互范围确定 | 先展示已有决策链的记录时间、来源质量与失败→修复关系；只读时间线有需要时再做独立 HTML 原型。显式 as-of 查询或只读 adapter 先写有退出条件的 spike | 不自动推断期限，不裁定事实真假，不自动删边修链，不引入共享写库或数据格式迁移；新时间字段和跨宿主 adapter 单独确认范围 |

C 中的性能门槛先根据目标机器和测得基线制定并固定；不能凭空写成已达标。可确定的正确性硬门槛包括：新增跨工作区泄漏为 0、已知损坏链不得被投影为正常事实、同轮注入不突破既定预算。每个指标要说明测量层级，不把 API 耗时当端到端回答延迟。

## 停止条件

只有出现以下情况才停止并给出具体证据与可选方案：验收不通过且需改变产品契约；需要用户真实数据/付费或生产操作；宿主能力缺失而无法完成声明的验收；需要增加工具/默认自动行为/新服务/破坏性格式迁移；与当前工作树中的他人修改冲突；C 没有足够证据支持 D 的候选方案。

普通实现选择、可逆修复和本范围内的测试不需要每片再问一次。若阻塞只影响某个独立验证项，继续完成其他已授权且不依赖它的工作，再如实回交。不要把未知项写成已验证，也不要通过降低断言或删测试让结果变绿。
