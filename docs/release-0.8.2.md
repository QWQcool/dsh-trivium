# dsh-trivium 0.8.2

状态：**已发布到 npm**。`latest=0.8.2` 已确认（2026-10-30 15:32 +08:00 注册表直查 `dist-tags`，发布后约 3 分钟生效）。
本轮是**正确性补丁 + 一项新增能力**：修掉 4 个会静默丢事实/给出过期答案的缺陷，新增"经用户确认的偏好导出"与其消费端自校验。

数据格式、默认开关、四工具的契约、内核 pin（`triviumdb 0.9.0-beta.3`）**均未变**，可直接替换 0.8.1。

## 修复

### 1. 工具指令句不再是"整轮丢弃"

「按顺序调用工具，生产端口是 9443。」原先命中工具指令词后整轮被丢弃，事实直接消失
（`shouldExtractBatch → {call:false, reason:"empty"}`）。现在按**句**判定：只有去掉指令短语
和 `ctx_*` 工具名后只剩指令填充的句子才算纯操作，混合句整轮保留并走正常抽取。

### 2. 抽取返回空文本 = 失败，而不是"没有内容"

模型把 token 预算花在 reasoning 上时会返回空正文，旧实现把它当成 `{"candidates":[]}`，
于是消费窗口、清空 pending，事实静默丢失。现在空/纯空白回答标记为失败，`pending` 保留待重试；
显式空候选列表仍是成功。

### 3. 抽取调用改 `reasoningEffort: "off"`

同一原因的另一半：`maxTokens` 从 400 提到 900 后仍有 12/18 次被 `max_tokens` 截断。
抽取是 JSON 杂务，现在显式请求关闭推理（宿主目录不认该档位时**回退一次**去掉该选项，
不会因此让抽取不可用）。实测截断 12/18 → 0/18，抽取命中 5/9 → 9/9。

### 4. 凭据闸门补上"值"的形状

原规则只认 `api_key|secret|password|token|bearer|sk-` 这些英文词，中文「口令 verify-QA-71」
能直接入库。现在额外识别 GitHub/AWS/Google/npm/Slack 前缀、JWT、PEM 私钥，以及
"密码/口令/密钥/令牌 + 值"的中文写法；同时把英文词从"裸词"收紧为"词 + 值"，
修掉「token 预算 500」被误判为凭据的旧问题。拒绝原因会记录，且**不会把密文写进日志**
（`preview` 固定为 `<redacted>`）。

### 5. 改口时会退休被替代的决策

「先别动方案 A」与「更正：不再使用方案 A，改用方案 B」原先写成两个独立决策，
短地图把两条都列出来，模型有时答已被撤销的 A。现在新决策含显式替换词
（更正/改为/改用/不再使用/替换/取代/放弃/作废/replace/switch to）且点名了某个活的旧决策时，
建立 `supersedes` 链；短地图只列当前决策，历史仍可 `ctx_read` 到。真实复验 3/5 → 10/10。

### 6. 新会话先重放 pending，再建短地图

会话启动原先先建短地图、再 fire-and-forget 地重放遗留窗口；单轮进程可能在重放落地前退出，
下一个会话于是读到空库、注入 `decisions=0` 的地图并回答"记忆里没有记录"（15 次里 3 次）。
现在先 `await` 重放（上限 **8 秒**，超时继续启动、pending 保留）再建图。

### 7. 凭空写出的绝对日期不再入库

抽取会在事实里编日期（实测 `On 2026-04-06 …`，对话发生在 10-30）。现在候选里的绝对日期
必须在本次窗口原文里出现过，否则删除日期、保留事实并上报 `adjusted`；删空则整条拒写。
窗口含相对时间表达时按 `[now−7d, now+400d]` 放行正确换算（"下周五"→具体日期不再被误删）。

## 新增

### 偏好导出（可选，默认不启用）

`dsh-trivium-prefs` 提供 `init / export / revoke / status / verify`：

- 绑定 = 工作区 + 消费方 + 用途 + **逐条授权**（soft/hard），跨工作区/跨消费方一律拒绝；
- 快照跟随决策后继链，跳过 fork/归档/过期/脏数据；≤8 条且 ≤300 估算 token，
  超限**报错并给预览，不静默截断**；带 `digest = sha256(规范化事实)`；
- 原人设文件**一个字节不改**，另生成 `persona-with-prefs.md` 供消费方读取；
- 撤回是**清空偏好块**而不是停止刷新，之后 `export` 直接 `binding-revoked`；
- `verify` 只读校验：重算 digest、绑定状态/消费方、是否过期、块是否仍含每条已批准事实、
  消费方文件是否带块、库指纹是否变化（库被占用时该项跳过并在输出标注）。

## 已知问题

1. 关掉抽取推理后，模型不再自行隐去"像凭据"的内容，安全职责移到本地正则；规则有覆盖上限
   （既无前缀、又无"密码/口令"字样、也不是 JWT/PEM 的自造口令会漏）。
2. 会话启动最多多等一个抽取调用（8 秒上限）；一次性进程会因该请求未结束而延迟退出。
3. 日期闸门是字面比对：不认 `04/06/2026`、英文月份、中文数字日期；相对时间放行是区间近似。
4. 替代链判定是启发式（显式替换词 + 标签命中），多目标时串成链而非拒绝。
5. `skipped / adjusted / superseded` 目前只写进 `lastExtract` 与日志，UI 尚无入口；
   `verify` 是可选手动命令，消费端不会自动调用。
6. 依赖仍为 `triviumdb 0.9.0-beta.3`（与 0.8.1 相同），上游 0.9.0 稳定版未发布。
7. 未覆盖：自然增长触发的压缩、摘要质量单独判分、多模型、5/10/20 轮长会话。

## 升级建议

- 直接替换即可；四工具签名、`.tdb` 数据格式、默认开关均未变。
- 若你在用自定义 profile 或脚本调用 `distill`，返回值多了 `skipped / superseded / adjusted`
  三个字段（只增不改），`llmFailed` 的语义扩大到"空回答也算失败"。
