# dsh-trivium 0.9.4

**本地发布候选，尚未发布。** npm Registry 上的已发布基线仍为 `dsh-trivium@0.9.3`。 [English](release-0.9.4.en.md)

## 新增

- **任务记忆变更。** 在已打开的工作区明确选定一个当前实体后，可查看变化，或显式把当前视图保存为比较基线。以后查看会列出一跳范围内当前事实的净变化：新增、更新、被替代、归档、到期或离开范围。离开范围不表示删除，也不保证记录每次中间变更。可忘记已保存的基线，即使对应实体已无法打开。工作区本地的 `.dsh/trivium.task-checkpoints.json` 保存身份和版本哈希，不存事实原文。每个范围最多 128 项（含实体），每个工作区最多 32 条基线。超预算或预览失效会明确报错，不会被当作无变化。不会开启后台推送、embedding 请求或自动注入。 [使用和接口](read-api.md#任务记忆变更)
- **按选定来源查找原文。** 在「上下文 → 文档依据」显式选择 1–8 个已保存来源，只查所选来源的确切修订。返回原文及其 UTF-8 字节范围；不同路径的同名文件不会混为一项。来源修订变化后需刷新列表再查，不会悄悄换到新修订。默认最多返回 8 条片段，预算为 600 估算 token。不宣称片段足以回答问题，不调用模型或 embedding。 [使用和接口](read-api.md#在选定文档来源内查找原文)

## 改进

- **重复引用合并展示。** 只有来源、文档、修订、字节范围和引用原文都相同，已加载结果才归为同一展示组。每条事实关联仍保留自己的 ID 和复核状态，不删除已保存的引用，原关联仍可查询。

## 修复

- **孤立实体查询。** TDB 0.9.3 的行预算是 1,000；旧逻辑为探测是否超限而请求 `LIMIT 1001`，不论库大小都会被拒。新逻辑只在预算内读取。**正好匹配 1,000 条实体也会拒绝**，与超过 1,000 条一样：取满不能证明没有下一行。查询会明确失败，不会静默返回不完整的扫描结果。
- **`limit = 1000` 的实时 TQL。** 最大页不再请求超出内核预算的探测行。**恰好返回 1,000 行也可能保守报 `truncated: true`**，因为无法多取一行区分完整页和被截断的一页。如果为满足响应字节预算而缩小行数重试，被截断的响应会标明 `truncationReason: "response-byte-budget"`，不会把重试结果误标为完整。

## 删除与移除

无。

## 升级、兼容与数据

候选包仍固定 `triviumdb@0.9.3`，不更改 TDB 数据格式、默认开关、`DIM` 或四工具契约。已随插件 0.9.3 完成内核升级的库，无需再执行 `prepare` 或 `migrate`。尚未升级到 TDB 0.9.3 的旧库仍按[原升级与回退指南](kernel-upgrade.md)处理。Node 要求仍为 `^22.19.0 || >=24`。

保存或忘记任务基线只写入新增的工作区侧车文件。希望重装兼容版本后仍能使用基线，请保留这份文件；它不属于 TDB 事实库，也不是事实库快照。来源检索和引用分组不会改写保存的来源、事实或引用关联。既有接口保留，新增的来源检索和检查点操作均由用户显式执行。
