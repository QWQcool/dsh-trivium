# dsh-trivium 0.9.4

**读取路径的正确性补丁。** 0.9.3 换上新内核后，凡是"多取一行判断是否截断"的写法都会被内核整条拒绝，两处读接口因此**完全不可用**；这一版只修这两处。 [English](release-0.9.4.en.md)

内核不变：仍是 `triviumdb@0.9.3`。数据格式不变，无需迁移。已验证宿主：`@deepseek-ai/dsh@0.2.2-rc.1`。

## 修复

### 孤立实体查询在 0.9.3 上全部失败

`lib/read-query.js` 的 `orphanEntities` 为了判断是否超过上限，向内核发的是 `LIMIT 1001`（上限 1000 再多取一行）。内核 `0.9.3` 起强制 **`OFFSET + LIMIT ≤ 1000`**，超出会把**整条请求**判为 `TDB_QUERY_BUDGET`——与库大小无关，6 个节点的库同样失败。

现在只取预算内的行，并把"取满一页"视为到达上限直接拒绝。宁可拒绝，也不返回一个不完整的孤立实体扫描。

**行为变化**：正好 1000 个实体的库会被拒绝（旧实现是"超过 1000 才拒绝"）。这是没有探测行时的保守取舍，已在代码注释里写明。

### `ctx_find` 式实时 TQL 在 `limit = 1000` 时失败

`lib/live-tql.js` 同样用 `LIMIT limit + 1` 探测截断，而 `1000` 是文档里的最大 `limit`，所以取最大值时**必然**失败。

现在探测行数封顶到预算上限；当无法多取一行时，把"响应取满"保守地报为 `truncated: true`，不再假装结果完整。该保守判定**仅在 `limit ≥ 1000` 时启用**，常规 limit 的截断语义未变。

## 升级与兼容

直接替换插件即可：内核、数据格式、默认开关、四工具契约与 `DIM` 均未变，无需 `prepare` 或 `migrate`。

## 验收范围

- `node scripts/run-all.mjs`：**108/108**（修前 106/108，失败项即上述两处）。
- 其中一条断言按新内核契约重写：原先"发 `MATCH … LIMIT 2000`，客户端截断到 1000 行"在新内核下不可能发生（内核先拒绝该查询）。现在它验证两件事——客户端显示上限仍然生效，以及越界 `LIMIT` 必须以 `422 TDB_QUERY_BUDGET` 被拒。
- 本版未重跑真实模型或真实宿主质量评测；上面两处是纯读取路径修复，不改变写入、抽取或注入行为。

## 已知限制

- 孤立实体扫描在"实体数达到 1000"时只能拒绝，无法区分"正好 1000"与"多于 1000"。
- `limit = 1000` 的实时 TQL 在响应恰好填满时会报 `truncated: true`，属保守假阳性。
