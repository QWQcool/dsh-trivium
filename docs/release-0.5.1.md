## 本次变更

0.5.1 只修正确性，不加新功能。

**同轮预算真的记账**

- 规划器按实际渲染文本的前缀边际成本给每条记录写 `tokens`，求和恒等于计划总量（标题与包装计入）。
- 账本按 `totalTokens` 预约，`commit()` 幂等；显式 0 预算保持 0，不再回落成 300；compaction 不再给同一用户轮免费重置额度。
- pre-step 在异步检索结束后重读账本，两个在途步骤不会共同花掉同一份额度。

**当前版本投影**

- `makeRevisionResolver()` 返回当前节点自己的 `type / 正文 / until / stale / archived / dirty`，自动召回、只读预览、`ctx_find` 三处共用。
- 命中被替代的旧版本时，输出新 id + 新正文；旧 id 只作为 `matched_history` 指针。人工 pin 与 `ctx_read(oldId)` 仍按原语义读旧正文。

**导入身份与原子性**

- 有 URI 的节点只按 URI 识别；不同 URI 的两个版本即使正文相同或包含，也不会被合并。
- 先规划身份、预分配 id、校验映射后与现库组合的完整图（自环/循环/分叉/类型/端点/32 跳），再用**一次** `commitTransaction` 提交节点、正文更新、业务边与 `supersedes` 边。
- 事务失败返回 `ok:false`，不留节点、不留正文覆盖、不留边。
- JSONL 旁路同样移除正文回退，只按 URI 识别；版本链上缺 URI 的节点明确拒绝。

**更正通知**

- 账本记录每个会话实际看到的 `id + 正文 + 状态指纹`；更新、归档、删除、合并、替代、撤销、导入都会给看过旧事实的会话排队一条短更正。
- 更正有独立消息块，不重发旧正文，与芯片/召回共用 300；只有随 reservation 送达后才消费，超预算留到下一轮。
- 更正按工作区隔离，不同库的同号节点不会串扰。

**只读体检**

- 新增 `node scripts/check-integrity.mjs <workspace> [--json]`，用内核 `accessMode: "readOnly"` 打开，报告自环、循环、分叉、重复 URI、悬空端点与不可解析的当前版本；只报告，不修复。

**内核**

- `triviumdb` 固定为 `0.9.0-beta.3`。升级前后 21 组离线脚本均通过；新增的 p21 另有 89 条断言。

## 升级与旧数据

- `npm install dsh-trivium@0.5.1`，或在 DSH 桌面端「插件」里升级。
- 0.5.0 用户可直接升到 0.5.1；v2 数据格式不变，不需要迁移。
- **0.4.21 误写到 `until` 的正文日期不会自动清除**：升级后请在设置「显示过期决策」里把误写的期限清空，或用 `ctx_remember` 传 `until: ""` 覆盖。正文本身不需要改。

## 已知限制

- **仅支持 900px 及以上宽度。** 390px 无横向滚动，但宿主侧栏固定 188px，插件内容列约 154px，不可读；手机宽度不在本版支持范围。
- 同一工作区的 `.tdb` 仍只允许一个读写进程；第二个宿主会得到 `409 DB_LOCKED` 的可读说明，而不是并发写入。
- 真实双窗口并发尚未覆盖：409 由客户端注入过期 ETag 制造。
- 更正没有独立的界面条目，模型侧生效、状态页可看到 `channel:"correction"`。
- 性能与负载测试不在本轮范围。
