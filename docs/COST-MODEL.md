# 成本口径

更新：2026-11-16。目标是同质量下减少实际开销。旧的"省 80%"结论已撤回；当前开发顺序见 [ROADMAP](ROADMAP.md)。

## 1. 每轮分别记什么

- 生成模型调用、正文 embedding、query embedding 分开计数，包含失败、重试和工具循环。
- 记录请求模型、实际返回模型、prompt/completion/cache token、延迟、价格来源与生效日期。缺少用量不能记成零费用。
- prompt 中的估算 token 用于上下文预算，不当作实际计费 token；候选检索命中不当作回答质量。
- 本地推理可无 API 账单，但仍报告 GPU/CPU 时间、吞吐、磁盘和缓存空间。增加一个筛选模型的成本也算进去。

## 2. 实际账单与归一比较

2026-10-29 的历史约定是同时保留峰价上界与谷价归一值，对外比较使用谷价。这个约定继续用于重算那些冻结实验，归一值不是实际账单。

新实验先固定提供商、模型版本、价格快照与费用预算，原始账单和同价归一结果并列。不能按请求发生时间猜价格，也不能把未知费用或未完成请求删掉。真实价格在开跑时核对[官方价格页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)，不把旧表当成今天报价。


输出按臂记录 calls、promptTokens、cachedTokens、completionTokens、cnyPeak、cnyOffpeak 和 grandTotal；不联网，不覆盖原始证据。

## 4. 低成本改进的放行条件

先用相同语料、预算和模型比较：事实入库不漏、错误注入不增、最终回答不退步，再判断减少了多少请求、实际 token 和费用。分开报告冷启动/缓存命中、词面/向量路径及 p50/p95。失败样本、预算拒绝和缓存失效必须在报告中。

## 5. 零模型调用的记忆基线（2026-11-16）

为了在改动前先有可重复的对照，新增一条**不调用模型、不请求 embedding**的离线路径：

```sh
node scripts/memory-eval.mjs --out .tmp/new-memory-eval.json --reps 3
node scripts/smoke-p102.mjs   # 评分器与夹具自测
```

- 输入：`scripts/fixtures/memory-eval-v1.json`（26 个合成场景，18 开发 + 8 留出，6 类；事实、来源、范围与期望 id 在首跑前冻结）。
- 写入：真实 `extract.distill()`，但 `llmCall` 是返回冻结候选的替身——量的是**写入守卫与去重**，不是模型抽取能力。
- 读取：真实 `searchEntity` 词面通道（`semantic` 未请求），与面板/HTTP 共用后端。
- 结果（详见[基线报告](reviews/MEMORY-EVAL-BASELINE-2026-11-16.md)）：写入正确 9/9、漏记 0、重复 0、回显漏写 0/3；无来源新增 1/1；检索 Top-1 5/12、Top-5 10/12、排除锚点后 Top-1 9/12；无答案 5 个场景共返回 3 个候选（只列不判）；禁止 id 命中 0。
- 成本：真实模型调用 0、embedding 调用 0；token 与账单**未测**，不用字符数代替。耗时 p50 43.4 ms / p95 345.9 ms（n=78，3 轮 × 26 场景），不设通过线。
- 重复性：同版本同输入两次全量运行，判定与计数一致，仅耗时字段不同。

这条基线只覆盖"写入准确性 / 检索范围与相关性 / 候选成本"，不覆盖最终回答质量（未生成回答）。历史 2026-10-29 冻结实验继续按原口径重算，不被本基线覆盖。

2026-11-17 的[后续对照](reviews/MEMORY-EVAL-2026-11-17.md)保持同一冻结语料，补齐评测器防误计分与证据保留，并验证无来源候选的 pending 和显式任务记忆包。新增的 `estimatedTokens` 只计算记忆包 `context`，使用项目现有估算器；完整 JSON、真实模型输入输出及费用仍未测，不把“预算未超”当作真实账单下降。来源待核对、正文不符、预算违规和无答案候选各自计数。

后续同日的[真实账号对照](reviews/MEMORY-QUALITY-2026-11-17.md)已独立测量实际 usage：有效 36 次请求，输入（含缓存）10365、输出 1050；包含作废首轮和两次连通验证共 74 次、21335 token。旧通道回答 12/12、任务记忆包 10/12；不能宣称后者降本提质。金额账单仍未测。补充依据与人工确认均不需要额外模型或 embedding 请求。
