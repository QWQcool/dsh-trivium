# F-W04 / F-W05 收尾结果

日期：2026-10-30。基线为 `d5f0840`。本轮没有变更版本号、发布 npm 或调用付费模型；模型费用 **¥0**。当前代码与已发布的 0.8.2 不同，以下结果属于源码验证。

## 修改

- F-W04：变更记录读取失败或损坏时，HTTP 返回失败而不是伪装为空；修复多次裁剪的累计数量。记录按抽取窗口生成不含明文的事件标识，同一窗口重放去重，后续窗口仍可见；疑似敏感预览和详情写盘前过滤。
- F-W04：独立审计锁保护追加与裁剪。锁竞争时不等待，观察到的失败会留下工作区级缺口标记；即使另一进程或重启后也可显示记录可能不完整。UI 区分加载、空、错误及恢复状态；切换工作区时丢弃旧请求。
- F-W04：修复抽取成功后审计引用越出作用域导致误报失败、保留 pending 的问题。pending 恢复展示进行中、等待超时但后台仍运行、成功或失败；超时后保留恢复认领，后台结束后才允许后续重试。
- F-W05：`ctx_remember`、`ctx_link` 和三个导入 HTTP 入口在打开数据库前参与工作区写锁；忙时返回可重试结果。活进程持锁超过 TTL 不再被误回收，死亡进程遗留的锁及恢复锁可回收。
- F-W05：将旧版单会话 pending 兼容迁移为多窗口队列，保存和消费按工作区串行；恢复旧窗口保留原会话来源，新会话写入不覆盖旧窗口。启动时依次恢复队列，损坏文件保留并报告；可识别的旧快照有界去重，本地保存失败有限次数重试。

## 遗留边界

- 恢复状态和 pending 写入失败提示仅在当前进程内，重启后未知，不代表恢复已成功。已观察到的审计写失败会尝试留下持久缺口标记，后续成功不会自动清除；不承诺自动补写丢失记录。若事实提交后、审计调用前进程被强杀，或文件系统连标记也无法写入，跨重启无法保证发现缺口；事实与审计不是跨文件原子事务。
- 重放去重以完整抽取窗口为身份，消息组合变化时不视为同一窗口。过滤规则不能保证识别任意无上下文的敏感值。
- 工作区锁是操作级锁，数据库原生句柄可能被宿主缓存；另一个进程需等持有宿主关闭后重试。陈旧文件锁检查与删除不是原子条件操作，极端恢复竞争仍依靠 TriviumDB 原生排他锁兜底。
- pending 确认表保留最近 4096 个身份；更早的跨进程迟到快照可能重新出现。旧记录若没有定位符和本地身份，无法完整区分完全相同的旧事件与重放。持久化失败最多做有限次后台重试，权限故障或进程提前结束仍可能使尚在内存里的内容无法落盘，界面会提示。
- 同一待处理窗口中，只对连续、具有可靠宿主序号的事件稳定排序；无可靠序号的事件不会被猜测顺序。较早事件若在较晚事件已消费后才抵达，无法追溯重排。
- 多窗口格式保留了旧版文件的顶层读取形状，但旧版程序写回时不理解其他窗口；不要让旧版与新版同时操作同一个工作区，降级前备份 pending 文件。
- F-W04 的真实 DSH 宿主视觉、完整键盘和主题验收仍未完成；没有真实模型质量或正式 npm 包消费验收。F-W01 的 `ensureLink` 故障注入以及 F-W02 的更多日期表达也不属于本轮修复范围。

## 测试环境偏差

首次宿主 UI 尝试虽隔离了插件 home，宿主仍打开了用户默认工作区并创建或更新数据文件和日志；没有启动前快照，无法确认已有文件的内容是否变化，已停止宿主且未删除现场。早期一次导入测试因空选择列表触发对用户级配置文件的读取尝试，未保存逐文件读取回执；可能写入的仅为已删除的临时测试库，没有模型调用或外网发送。最终导入测试将用户目录与发现过程限制在测试根内，并显式选择合成文件。
