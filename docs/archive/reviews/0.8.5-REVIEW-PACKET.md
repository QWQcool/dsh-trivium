## 一、这次发布改变了什么行为（用户能感知）

### 1. 抽取前的事件快筛

`screenTurns` 给每个事件打 0/1/2 分，**整窗 0 分时消费窗口、不发起抽取调用**；
2 分排到批首；某 0 分事件所在轮次若有工具调用，**升到 1 分**（不当作填充句丢弃）。
0 分白名单刻意窄：寒暄、纯命令、单个路径、单个 URL；带引号/管道/中文一律 ≥1。

- 收益：夹具上抽取调用 30 → 10（−66.7%）；真机确认过一次「ok」整窗丢弃、**没有发生抽取调用**。
- 风险：**误判 0 = 静默丢事实**，且没有事后回收机制。真机样本只有 2 次。

### 2. 短地图热度

被 `ctx_find` / `ctx_read` 命中过的事实获得热度，优先占据短地图槽位（旧版按插入顺序，最旧的事实永远进不去）。
热度写在 `.dsh/trivium-usage.json` 旁路文件，60 秒节流。

- 风险：热度自我强化（已排除面板浏览与自动召回，但"读得多"本身是偏差）；跨进程后写覆盖。

### 3. 增量地图注入

地图带版本：**没变化 → 0 token**；有变化 → 摘要 + ≤6 行差异；每 6 轮强制全量。

- 真机：启动 `full/session-start` 123 token → `skip/unchanged` 0 token → `diff`。
- **本轮修复的真实缺陷**：`turnsSince` 曾在一轮对话里走 0 → 4（`turnKeyOf` 的 `obj:<n>` 回退依赖对象身份，
  宿主每步重新序列化历史 → 键变了）。后果不只是全量更频繁，**每轮 300 token 的投递预算也在每步被重置**。
  已改为 `mapTurnKeyOf`（host id → 否则「用户消息条数 + 最后一条用户文本 hash」），真机复验 `turnsSince=1`。

### 4. 卡住与待补写可见

`stuck` / `recovered` 成对记录（跨会话配对靠变更记录 seed）；面板「运行记录」页新增诊断卡，
未观测值显示「没有记录」而不是 0。抢锁失败/失败的窗口有「待补写」卡片 + `GET /api/dsh-trivium/pending`。

- 真机：种一个死进程+10 分钟前的锁 → `stuck{kind:"lock-stale", age=634s}` → 抽取后 `recovered{afterMs:35154}`。

### 5. 事实身份去重（**评审重点**）

旧规则只有"正文互相包含"。现在 `lib/identity.js` 提供四个本地信号：

| 信号 | 规则 |
|---|---|
| 类型 | 必须相同；`entity` 仍走名字规则 |
| 否定 | 一方含否定词而另一方不含 → 不合并 |
| **数值** | 数字集合（阿拉伯数字 / CJK 数词 / 周X）不一致 → **不合并** |
| 相似度 | 字符二元组 Jaccard；名字同族 ≥ **0.5**，否则 ≥ 0.8 |

实测：「发布窗口固定在每周四晚上」↔「每周四晚上是发布窗口」= 0.538–0.571 → 合并；
「周四」↔「周五」= 0.600 但 **数值冲突 → 不合并**；无关句 0.00–0.16。

- 为什么必须有数值守卫：第一次接入时把三条只差一个数字的事实并成一条（相似度 0.9+），
  那正是"修订版"的形态；**静默合并等于静默改历史**。
- 风险：没有语义理解，同义不同词仍存两条；否定守卫会挡住互补句（「用 npm，不用 pnpm」含「不」）。

### 6. 批量写入

`runDeferredWrites` + `flushWorkspaceDb`：多个变更共用一次 `db.flush()`。
外部导入 22 条从 **2020 ms / 47 次 flush** 降到 **110 ms / 2 次**。Router 每事件循环 tick 一批、flush 后才回包。

## 二、基础设施改动（不改变用户语义，但影响面大）

| 改动 | 说明 | 风险 |
|---|---|---|
| 内核升级 `0.9.0` | 类型化存储**拒绝 `undefined`**（beta.3 静默丢弃） | 已用 `hardenEngine` 在引擎边界统一 prune，写面取自 `triviumdb.d.ts`：`insert / insertWithId / updatePayload / updateEdge / commitTransaction` |
| 性能变化 | 单条 insert 188 → **155.5 ms**，flush 91 → **73.7 ms**；但**批量路径更慢**：Router 队列 p95 206 → **483 ms**、吞吐 1462 → **559 /s** | 500 条仍 0 丢写；若调大批窗口需重测 |
| peer 自愈 | `npm install` 会删掉 `@deepseek-ai/dsh-llm`、`dsh-tools`（registry 只有 0.0.1-rc.1），`scripts/link-peers.mjs` 在 `run-all` 启动时重建 junction | 依赖宿主 profile 里的副本；CI 上若 registry 有合规版本则不需要 |
| 测试清理 | 删除 3 个零引用脚本；`scripts/` 从 121 → 119 | 无 |

## 三、随包但默认关闭（无调用方）

`scope` 参数（`workspace` / `parent` / `inherit`）、`lib/inherit.js` 只读继承、
`lib/router.js` 单点写、开关 `scopeInheritance`（缺键=关）。
关掉时 `readInheritedMap` 返回 `disabled`、`startRouter` 抛 `SCOPE_DISABLED`，**都在开句柄之前**。

评审问题：**这些代码该不该出现在一个"面向用户"的版本里**？支持的理由是自洽与可测；反对的理由是没人用的代码就是负债。

## 五、我自己认为最可能出事的三处

1. **快筛误判 0**：代价是静默丢一条事实，而且没有任何回收或告警。样本只有 2 次真机。
2. **事实身份误合并**：阈值 0.5 是按一组手写样本定的，没有语料校准；一旦误合并，旧事实被覆盖且不可逆（除版本链）。
3. **0.9.0 批量路径变慢**：如果真实用户主要走导入，这次升级可能让"批处理带来的 18×"缩水。
