# FRONTEND.html 与当前前端的对照

日期：2026-10-28。对象：[历史原型](next-memory/FRONTEND.html) 与 `lib/client.js` 的实际设置面板。本文是源码和交互结构对照；0.7.1 已发布，最终验证见 [0.7.1 验收](verification-0.7.1.md)，此前桌面有限走查见 [UI 审计](ui-design-audit-2026-10-28.md)。离线原型不是真机证据。

结论：**功能分区大体对应，实际布局没有逐项照搬；这份 HTML 已不足以作为下一批实现的完整规格。** 它仍适合解释最初的“来源／历史／召回检查”设计，但其版本、预算演示和宿主宽度假设已经过时。

## 对照结果

| 区域 | HTML 原型 | 当前实现 | 判断 |
|---|---|---|---|
| 页面入口 | 模拟 DSH Settings 左侧导航，不增加产品顶层导航 | 注册宿主 `settings.section`，同一插件设置入口 | 匹配；HTML 自绘宿主外框不能拿来约束宿主 |
| 主分区 | 记忆条目／召回检查 | 同名两个主页签 | 匹配 |
| 详情分区 | 内容／来源／决策历史 | 同名三个详情页签，来源与历史按需读取 API | 匹配，但真实数据、错误和加载状态来自 API |
| 列表与详情布局 | 左侧可选中列表，右侧独立 inspector；详情有复制正文按钮 | 卡片列表，条目内联展开；编辑、归档、删除、合并等实际管理动作较多 | 视觉和操作结构不同；不能声称已按原型完整实现 |
| 页面优先级 | 工作区标题、配置入口后直接进入记忆列表 | 保存/导入导出工具栏、库信息、检查更新、配置折叠在列表前 | 当前首屏低频管理信息较多；B 批应让搜索和条目优先 |
| 历史与过期 | 两个独立筛选；旧版本可跳到当前版本 | 两个独立筛选；有当前版本指引 | 核心语义匹配 |
| 来源 | 合成会话标题、消息编号、摘录；可展开/复制样例片段 | 展示实际已保存字段；缺失与不可用分开；没有宿主定位能力时明确不提供跳转 | 原型的样例丰富度不是可承诺的真实来源；禁止补造字段或链接 |
| 版本历史 | 视觉时间线，可展开较早记录，点回某条 | API 历史列表；读取 `limit=20`，当前界面尚未使用 `nextCursor` 做翻页 | 表达和长链覆盖不完全匹配；未来时间线应读真实完整关系 |
| 替代确认 | 两条已有决策比较、说明、模拟 409 后保留选择 | 真实 ETag / operationId / 409；保留选择并重读 | 意图匹配；模拟勾选框不是并发测试 |
| 撤销 | 只对 `state.lastOperation` 演示撤销，使用原生 dialog | 服务端检查当前链并撤销相应关系 | 实际语义更完整，不能复制原型的最近一次操作假设 |
| 召回检查 | 左侧候选原因、右侧文本与预算；固定 6 条样例 | 真实预览、trace、入选/淘汰、文本、更正与体检 | 原型更直观，但数据覆盖落后；需要区分“试算”和“已经送达” |
| 更正和版本链体检 | 未体现 pending/sent、阻塞原因或 integrity | 0.7.0 起已有界面；0.7.1 继续收尾更正与诊断 | 原型缺失，下一版必须纳入 |
| 预算与 compaction | 自写 `estimate()`、固定候选、首条预算裁剪；`compact` 文案称“重置本轮投递账本” | 实际规划器/账本累计记账；同一用户轮 compaction 不重获 300 额度 | **语义过时，禁止以该演示算法反改生产逻辑** |
| 历史长度 | `historyContent` 至多收集 32 个节点 | 合法上限为 32 条边、33 个节点，服务端有分页 | 原型边界不准确 |
| 主题与窄屏 | 独立 light/dark token；940px 以下隐藏模拟宿主侧栏，680px 以下上下排 | 使用宿主主题与真实设置容器；宿主侧栏不会因插件 CSS 自动消失；当前支持 ≥900px | 原型不能证明真实窄屏或深色可用 |
| 键盘 | 原生 dialog、方向键/Home/End 切 tab、显式焦点恢复 | 宿主按钮/自定义页签和弹窗；0.7.1 收尾实际键盘与焦点 | 设计意图可借鉴，必须由真实宿主验证；DOM 实现不是可直接移植的等价物 |
| 演示工具条 | 场景切换、设计标注、暗色预览、虚构错误 | 不进入运行 bundle | 正确隔离，应一直保留这个区别 |
| 版本标识 | 页脚仍写 `0.4.22 / TriviumDB 0.8.11 · 未实施的新功能` | 0.7.1 收尾基于现行代码与精确 beta 内核 | 必须加历史身份；不能让下一任将其当最新版本约束 |

检查时还发现真实 `historySection` 曾在多条历史前无条件显示“没有版本历史，这条就是当前版本”。0.7.1 已修复并加入 p24 行为回归；不把它算成原型匹配问题。

## 后续是否再做一份 HTML

**B 批建议做一份新的、带版本范围的 HTML 交互原型；C 和 D 不需要另画管理界面，E 有新的时间线交互时再补原型。**

建议路径为 `docs/next-memory/FRONTEND-0.8.0.html`。这是下一批 B1 的交付，本轮对照没有生成这个文件。原 `FRONTEND.html` 保留为历史设计，迁移过时链接并明确历史身份，不用覆盖它来伪造当时已经考虑过的新功能。

新原型的作用是固定信息顺序、状态和操作，不是增加第二套业务实现。无需再画整个记忆工作台；只需要：

1. 工作区明确、搜索和条目优先；更新与低频配置进入次级位置。
2. 一个完整条目流程：查看／编辑／保存成功与失败／归档／永久删除确认。
3. 写入回执区分已提交、被拒绝、等待处理、事实已提交但派生维护失败；不能只用统一绿色“成功”。
4. 导入先预览新增/更新/归档/冲突，再确认提交；预览过期和提交失败有单独状态。
5. “实际送达记录”“只读试算”“维护检查”分清，补更正待发、阻塞、已发和体检状态。
6. 真实宿主宽度约束下的 900px、1280/1440px、浅深色与完整键盘路径；保留宿主侧栏尺寸，不靠隐藏它获得空间。

示例状态要标“演示”，可以用固定 fixture 展示服务端契约，不能用独立假算法证明预算、事务或召回正确。B1 应同时给出原型控件→实际组件→API→验收断言映射；完成实施后用同一组场景在真实宿主走查。

## 与后续计划的关系

[调研报告](memory-plugin-landscape-2026-10-28.md) 的 A–E 是综合本项目源码/测试/UI 审查与 11 个同类项目的一手资料形成的路线，不是直接抄某一个插件，也不是横向 benchmark 的排名结论。A 为可靠性；A 后还有 **B、C、D、E 四批**。

B 的“操作体验”包含前端改进，但不止换布局：还要把操作结果、工作区、只读预览与真实提交、实际投递与试算区分清楚，因此需要少量 API 和状态契约配合。C 建立评价依据，D 按 C 的失败样本选择一个改动，E 延伸决策图特色。可交给其它 IDE 的执行提示词见 [后续开工提示词](NEXT-IDE-PROMPT-0.7.1.md)。
