# dsh-trivium 0.6.0 发布说明

状态：**已发布**。npm `dsh-trivium@0.6.0` 于 2026-10-28T05:14:18Z 发布，`latest` 指向 0.6.0。
产物 shasum `ad979e5bf53b77d63273dd5d3c8668d9f397474d`，37 个文件，与本地 `npm pack` 一致。

0.6.0 是维护版本：把两个维护工具真正随包分发，并固化两项验收。核心记忆逻辑与 0.5.1 相同，数据格式不变。

## 本次变更

**随包分发的两个命令**

- `dsh-trivium-check <workspace>`：只读打开图，报告 `supersedes` 自环、循环、分叉、重复 URI、悬空端点与无法解析的链。退出码 0 干净、2 有问题、1 打不开。
- `dsh-trivium-clear-until <workspace>`：默认只列出仍带期限的过期决策；`--apply` 只清「期限文本同时出现在正文里」的那些（0.4.21 从正文抓日期的形态）；`--apply --all` 清所有过期期限，包括用户显式填的。先关宿主，内核是单写者。

0.5.1 的发布说明让用户运行 `scripts/check-integrity.mjs`，但该脚本当时不在 npm 包里；0.6.0 修正了这个承诺，并把清理工具一并交给用户。

**验收固化（无行为变更）**

- 轮标识：真实宿主会话日志里的用户消息带稳定 `id`（`user/message` 与 `agent/inbox/spliced` 同一 id），`turnKeyOf` 走 `uid:` 而不是对象身份回退。多步工具循环不会因为消息对象被重建而重新发放预算。
- 真实双窗口：两个真实标签页读取同一 ETag，窗口 A 修改正文，窗口 B 提交得到 `409 code:"etag"`，刷新 ETag 后重试成功。

## 升级

- `npm install dsh-trivium@0.6.0`，或在 DSH 桌面端「插件」页升级。
- 0.5.1 用户可直接升级；没有数据迁移，v2 格式不变。
- 只需要清理 0.4.21 误写期限的用户，可以在升级后运行 `npx dsh-trivium-clear-until <workspace>` 先看列表，再加 `--apply`。

## 已知限制

- 仅支持 900px 及以上宽度（390px 受宿主侧栏限制不可读）。
- 同一工作区的 `.tdb` 只允许一个读写进程；第二个宿主得到 `409 DB_LOCKED` 的说明。
- 清理工具只按「期限是否出现在正文」做启发式；显式期限默认不动，需要 `--all` 才会清。
- 多进程并发写、手机宽度、性能测试仍不在本版范围。
