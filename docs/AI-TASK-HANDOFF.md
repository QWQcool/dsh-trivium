# 两项任务交接：桌面实体面板与记忆评测基线

这份文件用于把两项工作分别交给其他 AI 模型执行。执行某一项时，同时遵守“共同要求”和对应任务；两项都做时可按 A、B 顺序执行。项目后续优先级仍以 [ROADMAP](ROADMAP.md) 为准，现状见 [CURRENT-STATE](CURRENT-STATE.md)。

## 直接复制给模型

执行任务 A：

```text
请在当前项目执行 docs/AI-TASK-HANDOFF.md 中的“共同要求”和“任务 A：实体范围检索面板验收”。从检查当前状态开始，完成验证、范围内必要修复、回归和结果记录；不要中途就常规选择或步骤询问我。仅在确实无法继续且必须由我处理时集中说明阻塞。完成后报告实际结果和未完成项。
```

执行任务 B：

```text
请在当前项目执行 docs/AI-TASK-HANDOFF.md 中的“共同要求”和“任务 B：可重复的记忆评测基线”。从检查现有评测开始，完成合成语料、离线评测、评分器自测、基线结果和相关文档；不要中途就常规选择或步骤询问我。仅在确实无法继续且必须由我处理时集中说明阻塞。完成后报告实际结果和未完成项。
```

两个模型并行时，先让它们读取当前工作区中的本文件；新建的工作目录不会自动包含尚未提交的文件。也可以把对应任务和共同要求的正文直接发给模型。

## 共同要求

### 自主执行

- 用户希望任务一次完成。自行检查环境、阅读代码、制定细节、运行测试、创建合成数据、修复本任务范围内的问题并更新相关文档；常规实现选择、可逆修改和测试步骤不需要逐项询问。
- 遇到失败先自行定位、修复或选择安全替代方案，并继续能独立完成的工作。仅在系统权限或登录确实无法自行完成、继续会中断无法确认的用户工作等实质阻塞时，集中说明一次最小的必要问题；不要把等待确认当成默认流程。
- 如果某项实机步骤确实无法完成，先完成离线验证和其他独立工作，最终明确标为“未完成”，说明阻塞、已经尝试的方法和剩余验收步骤；不要把模拟结果写成实机通过。
- 用户已授权为桌面实机验证适量使用已登录账号的模型额度。优先不调用模型；确有需要时只发送合成测试内容，控制调用次数并记录实际用量。不要读取或传输用户其他工作区的内容、凭据或私人数据。

### 工作环境和边界

- 本交接编写时的源码基线为 `main@39ef51c`，TDB 为 `0.9.1`，桌面已安装包含记忆回显修复的本地构建。开始时检查当前分支、提交、工作区状态和实际安装版本；后续若已有更新，以当前代码为准，不要为了回到该提交覆盖或重置用户改动。
- 两项任务可以并行，但不要在同一个工作目录同时切换分支或编辑相同文件。并行时使用独立分支和工作目录，例如 Git worktree；它只是工作目录，不需要备份项目或复制 Git 数据。只有任务 A 操作桌面界面，任务 B 使用离线合成数据。无法安全并行时自行串行完成。
- 所有数据使用本轮新建的临时合成工作区。不要查找、恢复、删除、合并或改写用户原有 `.dsh` 记忆，不修改 Git 历史，不覆盖已有的原始证据。允许清理本轮自己创建且已确认位于临时目录的测试文件。
- 启动或重启桌面前确认不会中断正在运行的用户任务；需要安装插件时优先使用项目源码构建和宿主官方命令，遵守执行环境要求。已发布的 npm `0.8.9` 仍有旧卸载清理脚本，不能拿它代替当前修复版。运行中的数据库复用宿主句柄或固定快照，不从第二个写进程直接打开同一库。
- 不安装 Ollama，不接入或优化远程 embedding；可以使用明确标记的本地测试替身验证降级和错误，不向真实 embedding 服务发请求。不发布 npm，不创建 issue、评论或其他对外消息；这些不属于本次任务。
- 保持改动精简，优先扩展现有测试集合和文档。可以按照用户已有授权和项目约定创建任务分支、提交及同步；不要强推、覆盖别人的分支或自动清理用户文件。两个并行任务完成后由整合执行者合并结果并核对共享状态文档。
- 最终一次性交付：改了什么、涉及文件、逐项验收结果、真实桌面/受控模拟/离线分别覆盖什么、实际运行的命令及结果、未完成或不确定事项、提交/分支状态。不要用“应该可以”代替运行结果。

## 任务 A：实体范围检索面板验收

### 目标

在桌面版和可重复的受控测试中验证实体范围检索面板，重点覆盖工作区隔离、迟到响应、错误提示和 live/快照差异。首轮合成桌面验证已覆盖基本检索、404、live/快照和零 embedding；先阅读[既有面板记录](reviews/ENTITY-SEARCH-PANEL-2026-11-13.md)，不要把它重新算成新证据。

### 建议入口

- 面板及请求状态：`lib/client.js` 中 `entitySearchCard`、`runEntitySearch`、`clearEntitySearch`、`entitySearchFailure`。
- 现有真实组件结构测试：`scripts/smoke-p78.mjs`；实体后端及 HTTP 测试：`scripts/smoke-p93.mjs` 的 entity-search 段。协议和错误码见 [read-api](read-api.md)。
- 尽量在现有测试中加入针对用户可见行为的断言；如确实需要新的测试辅助代码，保持小而独立，勿改变生产默认行为来伪造错误。

### 必须覆盖

1. **工作区切换和迟到响应**：创建 A、B 两个互不相关的合成工作区，尽量使用相同实体 ID 对应不同内容。确认请求绑定正确工作区；从 A 切到 B 后，A 的结果或迟到错误不能出现在 B 的面板中，旧输入和结果按现有契约清除。在可控测试中延迟并倒序返回请求，不能只测顺序成功路径。
2. **正常与空结果**：验证范围内事实、真实关系路径、`scope_anchor_only` 和 `no_candidates` 的显示。明确展示 `answerability: not_assessed`；有候选不等于已找到答案，词面和语义分数不能混成同一排名。
3. **来源隔离**：在合成库中捕获快照，再修改一条合成事实；live 返回修改后内容，固定快照保留捕获时内容。缺失快照清楚提示，不静默切换到 live 或其他快照。
4. **输入和错误态**：覆盖无效输入/400、实体不存在/404、不可用或范围/来源变化/409、工作预算/422、读取繁忙/429；补充超时/408 或取消路径。各自显示可区分的状态，不把失败或部分候选显示为成功的空结果，也不自动重试造成重复请求。
5. **默认成本**：语义通道默认关闭，普通检索对真实 embedding 服务的调用数为 0。若验证语义不可用或并发冲突，只用离线替身；降级应保留同范围词面结果并明确提示。
6. **真实桌面**：在可用桌面中使用独立合成工作区，实际操作至少覆盖工作区切换、一次正常检索和 live/快照对照。409/422/429 及乱序响应可通过受控组件/HTTP 测试稳定触发；如果没有在真实桌面触发，报告中必须明确其验证层级，不能冒称真实桌面通过。

### 验收与交付

- 对每个场景给出预期、实际、证据层级、结果和必要的复现方法；发现并修复本任务范围内的缺陷时，加入能够复现原问题的有意义回归。
- 运行 `npm test -- p78`、`npm test -- p93`、`npm run test:docs` 和最终 `npm test`。记录实际通过数量；失败先排查，无法解决时保留失败结果。历史上 `p93` 出现过一次进程异常退出，重跑通过不等于已查明原因。
- 在[面板记录](reviews/ENTITY-SEARCH-PANEL-2026-11-13.md)追加带日期的新结果，保留原记录；更新 [CURRENT-STATE](CURRENT-STATE.md) 中本任务的实际状态。不要覆盖历史数据或把未覆盖的异常标成通过。

## 任务 B：可重复的记忆评测基线

### 目标

为后续“少花代价提升记忆能力”建立可重复、可审查的离线基线：分别看事实写入、检索范围、相关性和成本。该任务测量当前行为，不要求当前得分达到人为指定的高分，也不顺手改变生产记忆策略。

### 建议入口

- 已有问答夹具与评分：`scripts/quality-fixtures.mjs`、`scripts/smoke-evaluation.mjs`；抽取评分：`scripts/extraction-rubric.mjs`。
- 已有实体检索夹具：`scripts/fixtures/entity-search-acceptance.json`、`scripts/fixtures/scoped-text-relations.json`；写入回显回归：`npm test -- p100`。
- 现有 `bench-quality-v2.mjs`、`bench-extract-cost.mjs` 的默认审计/离线模式可供参考；`--run` 会产生付费模型请求。先检查参数和既有输出，不能覆盖历史结果或直接运行付费批量实验。
- 历史质量夹具和已冻结实验的版本、原始证据及评分口径不得悄悄改写。优先扩展既有测试集合；需要新的冻结合成数据时，使用独立且有版本的夹具，并说明新增理由。

### 必须完成

1. **固定语料**：至少 24 个可复现的合成场景，分成至少 16 个开发场景和 8 个留出场景；两组避免复用同一事实的简单改写。先固定期望事实、来源和范围再运行，记录场景 ID、输入、期望及适用条件。至少覆盖同名/跨工作区、数值与否定、历史/替代/过期、自有工具回显与同轮新事实、无答案/范围外、标识符与中英文表达；每类至少 3 个场景，可以交叉。
2. **事实写入评分**：分别报告正确、漏记、无来源新增和重复写入的数量及分母。用户新事实与 `ctx_find`/`ctx_read` 旧记忆回显要分别标注；改写无法由确定性规则判定时列为待人工复核，不擅自归为正确或错误。先用已知正确、漏记、错误、重复的样例验证评分器本身。
3. **检索评分**：对有答案题按冻结的相关事实 ID 报告 Top-1/Top-5；单独检查跨实体、跨工作区和不应作为当前事实的历史记录。无答案题单列返回候选的情况：候选本身不等于最终答案，不把无答案候选直接算成模型回答错误，也不把它算成答对。
4. **比较口径**：至少提供一条可运行的当前离线基线路径，清楚说明输入、写入方式和读取方式；如果额外使用规则抽取、预置候选或模拟模型，分别标注，不能把模拟模型结果说成真实模型抽取能力。若没有执行最终生成回答，则“最终回答正确率”标为未测。
5. **成本与复现**：提供一条明确的离线运行命令和结构化结果，记录源码版本、夹具版本、环境、题目数、失败及跳过数、真实模型/embedding 调用数、耗时；没有实际 token、账单或价格时填写未测，不能用字符数冒充真实 token。条件允许时报告多次测量的 p50/p95 和样本数，不用机器相关耗时设脆弱的硬编码通过线。同一固定版本和输入重复运行时，除时间、路径等环境字段外，场景、判定和计数一致。
6. **报告真实差距**：报告总体及各类别结果、失败/待复核样例、可比较与不可比较的地方。不要为了提高结果修改冻结答案、跳过失败样本、硬编码生产输出，或把现有系统的不足写成测试工具失败。

### 验收与交付

- 交付夹具、可执行的离线评测入口、评分器自测和一份真实跑出的基线摘要；如果复用已有入口有困难，可以新增最小必要文件并说明原因。新输出使用新的路径，不覆盖已有实验记录。
- 运行相关新测试、`npm test -- p33`、`npm test -- p100`、`npm run test:docs` 和最终 `npm test`；若使用实体检索后端，另运行 `npm test -- p93`。记录实际结果和未测项目，不因基线得分不满分而隐藏数据。
- 在 [COST-MODEL](COST-MODEL.md) 或既有相关结果入口追加方法、命令、实际结果和局限；若新增运行入口，同步 [DEVELOPMENT](DEVELOPMENT.md)。更新 [ROADMAP](ROADMAP.md) 中与本评测相关的状态，不覆盖或改写历史测量。
